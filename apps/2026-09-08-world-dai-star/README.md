# スマスロ ワールドダイスター 設定判別ツール

「スロット ワールドダイスター」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5055)（2026/09/08更新）に掲載されている判別要素をそのままの分類（ST終了画面→コパンダトロフィー→ボーナス消化中の示唆→獲得枚数表示）で反映し、数値データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-08-world-dai-star/

## 機能

- **数値データ**（①）: CZ出現率・ボーナス初当たり確率（いずれも総G数を共通の母数とする合算値なので1つの見出しの下で2つの独立した二項尤度チャンネルとして入力可能）、上位ST中のクライマックスストーリー当選率（演目がオペラ座の怪人以外の場合。上位STの到達回数を母数とする独立チャンネル）——全2系統・3チャンネル
- **判別要素**（②）: ST終了画面（2人浴衣／3人浴衣）、コパンダトロフィー（5色）、最上位ST中のボーナス消化中のボイス示唆（ここなのセリフ2種）、チャンス目成立時のサイン（ボーナス消化中・エンディング共通、4色）、獲得枚数表示（4パターン）——計17種類をDMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「ワールドダイスター（スロット）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_wds/0/)（2026/08/29更新）を全文確認したところ、CZ出現率（1/180.6〜1/156.0）・コパンダトロフィー・獲得枚数表示・サイン／ボイスの示唆内容はDMMぱちタウンの内容と完全に一致していた。

一撃側にのみ「ボーナス初当たり確率」の設定1〜6完全テーブル（設定1: 1/306.5 〜 設定6: 1/246.6）が掲載されていたため、これをCZ出現率と並ぶ2本目のチャンネルとして採用した（DMMぱちタウン側は機種概要欄の機械割97.8%〜112.4%のみで、初当たり確率そのものの内訳テーブルは見当たらなかった）。

なお「チャンス目成立時のサイン」の設定2以上濃厚の色について、DMMぱちタウンは「白」、一撃は「青」と表記が食い違っていた（それ以外の紫／金／虹の3色と示唆内容は完全一致）。本ツールでは詳細な解説文が付いているDMMぱちタウン側の表記（白サイン）を採用した。

## データについて

本機種は2026年8月3日導入の新台（今回の確認時点で導入から1か月強）で、両サイトとも判別要素の掲載自体は充実していたが、6設定分の完全な数値テーブルは限定的だった。以下は本文を確認したうえで、あえて数値チャンネル・判別要素チップのいずれにも採用しなかった項目とその理由。

- **アクターエピソードの払い出し枚数**：「若干ではあるが、高設定ほど200枚が選択されやすい」との定性的な記載のみで、設定ごとの具体的な比率が示されていないため未採用。
- **ラッキーモード移行率**（設定変更時 約60%／上位ST終了後 約50%）：設定ごとの内訳ではなく単一の共通値のみのため、設定差データとしては利用できず対象外。
- **小役確率・小役合算確率・規定ゲーム数抽選（ボーナス前兆／高確移行）・しりうす湯の各種抽選・チャンス目成立時のアイテム当選率**など：DMM側の表はいずれも設定ごとの内訳がなく単一の共通値のみだったため対象外。
- **上位ST中のクライマックスストーリー当選率**は6設定分の完全な数値が判明していたため採用したが、演目が「オペラ座の怪人」だった上位STは全設定共通で当選濃厚となり判別に使えないため、プレイヤー自身が「オペラ座の怪人以外だった上位ST」の回数と成功回数を区別して数える必要がある、やや上級者向けのチャンネルであることに留意。
- **上パネルの劇団カスタム（シリウス／劇団電姫）による演出差**：見た目のみが変化する仕様と明記されており設定差そのものではないため対象外。
- **努力の破片（穢れ要素）の獲得・蓄積示唆**：［弱/中/強］の強さ表記はあるが、示唆先が「規定ポイント到達率」であって設定差ではないため対象外。

新台特有の事情として、数値チャンネルは「CZ・ボーナス初当たり」の1系統（2チャンネル）＋「上位STクライマックスストーリー」の1チャンネル、計3チャンネルにとどまっている。**今後DMM・一撃のページが更新され、上記の共通値のみだった項目に設定ごとの内訳が追加された場合は、追加のアップデートを検討されたい。**

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) を参照実装として、CSS（白背景・ほぼ黒文字・赤アクセント1色のデザイン）を完全に踏襲した
- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: CZ出現率・ボーナス初当たり確率・上位STクライマックスストーリー当選率それぞれの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 空欄フィールドの安全対策として [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/) と同じ`parseField(el)`パターンを採用：空欄は`null`（＝そのチャンネルは計算対象外）、入力済みは0以上の整数として扱い、CZ出現率とボーナス初当たり確率が同じ総G数を母数として共有する構成でも、`k`側の入力欄が空欄のまま総G数だけ入力されるケースを「0回観測」と誤解釈しないようにしている
- CZ出現率とボーナス初当たり確率は同じ総G数を母数とするため`field-group-label`を1つにまとめ、2つの`k`入力欄をその下に並べている（[apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCZ・エピソードボーナスの入力欄と同じパターン）
- 「チャンス目成立時のサイン」はDMMの解説文（「エンディング中のチャンス目と同様に設定2以上濃厚のサインが出る」）と一撃の解説（同一テーブルを「エンディング/最上位ST時のボーナス」共通枠として掲載）の両方から、最上位STのボーナス消化中とエンディング中で同じ仕組みの示唆であると確認できたため、二重カウントを避けてあえて1つのチップ群にまとめている
