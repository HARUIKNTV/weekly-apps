# スマスロ「L南国育ち SPECIAL」設定判別ツール

DMMぱちタウンの[「L南国育ち SPECIAL」設定判別・推測ポイント](https://p-town.dmm.com/machines/5031#anc-point)（2026/09/09更新）と、一撃(1geki.jp)の[「南国育ちスペシャル（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_nangoku_sp/0/)（2026/07/04更新）に掲載されている設定差データをもとに、入力した数値データと示唆演出の出現回数から設定期待度を算出するファンメイド計算機です。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-nangoku-sodachi-special/

## 機能

- 初当たり確率（総G数・ボーナス当選回数）から二項分布の対数尤度で設定期待度を算出
- 規定数以外（1・2・4・6・8回目）のスイカ成立時のボーナス当選率を、「通常A・B滞在時」と「チャンス/飛翔準備A・B/超飛翔準備滞在時」の2つの独立したチャンネルとして個別入力・計算（滞在中のモードによって当選率が大きく異なるため）
- ボーナス終了時のPUSHボイス（本機で唯一確認されている設定示唆演出）をタップ式のカウンターチップで記録し、「◯以上濃厚」は候補を確定、「高設定示唆」は参考程度の重みとして加算
- 空欄の入力項目は「データなし」として扱われ、該当チャンネルの計算から除外（0を入力した場合のみ「0回」として扱う）

## 1geki.jpとのクロスチェック

- 1geki.jpは独自の「[設定判別ツール](https://1geki.jp/slot/l_nangoku_sp/99/)」を公開しており、入力項目が「初当たり確率」「規定数以外スイカでのボーナス当選【通常A・B滞在時】」「規定数以外スイカでのボーナス当選【チャンス/飛翔準備A・B/超飛翔準備滞在時】」の3チャンネル＋示唆演出チェックのみで構成されていることを確認。本ツールの数値チャンネル構成はこれと一致させている。
- 1geki.jp公式ツールの判別対象設定も「設定1・2・4・5・6」の5択のみで、設定3のトグルが存在しないことを確認。DMMぱちタウン側の表（スイカ回数別ボーナス当選率）でも同様に設定3の行のみ欠落しており、両サイトの記載が一致している。
- 小役確率（チェリー1/44.9・スイカ1/99.9・レア役合算1/31.0）と50枚あたりの消化ゲーム数（約33.0ゲーム）は「全設定共通」と両サイトで明記されているため、設定差判別のチャンネルには使用していない。
- PUSHボイスの示唆内容（「今日の運勢は…」系＝設定2/4/6以上濃厚、それ以外＝高設定示唆の弱/中/強）はDMM・1geki双方の記載が一致。ただしDMM側は「張り切っていこー」「自分を信じて」「良い感じよ♪うんうん」の3種を「調査中」としていたため、より詳細な弱/中/強のtier分類は1geki.jp側の記載を採用した。

## データについて

見つけたが採用しなかったデータ（理由付き）：

- **初当たり確率・スイカ回数別ボーナス当選率の設定3の値** — DMMぱちタウン・1geki.jpのいずれにも設定3の行が存在しない（設定1・2・4・5・6の5行のみ掲載）。1geki.jp公式の設定判別ツールも設定1・2・4・5・6の5択構成で、設定3のトグル自体が用意されていない。存在しない数値を近傍設定から推測で補うと計算結果が歪むため、本ツールでも設定3を判別対象から除外し、5設定のみで確率計算を行う仕様とした。
- **モード示唆演出（リールランプフラッシュ色・ボーナス中の楽曲・ボーナス告知演出のキュイン音種）** — DMMぱちタウンに詳細な表があるが、これらはいずれも「内部モード（チャンス/飛翔/超飛翔など）」や「BIG/REG/裏REGの当選種別」「SDC（スペシャルドキドキチャンス）の成否」を示唆するものであり、隠しパラメータである「設定（1〜6）」そのものを示唆する情報ではないため、設定判別チップには含めていない。
- **プレミアム演出一覧（予告音からレア役否定＝ボーナス濃厚、ロングフリーズ濃厚パターン等）** — いずれも「ボーナス当選」「BIG当選」「ロングフリーズ発生」を確定させる演出であり、設定を示唆するものではないため対象外。
- **通常モード移行率の表（設定変更後／飛翔転落後／超飛翔転落後）** — 移行元状態別の遷移率のみが掲載されており、設定ごとの数値差は記載されていないため対象外。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/` のCSS・HTML骨格・チップ/結果表示ロジック（`logBinomLikelihood` による二項分布対数尤度計算とsoftmax正規化）、および `apps/2026-09-07-monhun-rise/` の `parseField` による空欄安全パース（空欄＝データなし、を確定0件と区別する）をベースに実装。

本機は判別可能設定が「1・2・4・5・6」の5段階（設定3非公表）という他機種にない特性があるため、内部的に `SETTINGS = [1, 2, 4, 5, 6]` という配列を導入し、確率テーブル・候補設定集合・結果バー描画のすべてをこの配列基準でループする設計に変更している（決め打ちで1〜6をループする従来実装からの変更点）。

フィードバックウィジェット（画面右下の💬ボタン）も同ファイルの実装をそのまま踏襲している。
