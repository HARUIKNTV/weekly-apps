# ゴーゴージャグラー3 設定判別ツール

「ゴーゴージャグラー3」（北電子、Aタイプ・ジャグラー系の人気シリーズ第3弾、2023年7月3日導入開始）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「ゴーゴージャグラー3」](https://p-town.dmm.com/machines/4375#anc-point)（2026/08/17更新）および[一撃（1geki.jp）「ゴーゴージャグラー3」小役確率ページ](https://1geki.jp/slot/s_gogojuggler3/4/)（2025/12/09更新）に掲載されているBIG確率・REG確率の公表スペック値をもとに、二項分布の尤度計算により設定期待度を算出します。

## A-type機種としての特殊な扱いについて

このサイトの他のツール（スマスロ系AT機）は、ストーリー性のある専用の終了画面・エンディング演出・示唆演出（金文字濃厚、虹背景など）を多数搭載しており、それらを②判別要素のチップリストとしてカウントする設計になっている。

しかし「ゴーゴージャグラー3」はAT・CZ・ストーリー要素の一切ない純粋なAタイプ機種であり、そうした専用の示唆演出は存在しない（プレミアム演出はいずれも出目上「大当り濃厚」を示す直接情報であり、設定を絞り込むための「示唆」ではない）。そのためこの機種では、②判別要素をチップリストではなく短い説明文のみとし、①数値データにあるBIG確率・REG確率の2つの独立した二項尤度チャンネルによる判別を中心に据えている（[マイジャグラーⅤ](../2026-09-10-my-juggler-5/)と同じ設計方針）。これはバグではなく、Aタイプ機種の判別方法の実態に合わせた意図的な設計。

## 機能

- **数値データ**（①）: 通常時総G数を共通の分母として、BIG当選回数・REG当選回数の2つを、それぞれ独立した二項尤度チャンネルとして入力可能
  - 空欄の項目は「データなし」として扱われ計算から除外される。0を入力した場合のみ「0回」として計算に反映される（`parseField()`によるnull安全設計）
- **判別要素**（②）: A-type機種のため専用の示唆演出が存在しないこと、およびブドウ・チェリー確率を採用しなかった理由を説明する注記のみを表示。チップリストは意図的に省略している
- 数値データの入力状況に応じて、現在の最有力設定候補をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

一撃「ゴーゴージャグラー3」の[設定判別・推測ポイントページ](https://1geki.jp/slot/s_gogojuggler3/0/)と[小役確率ページ](https://1geki.jp/slot/s_gogojuggler3/4/)に掲載されている「ボーナス確率」表（BB確率・RB確率・ボーナス合算、全設定分の公表スペック値）を、[DMMぱちタウンの特集記事「ゴーゴージャグラー3（ゴージャグ3）の設定差はこれを見ればOK！」](https://p-town.dmm.com/specials/3073/)（2024/11/18更新）と突き合わせて確認した。

- DMM特集記事本文にある「設定1でもBIG確率は1/259.0」「設定6ではBR比率が1対1となり合算確率は1/117.4」という記述は、一撃のボーナス確率表（設定1: BB 1/259.0・RB 1/354.2、設定6: BB 1/234.9・RB 1/234.9・合算1/117.4）と完全に一致した。信頼性の高い一撃側の表をBIG確率・REG確率としてそのまま採用した

### 採用したデータ（BIG確率・REG確率）と、あえて採用しなかったデータ

課題設計として「合成確率（BIG+REG）」「BIG確率」「REG確率」「ブドウ確率」「チェリー確率」のうち、重複しない組み合わせを選ぶ必要があった。今回は**BIG確率＋REG確率**の2チャンネルのみを採用し、以下は意図的に不採用とした：

- **合成確率（ボーナス合算）**: BIG確率とREG確率を独立チャンネルとしてすでに採用しているため、合成確率を加えると同じボーナス当選情報を二重にカウントしてしまうため不採用
- **ブドウ確率・チェリー確率**: **全設定（設定1〜6）分の公式スペック表がDMMぱちタウン・一撃のいずれにも見当たらなかった**ため不採用（CRITICAL RULE: 欠けている設定を絶対に捏造しない）。DMMぱちタウンの機種ページ本体では「解析情報通常時：準備中」となっており、公式な小役確率表は非公開のまま。判明しているのは以下の実戦値のみ：
  - DMMぱちタウン特集記事（[specials/3073](https://p-town.dmm.com/specials/3073/)）: 設定5＝ブドウ1/5.85（441回/2580G）・チェリー1/35.8（72回）、設定6＝ブドウ1/5.79（552回/3198G）・チェリー1/35.1（91回）
  - 一撃 小役確率ページ: 設定6＝ブドウ1/6.2（1215回/7528G）・チェリー1/34.9（216回）
  
  これらはいずれも「設定5・6のみ」または「設定6のみ」の実戦サンプルであり、設定1〜4の値は一切判明していない。仮にこの2点のデータだけでブドウ・チェリーをチャンネル化すると、設定1〜4の尤度に寄与せず実質的に「高設定（5・6）かどうか」しか判別できないうえ、5と6の差も僅少（1/5.85 対 1/5.79）で、ユーザーに「全設定を判別できる項目」であるかのような誤解を与えかねないと判断し、数値データからは完全に除外した。カード②の注記でその理由を明示している

## データについて

- BIG確率・REG確率は北電子の公表スペック値（全設定共通で信頼度が高い）。一撃「ボーナス確率」表を採用し、DMMぱちタウンの特集記事内の数値と完全一致することを確認済み
- ブドウ確率・チェリー確率は前述の理由により本ツールでは採用していない。上記の実戦値はあくまで参考情報であり、本ツールの計算には一切使用されていない

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS（白・黒・赤基調のパレット）とHTML骨格（ヘッダー／広告枠／カード①②③／出典／免責事項／フッター、AdSenseスクリプトタグの位置を含む）をそのまま踏襲した単一HTMLファイル。依存ライブラリなし、ビルド不要
- **A-type向けの適応点**: [apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)と同じく、②判別要素はチップリスト方式（`ITEMS`配列＋`buildChips()`）を丸ごと省略し、短い説明文のみに置き換えた。`computeCandidateSettings()`のようなハード除外ロジックも不要となり、`render()`は「2チャンネルの対数尤度を合算してソフトマックス的に正規化する」だけのシンプルな構成にした
- 尤度計算: [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`render()`にある`parseField(el)`パターンを採用。空欄は`null`を返し、各チャンネルはその欄が`null`でないことを個別に確認してから対数尤度計算に加算する
- 本機種は全6設定（設定1〜6）が存在する機種であり、[apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/)の`SETTINGS`配列による設定除外パターンは不要（設定そのものが欠けているわけではない）。一方でブドウ・チェリーというチャンネル自体を、全設定分のデータが存在しないという理由でまるごと不採用にした点が本機種特有の判断
- BIG・REGとも同じ「通常時総G数」を分母として共有する設計（1geki.jpの設定判別ツールや他の解析サイトの標準的なUIパターンに合わせた）
