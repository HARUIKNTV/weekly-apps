# ニューキングハナハナV-30 設定判別ツール

「ニューキングハナハナV-30」（パイオニア、ノーマル(A)タイプ・ハナハナシリーズ、ボーナストリガー(BT)搭載機、2026年01月05日導入開始）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「ニューキングハナハナV-30（キンハナ）」](https://p-town.dmm.com/machines/4912#anc-point)（2026/09/10更新）および[一撃（1geki.jp）「ニューキングハナハナV（30パイ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_new_king_hanahana_v30/0/)（2026/01/04更新）に掲載されているBB確率・RB確率の公表スペック値をもとに、二項分布の尤度計算により設定期待度を算出します。

## A-type機種としての特殊な扱いについて

このサイトの他のツール（スマスロ系AT機）は、ストーリー性のある専用の終了画面・エンディング演出・示唆演出（金文字濃厚、虹背景など）を多数搭載しており、それらを②判別要素のチップリストとしてカウントする設計になっている。

しかし「ニューキングハナハナV-30」はAT・CZ・ストーリー要素の一切ないノーマル(A)タイプ機種であり、[マイジャグラーⅤ](../2026-09-10-my-juggler-5/)や[ゴーゴージャグラー3](../2026-09-10-gogo-juggler-3/)と同様に、②判別要素をチップリストではなく短い説明文のみとし、①数値データにあるBB確率・RB確率の2つの独立した二項尤度チャンネルによる判別を中心に据えている。これはバグではなく、Aタイプ機種の判別方法の実態に合わせた意図的な設計。

本機には「ボーナス終了時のハイビスカスランプ発光色」「BIG後半のスイカ揃い時のリールサイドランプ発光色」という示唆演出が存在するが、DMMぱちタウン・一撃のいずれのページにも「どの設定でどの色が出現するか」という具体的な出現設定の対応表は掲載されておらず、色ごとの期待度の強弱（例: 白＜青＜黄＜緑＜紫＜虹）という順序のみが公開されている。特定の設定を確定・除外するには確度が不十分なため、欠けているデータを捏造しないというルールに従い、これらはチップ化せず②の説明文で言及するにとどめた。

## 機能

- **数値データ**（①）: 通常時総G数を共通の分母として、BB当選回数・RB当選回数の2つを、それぞれ独立した二項尤度チャンネルとして入力可能
  - 空欄の項目は「データなし」として扱われ計算から除外される。0を入力した場合のみ「0回」として計算に反映される（`parseField()`によるnull安全設計）
- **判別要素**（②）: A-type機種のため専用の示唆演出（数値化できる対応表付き）が存在しないこと、およびブドウ・チェリー確率を採用しなかった理由を説明する注記のみを表示。チップリストは意図的に省略している
- 数値データの入力状況に応じて、現在の最有力設定候補をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

一撃「ニューキングハナハナV（30パイ）」の[設定差・設定判別要素まとめページ](https://1geki.jp/slot/s_new_king_hanahana_v30/0/)に掲載されている「ボーナス確率」表（BB確率・RB確率・ボーナス合算、全設定分の公表スペック値）を、DMMぱちタウンの機種ページ本体の記述（BIGは約312枚、REGは約130枚、機械割97%〜108%、天井非搭載、導入開始日2026/01/05）と突き合わせて確認した。DMMぱちタウン側は設定判別ページに具体的な確率数値表を掲載しておらず（示唆演出のランプ色順序のみ）、数値スペックの一次情報としては一撃の表を採用した。

- 一撃「ボーナス確率」表: 設定1（BB 1/299・RB 1/496・合算1/186）〜設定4（BB 1/268・RB 1/409・合算1/162）、最高設定V（BB 1/253・RB 1/372・合算1/150）。「設定4以上を判別するうえでは、概ね1/170を切る数値が1つの基準」という一撃本文の記述とも整合する

### 採用したデータ（BB確率・RB確率）と、あえて採用しなかったデータ

課題設計として「合成確率（BB+RB）」「BB確率」「RB確率」「ブドウ確率」「チェリー確率」のうち、重複しない組み合わせを選ぶ必要があった。今回は**BB確率＋RB確率**の2チャンネルのみを採用し、以下は意図的に不採用とした：

- **合成確率（ボーナス合算）**: BB確率とRB確率を独立チャンネルとしてすでに採用しているため、合成確率を加えると同じボーナス当選情報を二重にカウントしてしまうため不採用
- **ブドウ確率・チェリー確率**: 全設定（設定1〜4・V）分の公式スペック表がDMMぱちタウン・一撃のいずれにも見当たらなかったため不採用（CRITICAL RULE: 欠けている設定を絶対に捏造しない）。公開されているのは「BIG中・RB中はスイカの出現回数が多いほど高設定に期待できる」という定性的な記述のみで、設定ごとの具体的な出現率表は非公開
- **ボーナス終了時のランプ色・リールサイドランプ色による示唆**: 前述の通り、色ごとの相対的な期待度序列は公開されているが、「設定何でこの色が出るか」という設定対応表が存在しないため、数値化・チップ化せず②の説明文にとどめた

## データについて

- BB確率・RB確率は一撃（1geki.jp）の「ボーナス確率」表（自社調査による公表スペック値）を採用。設定1〜4は連続値、最高設定は「V」という独自ラベル（本機は設定5が存在しない5段階設定）
- **重要**: 本機は設定1・2・3・4・Vの5段階設定であり、標準的な設定1〜6の6段階ではない。設定5に相当する値は存在しないため、`SETTINGS = [1, 2, 3, 4, 'V']`という配列でのみ扱い、欠けている設定5の尤度を補間・推定することは一切行っていない（[apps/2026-09-06-valvrave-2/index.html](../2026-09-06-valvrave-2/index.html)と同じ設計パターン）
- ブドウ確率・チェリー確率、および示唆ランプ色の設定対応表は前述の理由により本ツールでは採用していない

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS（白・黒・赤基調のパレット）とHTML骨格（ヘッダー／広告枠／カード①②③／出典／免責事項／フッター、AdSenseスクリプトタグの位置を含む）をそのまま踏襲した単一HTMLファイル。依存ライブラリなし、ビルド不要
- **A-type向けの適応点**: [apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)・[apps/2026-09-10-gogo-juggler-3/](../2026-09-10-gogo-juggler-3/)と同じく、②判別要素はチップリスト方式（`ITEMS`配列＋`buildChips()`）を丸ごと省略し、短い説明文のみに置き換えた。`render()`は「2チャンネルの対数尤度を合算してソフトマックス的に正規化する」だけのシンプルな構成にした
- **欠けている設定の扱い**: 本機は設定5が存在しない5段階設定（設定1・2・3・4・V）のため、[apps/2026-09-06-valvrave-2/index.html](../2026-09-06-valvrave-2/index.html)の`SETTINGS`配列＋オブジェクトキー方式（`P_BB[s]`・`P_RB[s]`）をそのまま採用。`SETTINGS = [1, 2, 3, 4, 'V']`のみをループし、存在しない設定5を補間・推定することは一切していない
- 尤度計算: [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`render()`にある`parseField(el)`パターンを採用。空欄は`null`を返し、各チャンネルはその欄が`null`でないことを個別に確認してから対数尤度計算に加算する
- BB・RBとも同じ「通常時総G数」を分母として共有する設計（1geki.jpの設定判別ツールや他の解析サイトの標準的なUIパターンに合わせた）
