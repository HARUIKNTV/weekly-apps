# 新ハナビ 設定判別ツール

パチスロ「新ハナビ」（型式名 S/新ハナビR/HA、導入開始日 2021年07月05日、[DMMぱちタウン機種ページ](https://p-town.dmm.com/machines/3911#anc-point) machines/3911）の設定判別を助ける計算ツール（参照日: 2026年09月10日）。DMMぱちタウンの機種ページ「設定判別・推測ポイント」に掲載されている小役確率・ボーナス確率・終了画面の判別要素をもとに、実戦データの入力から設定期待度を算出します。

シリーズ機種の「スマスロ ハナビ」（型式名 L/ハナビ/KM、導入開始日 2026年02月02日、DMM machines/4928、本サイトの[別ツール](../2026-09-10-hanabi/)で既にカバー済み）とは、機種タイトル・型式名・DMM機種ID・導入開始日のいずれも異なる別機種であることを確認済みです。「新ハナビ」は2021年導入の旧世代A-type機、「スマスロ ハナビ」は2026年導入のスマートスロットで、風鈴・氷・チェリー・花火チャレンジ・花火ゲーム・RB終了画面のピース花火といった役物・演出の名称は共通していますが、確率テーブルの数値は機種ごとに異なります（本ツールは新ハナビ側の数値のみを使用しています）。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-shin-hanabi/

## 機種の位置づけ：A-typeだが確定型の示唆演出あり

本機はAT・CZ・ストーリー性のある専用演出を持たない旧世代のA-type機ですが、マイジャグラーⅤ等の純粋なジャグラー系とは異なり、RB（REG）終了画面のピース花火出現や、RB中のハズレ目出現など、**特定の設定を確定的に示す演出（示唆ではなく確定情報）**がDMM・一撃の双方で明記されていました。そのため②判別要素は説明文のみではなく、これらをタップ式カウンターで記録できるチップ形式としています。

## この機種の特徴：公開データが設定1・2・5・6の4段階分のみ

DMMぱちタウン・一撃（1geki.jp）のどちらのページでも、ボーナス確率・通常時小役確率・BIG中の小役確率・RT中のハズレ確率など、すべての設定別テーブルが**設定1・2・5・6の4列のみ**で構成されており、設定3・4の数値はサイト内のどこにも一切掲載されていない。本ツールもこれに合わせて`SETTINGS = [1, 2, 5, 6]`という設定空間で計算しており、結果表示にも設定3・4は出てこない（実機に設定3・4が存在しないという意味ではなく、公開されている実戦データがこの4段階分にとどまっているという意味）。

## 機能

- **数値データ**（①）: 以下の5つのグループ・14項目をそれぞれ独立した二項尤度チャンネルとして入力可能
  - ボーナス確率（総G数・BIG当選回数[ドンBIG＋赤七BIG合算]・REG当選回数）
  - 通常時の小役成立回数（風鈴・氷・チェリー、いずれも合算値。総G数は上と共通）
  - BIG中の小役確率（BIG中消化G数・風鈴[平行揃い]・風鈴[斜め揃い]・バラケ目）
  - 花火チャレンジ中のハズレ確率
  - 花火ゲーム中のハズレ確率
- **判別要素**（②）: 以下2つの確定型演出をタップ式カウンターで記録
  - RB終了画面のピース花火出現（設定2以上濃厚）
  - RB中のハズレ目（1枚役狙い失敗）出現（設定5以上濃厚）
- 空欄の項目は「データなし」として扱われ計算に影響しない（`parseField`によるblank-safety。0を入力した場合のみ「0回」として扱う）
- 広告枠を3か所設置（ヘッダー直下728×90、判別要素と結果の間300×250、フッター上728×90）— プレースホルダー表示のみ
- モバイル表示時の日本語の不自然な改行を防ぐCSS（`word-break: keep-all`）を適用

## 一撃（1geki.jp）とのクロスチェック

[一撃「新ハナビ」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_shinhanabi/0/)を確認したところ、通常時の風鈴・氷・チェリーの合算成立率、REG（RB）確率、BIG中の風鈴・バラケ目、花火チャレンジ・花火ゲーム中のハズレ確率はいずれもDMM側の数値と完全に一致しており、相互に裏付けが取れた。BIG確率については、DMM側は「ドンBIG」「赤七BIG」を個別の確率（例：設定1 = 1/555.4ずつ）として掲載しているのに対し、一撃は両者を合算した「BB確率」（設定1 = 1/277.7）を掲載しており、1/555.4 + 1/555.4 ≒ 1/277.7 で数値的に整合することを確認した上で、プレイ中に個別に区別しなくて済む一撃の合算値を採用した。

## データについて（見つけたが採用しなかった項目）

以下はDMM・一撃の両サイトで見つけたものの、**特定の設定（列）の数値が欠落していた**、または実戦入力が非現実的なため未採用とした項目。欠落設定を補完・推測することは行っていない。

- **RB中のハズレ目（1枚役狙い失敗）確率**: 一撃の表では設定5・6のみ数値（1/376.6）が公開されており、設定1・2は「－」で数値自体が非公開。4設定分の数値が揃わないため二項尤度チャンネル化はせず、「出現＝設定5以上濃厚」という確定情報のみを②のチップとして採用した
- **氷B成立率**（通常時、氷Aとの内訳）: 設定1のみ「1/1638.4」の記載があり、設定2・5・6は空欄のため未採用（氷の「合算」値は4設定分そろっているためこちらを①で採用）
- **チェリーA1・チェリーA2・チェリーBの内訳確率**（通常時）: チェリーA1は設定1・5にしか数値がなく（かつ差がほぼ横ばい）、設定2・6は空欄。チェリーの「合算」値は4設定分そろっているためこちらを①で採用した
- **RB終了画面のハズレ／不足回数別のピース花火出現率テーブル**（4回以下／5〜6回／7回以上）: 設定1列がすべて「－」で非公開、かつ回数区分ごとの条件付き確率という複合的な指標のため、確実に判別できる「出現＝設定2以上濃厚」という単純な確定情報に一本化し、回数別の詳細出現率まではモデル化していない
- **花火チャレンジ／花火ゲーム中の通常リプレイ・RTリプレイ比率**: ハズレ確率と一部重複する指標で、設定2以降は「通常リプレイ／RTリプレイ」個別の確率ではなく「ハズレとの比率」のみが掲載され集計方法が実戦入力に不向きなため、確実に判別できるハズレ確率に一本化し未採用

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 設定空間を`SETTINGS = [1, 2, 5, 6]`配列で保持し、確率テーブルもオブジェクト（`{1: ..., 2: ..., 5: ..., 6: ...}`）で持たせることで、公開データが4段階分にとどまる機種にも対応できる形に一般化した（[革命機ヴァルヴレイヴ2](../2026-09-06-valvrave-2/)のSETTINGS配列パターンを踏襲）
- 空欄フィールドを「データなし」として扱う`parseField`によるblank-safety、および同じ総G数／消化G数を共有する複数チャンネルのうち入力済みのものだけを計算対象にするパターンは[モンスターハンターライズ](../2026-09-07-monhun-rise/)を参照実装として踏襲
- チップUI・尤度計算・フィードバックウィジェットの基本パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲
- 数値データのグループ構成・確定型チップの扱いは、同シリーズかつ公開データが同じ4段階分にとどまる[スマスロ ハナビ](../2026-09-10-hanabi/)の実装パターンを踏襲しつつ、本機（新ハナビ）で実際に確認できたデータの過不足に合わせて項目を再構成した
