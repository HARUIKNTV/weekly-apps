# スマスロ バイオハザードRE:3 設定判別ツール

「スマスロ バイオハザードRE:3」（エンターライズ、2026年5月11日導入）の設定判別ファンメイド計算機です。
[DMMぱちタウン「スマスロ バイオハザードRE:3（パチスロ）設定判別・天井・ゾーン・解析・打ち方・ヤメ時」](https://p-town.dmm.com/machines/4974#anc-point)（2026/09/09更新）の「設定判別・推測ポイント」欄をベースに、数値データはBinomial（二項分布）の対数尤度、判別要素（エンタトロフィー・フィギュア・獲得枚数表示）はタップ式のカウンターチップとして入力し、それらをsoftmaxで正規化して設定1〜6の期待度バーを算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-biohazard-re3/

## 機能

- **① 数値データ**：わかる範囲で入力するほど精度が上がる二項分布チャンネルを8グループ・21項目用意
  - AT初当たり・通常時CZ・5枚ベル（総G数ベース）
  - 弱レア役契機のCZ当選率（通常A／通常B／高確、内部状態別に3グループ）
  - 強レア役契機のCZ・AT直撃当選率（通常A／通常B／高確、内部状態別に3グループ、各グループでCZとAT直撃の両方を計算）
  - 心音レベル転落率（保証消化後）
  - 空欄の項目は「未入力＝ノーデータ」として扱い、0回として計算に含めません（ある項目だけ空欄にしても他の項目の判定に影響しません）
- **② 判別要素**：タップ式のカウンターチップで25種類の出現演出をカウント
  - エンタトロフィー（銅／銀／金／紅葉柄／虹）＝濃厚系、候補を即座に絞り込み
  - フィギュア16種（No.1〜16、奇数/偶数/高設定示唆の弱・中・強、およびNo.14「2以上濃厚」・No.15＆16「両方獲得で4以上濃厚」の確定系）
  - 獲得枚数表示（222/333/444/555/666 over）＝濃厚系
- **③ 結果**：設定1〜6の期待度をバーグラフとテキストで表示。濃厚・否定要素が矛盾した場合は警告表示

## 1geki.jpとのクロスチェック

[一撃「バイオハザードRE3（スロット/スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_bhr2/0/)（2026/08/10更新）で全チャンネルの数値を突き合わせ、CZ確率・5枚ベル確率・レア役契機の当選率・エンタトロフィー・フィギュア・獲得枚数表示の示唆内容はDMMぱちタウンと完全一致することを確認しました。
なお、**AT初当たり確率の設定1〜6完全テーブルは1geki.jpのみに掲載**されており（DMMぱちタウン側は機種概要欄に具体的な数値の記載なし）、本ツールのP_AT_INITIAL配列は1geki.jpの数値を採用しています。

## データについて

以下は本ツールに反映しなかった「見つけたが採用しなかった」データです。

- **規定ネメシスポイント振り分け（50pt〜500ptの10段階、通常時／AT中／上位AT中）**：両サイトに完全な設定別テーブルが掲載されていますが、10カテゴリの分布表であり単純な二項分布（成功/失敗）のチャンネルには当てはまりません。1geki.jpが提示する「350pt以下選択率」という集計指標も、CZ当選のたびに確定ポイント値をメモする必要があり、他の数値チャンネルと比べて入力の手間が大きく不釣り合いなため、数値チャンネル化は見送りました。高設定ほど100pt・200ptなど浅いポイントで当選しやすい、という傾向は免責事項の外で参考情報として触れるに留めています。
- **AT中／上位AT中のCZ当選率**：完全な設定別テーブルが存在しますが、AT中・上位AT中の滞在ゲーム数は1セッションあたり数百G程度に留まることが多く、二項分布のサンプル数として心もとないため、本ツールでは通常時のCZ当選率のみを数値チャンネルとして採用しました。
- **弱レア役・強レア役契機のCZ／AT当選率のうち「超高確」滞在時の数値**：両サイトとも超高確滞在時の値は設定1〜6ですべて同一（弱レア役CZ 25.0%、強レア役CZ 87.5%、AT直撃12.5%）であり、設定差がないため判別チャンネルとして意味を持ちません。通常A・通常B・高確の3状態のみを採用しました。
- **内部状態昇格率（通常A→通常B、通常A→高確など）**：DMMぱちタウンに掲載がありますが、設定別の内訳（設定1〜6ごとの数値）が示されておらず、全設定共通の値のみのため対象外としました。
- **フリーズ性能・パンデミックチャンスの報酬抽選・ウィルス種別ボーナス倍率などのゲームフロー詳細**：設定差のあるデータではなく、純粋なゲーム性・演出パターンの解説のため対象外としました。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/` のCSS・HTML骨格・JSアーキテクチャ（per-setting配列 → `logBinomLikelihood` → `computeCandidateSettings` → `buildChips` → softmax正規化の `render()`）をそのまま踏襲しています。
空欄フィールドの扱いは `apps/2026-09-07-monhun-rise/` の `parseField()` パターンを採用し、「空欄＝ノーデータ」と「0＝0回観測」を明確に区別しています（特に総G数や内部状態別N数のように複数チャンネルが同じ分母を共有するグループで、片方のk値だけ未入力にしても他のチャンネルの計算を汚染しないよう、各k値ごとに `Raw !== null` の個別ゲートを設けています）。
