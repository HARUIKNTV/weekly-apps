# スマスロ モンスターハンターライズ 設定判別ツール

「スマスロ モンスターハンターライズ」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4676#anc-point)（2026/09/05更新）と[一撃「モンスターハンターライズ（スロット）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_mh_rize/0/)（2026/02/18更新）の両方を読み込んだうえで、公開されている判別要素をDMMぱちタウンの分類順（ボーナス終了画面→エンタトロフィー→ボーナス入賞時のボイス→ボーナス確定画面→早期討伐後のムービー→エンディング）のまま反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-07-monhun-rise/

## 機能

- **数値データ**（①）: 以下6系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - **AT初当たり確率**（総G数ベース、一撃のみに掲載の完全な設定1〜6テーブル。DMM側は機種概要欄に「初当り確率は約1/309（設定1）」とあるのみで全設定分は非掲載）
  - **ライズゾーンの実質出現率**（総G数ベース。内部状態（通常/高確/超高確）不問の合算値を採用し、状態依存の弱レア役別テーブルは入力の複雑化を避けるため未使用）
  - **ロングフリーズ確率**（総G数ベース。分母が非常に大きいため参考程度）
  - **AT直撃当選率（弱レア役契機）**：弱チャンス目・スイカ・弱チェリー成立時
  - **AT直撃当選率（強レア役契機）**：強チャンス目・強チェリー成立時（弱レア役契機とは母数が異なるため見出しを分離）
  - **3枚ベルでの高確移行率**：通常→高確の移行を検知できた場合に入力
- **判別要素**（②）: ボーナス終了画面（示唆キャラ12種）、エンタトロフィー（5色）、ボーナス入賞時のボイス（7を狙う際の特殊ボイス・1確ボイス・入賞ボイス矛盾パターン、計5種）、ボーナス確定画面（示唆キャラ8種）、早期討伐後のムービー（1種）、エンディングのアイルーおみくじ（8色）——計39種類をDMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」「〜否定」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

DMMぱちタウンと一撃、両方のページを全文確認したところ、掲載されている判別要素（ボーナス終了画面／エンタトロフィー／ボーナス入賞時のボイス／ボーナス確定画面／早期討伐後のムービー／エンディングのアイルーおみくじ）と数値データ（AT直撃当選率、3枚ベルでの高確移行率、ライズゾーンの実質出現率、ロングフリーズ確率、アイルーだるま落としの規定リプレイ回数振り分け）は完全に一致していた。

一撃側にのみ掲載されていたのが**AT初当たり確率（AT出現率）の設定1〜6完全テーブル**（設定1: 1/309.5 〜 設定6: 1/230.8）。DMMぱちタウンは機種概要欄に「初当り確率は約1/309（設定1）」と設定1の値のみ記載しており、全設定分の完全テーブルは一撃側でのみ確認できたため、本ツールでは一撃の値を採用し、`P_AT_INITIAL`のコメントにその旨を明記した。

## データについて

以下は本文を確認したうえで、あえて数値チャンネル・判別要素チップのいずれにも採用しなかった項目とその理由。

- **クエストテーブル移行率／ポイントモード移行率**（DMM・一撃とも完全な設定1〜6テーブルが掲載）：いずれも4択（テーブルAのまま／テーブルBへ／天国準備へ／天国へ、など）の多項分布であり、単純な二項尤度チャンネルに落とし込むと選択肢間の相互排他性を壊してしまうため未採用。またこれらは「クエストテーブル」「ポイントモード」という内部モードの推測に関する情報であり、設定そのものの判別要素ではない（機種内のゲーム性パラメータ）ため対象外とした。
- **アイルーだるま落とし当選までの規定リプレイ回数振り分け**（40回/80回/120回/160回/200回の5択、設定1〜6完全テーブル）：「高設定ほど少ない回数が選ばれやすい」傾向はあるが、5つの選択肢のうちどれが選ばれたかという多項分布のため、上記と同じ理由で二項尤度チャンネル化を見送った。
- **ボーナス終了画面での次回クエストテーブル天国示唆**（ルーク＆HARUTO＆Mimi／ワドウ丸＆アッシュ＆つばき／Lara＆ミランダ＆隊長の各インナー柄、「次回天国期待度○%」「次回天国濃厚」）：DMM・一撃どちらにも掲載され、演出情報セクションにも同内容の再掲があったが、これは「クエストテーブルの天国」というゲームモードの示唆であり、設定（1〜6）とは無関係なため対象外とした。
- **小役確率**（リプレイ/3枚ベル/ハズレ3枚/スイカ/弱チャンス目/強チャンス目/弱チェリー/強チェリー等）：DMM側の表は設定ごとの内訳がなく単一の確率値のみだったため、設定差データとしては利用できず対象外。
- **[弱チェリー・スイカ]内部状態別ライズゾーン当選率**（通常/高確/超高確の3状態別テーブル）：数値自体は設定1〜6完全テーブルだが、プレイヤーが自身の内部状態（通常/高確/超高確）をリアルタイムに把握するのは困難で、かつ超高確時は全設定で100%（設定差なし）となるため、状態不問の合算値である「ライズゾーンの実質出現率」を採用し、状態別の内訳は未使用とした。
- **討伐モンスター数ごとのエンディング権利獲得当選率**：設定によらない共通テーブルであり、設定差データではないため対象外。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- `numericInputs`配列（要素の並び順）→ イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→ `render()`内の分割代入、の3点の並び順が一致していることを確認済み（[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)で見つかった配線漏れバグと同じ観点でチェック済み）
- AT直撃当選率は「弱レア役契機」「強レア役契機」で母数（n）が異なる（弱チャンス目・スイカ・弱チェリーの成立回数 vs 強チャンス目・強チェリーの成立回数）ため、`field-group-label`を分離した。一方、AT初当たり・ライズゾーン・ロングフリーズの3チャンネルはいずれも総G数を共通の母数とするため、1つの見出しにまとめている（[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲したパターン）
