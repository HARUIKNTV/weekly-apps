# スマスロ戦国コレクション6 設定判別ツール

「スマスロ戦国コレクション6」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5010#anc-point)（2026/09/07更新）を全文読み込んだうえで、公開されている判別要素をDMMぱちタウンの分類順（AT終了画面→特化ゾーン「夢幻斬りWONDER」リザルト→AT中の7揃い特殊形→セット開始時の扉絵→獲得枚数表示→エンディングのPUSHボイス）のまま反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-08-sengoku-collection6/

## 機能

- **数値データ**（①）: 母数（n）が異なる2系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - **AT初当たり確率**（総G数ベース。設定1: 1/363.6〜設定6: 1/252.2。DMM・一撃の両ページで数値一致を確認）
  - **特化ゾーン出現率**（AT中ゲーム数ベース、共通の母数を持つため1つの見出しに統合）：「ロボニャンドライブ」「夢幻斬りWONDER」「3人のコレクション」の3種類をそれぞれ独立入力。特に夢幻斬りWONDERは設定差が大きい（設定1: 1/9415.7〜設定6: 1/8195.5、高設定ほど出現しやすい）ため、設定推測の軸として有用
- **判別要素**（②）: AT終了画面（示唆キャラ7種）、特化ゾーン「夢幻斬りWONDER」リザルトのランプ色（4色）、AT中の7揃い特殊形（2種）、セット開始時の扉絵（4種）、獲得枚数表示（5種）、エンディングのレア役成立時PUSHボイス（7種）——計29種類をDMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「戦国コレクション6」設定差・終了画面まとめ](https://1geki.jp/slot/l_sencolle6/0/)（2026/08/26更新）を全文確認したところ、AT終了画面・特化ゾーン「夢幻斬りWONDER」リザルト・AT中の7揃い特殊形・獲得枚数表示・エンディングのPUSHボイスの各示唆内容と、AT初当たり確率・特化ゾーン出現率（ロボニャンドライブ／夢幻斬りWONDER／3人のコレクション）の数値テーブルは、DMMぱちタウン側と完全に一致していた。一撃はこれに加えて「特化ゾーン出現率合算」列や設定変更後の勝率（3500G/4500G時点）も掲載していたが、本ツールでは前者は個別3チャンネルと重複するため、後者は下記「データについて」の理由で採用していない。

セット開始時の扉絵（謙信・水着・味方キャラ6人・デフォルメキャラ全員）はDMMぱちタウンのみに掲載されており、一撃側では該当ページに明記が見当たらなかったため、DMM側のみを出典として採用した。

## データについて

以下は本文を確認したうえで、あえて数値チャンネル・判別要素チップのいずれにも採用しなかった項目とその理由。

- **AT中の2000枚OVER率**（一撃の機種概要欄に「2000枚over率が約70.1%（設定1）」との記載あり）：設定1の値のみが公開されており、設定1〜6の完全な対応表が確認できなかったため未採用。
- **設定変更（リセット）後の勝率**（3500G/4500G消化時点、設定1〜6完全テーブルあり）：これは「差枚数がプラスになっている台の割合」という集計済みの勝率であり、単純な「n回中k回成功」の二項試行として扱える数値ではないため、本ツールの尤度モデルには組み込まなかった。
- **小役確率**（リプレイ1/9.6・弱チェリー1/69.6など）：DMM側の表に設定ごとの内訳がなく、全設定共通の単一値のみだったため、設定差データとしては利用できず対象外。
- **AT終了画面のコナミコマンド入力によるボイス示唆**：「次回モード示唆」「○周期以内にAT当選濃厚」など、モードや周期に関する示唆のみで設定（1〜6）そのものへの言及がないため対象外。
- **アリストロフィーによる示唆**（銅／銀／金／クローバー柄／虹）：一撃の解説文に「戦国コレクション６は、アリストロフィーを搭載している模様。示唆内容は他機種同様と推察される」「※示唆内容は、他機種を参考にした推察」と明記されており、本機での公式な設定示唆の確認が取れていない推測情報のため未採用。
- **特化ゾーン出現率合算**（ロボニャンドライブ／夢幻斬りWONDER／3人のコレクションの合算値）：個別3チャンネルの入力と情報が重複し、二重カウントになるため未採用。個別チャンネルのみを採用した。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 空欄の数値フィールドは`parseField(el)`で`null`として扱い、「未入力」と「0回observed」を区別する（[スマスロ モンスターハンターライズ 設定判別ツール](../2026-09-07-monhun-rise/)の`render()`にある修正済みパターンをそのまま踏襲）。各チャンネルは共有の母数（n）が0より大きいことに加え、自身のk入力欄が`null`でないことの両方をゲート条件にしている
- `numericInputs`配列（要素の並び順）→ イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→ `render()`内の分割代入、の3点の並び順が一致していることを確認済み
- AT初当たり確率（総G数ベース）と特化ゾーン出現率（AT中ゲーム数ベース）は母数が異なる（通常時の総G数 vs AT中の消化G数）ため、`field-group-label`を分離。一方、特化ゾーン3種はいずれもAT中ゲーム数を共通の母数とするため、1つの見出しにまとめている
- 参照実装として[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS（白／黒／赤の配色）とHTML骨格・JS構成をそのまま踏襲した
