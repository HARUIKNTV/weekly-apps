# L不二子BT 設定判別ツール

「L不二子BT（スマスロ、アムテックス、型式名LB不二子M2、2025年12月22日導入）」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4921#anc-point)（2026/09/09更新）に掲載されている判別要素をそのままの分類（BIG・スーパーBIG終了画面／ジャッジ演出／枚数調整成功時のボイス／REG中のキャラ紹介シナリオ）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-fujiko-bt/

## この機種の特徴：天井なし・設定3が存在しない

- 本機には天井・有利区間が搭載されておらず（DMM記載「天井突入条件：なし」）、完全な設定狙い専用機。その分、設定判別要素が非常に豊富。
- DMMぱちタウン・一撃の全テーブルが設定1・2・4・5・6の5列で構成されており、設定3は存在しない5段階設定の機種（一撃側に「本機は設定3非搭載」と明記あり）。本ツールもこれに合わせて`SETTINGS = [1, 2, 4, 5, 6]`という設定空間で計算しており、結果表示にも設定3は出てこない。

## 機能

- **数値データ**（①）: ボーナス確率（BIG・REG）、リーチ目役D・E・F・G成立率、プラムA・B／チェリー出現率（通常時）、BIG・スーパーBIG中の斜めプラム確率、チェリー同時当選（REG・BIG）をそれぞれ独立した二項尤度チャンネルとして入力可能。空欄の項目は「データなし」として扱われ、0回として計算に混入することはない（`parseField`によるblank-safety対応）
- **判別要素**（②）: BIG・スーパーBIG終了画面のスタンプ、ジャッジ演出（パチンコジャッジ／カードジャッジ）、枚数調整成功時のボイス、REG中のキャラ紹介シナリオのすべてを、DMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と強さに応じて参考程度の重みだけを加える
  - REG中のキャラ紹介シナリオは1つの出現パターンが複数の示唆を同時に含む（例：「ル→次→五→赤不」＝高設定示唆[弱]＋奇数示唆）ため、同じラベルのチップを示唆の数だけ分けて用意し、出現したパターンに該当する全チップをタップしてもらう構成にした
- 広告枠を3か所設置（ヘッダー直下728×90、判別要素と結果の間300×250、フッター上728×90）— プレースホルダー表示のみ
- モバイル表示時の日本語の不自然な改行を防ぐCSS（`word-break: keep-all`）を適用
- 全ページ共通のフィードバックウィジェット（右下💬ボタン、FormSubmit.co経由）を搭載

## 一撃（1geki.jp）とのクロスチェック

[一撃「Ｌ不二子ＢＴ」設定差・終了画面・ボイス](https://1geki.jp/slot/lb_fj2/0/)（2026/01/23更新）を確認したところ、DMM側には数値化されていなかった**BIG確率・REG確率の設定別内訳**（1geki側の表でSBB列がrowspanで全設定共通の1/697.2と分離されており、BB・RB列のみ設定差ありと判明）を裏取りできたため、①のボーナス確率チャンネルに反映した。プラムA・B・チェリー出現率、チェリー同時当選（REG・BIG）、斜めプラム確率、REG中のキャラ紹介シナリオの出現率振り分けはDMM・一撃で数値が完全に一致しており、相互に裏取りが取れている。また、「本機は設定3非搭載」という記載は一撃側にのみ明記されていたが、DMM側の全テーブルも設定1・2・4・5・6の5列構成である点と矛盾なく、SETTINGS配列の根拠として採用した。

REG中のキャラ紹介シナリオ⑪⑫（赤ルパン絡みのパターン）について、DMMは「奇数/偶数示唆」、一撃は「設定5/6期待度アップ」と表現が異なっていたが、振り分け実数値の表（赤キャラ出現有無別の振り分け）を突き合わせたところ、ハード除外後の候補内では両者の実質的な意味が一致することを確認し、DMMの表現（奇数/偶数示唆）に統一した。

## データについて

以下は本文中で見つけたが、理由付きで採用しなかったデータ：

- **SBB（スーパーBIG）確率**：全設定共通1/697.2（「設定差なし」と明記）のため、設定判別には使えず未採用
- **プラムC、ベルA、ベルB**：いずれも「設定差なし」小役として明記されているため未採用
- **リーチ目役A・B・C**：DMM「リーチ目役確率」表でD列のみ全設定分の数値があり、A・B・Cは設定1の代表値のみで他設定は空欄（＝設定差なしのため代表値のみ掲載と判断）。設定差のあるD・E・F・Gのみ採用
- **当選ボーナスごとのリーチ目役確率詳細**（赤7BIG・赤7スーパーBIG・青7スーパーBIG・REG別の細分化テーブル）：既に採用した「リーチ目役確率（全ボーナス合算）」と同じ根拠演出の内訳であり、独立チャンネルとして追加すると同じ証拠を二重カウントしてしまうため未採用
- **チェリー契機の赤7スーパーBIG・青7スーパーBIG同時当選**：「設定差なし」と明記されているため未採用（チェリー契機のREG・BIG同時当選のみ採用）
- **銭形（2人目or3人目）出現有無の振り分け表**：内容が②のREG中キャラ紹介シナリオのチップ（ル→銭→五→不 等）で既にカウント済みの現象であり、同じ演出出現を①の数値チャンネルとして二重カウントすることになるため未採用
- **ハーレムモード中枚数決定ゾーン比率**：これはリサーチ中に誤って別機種（L ToLOVEるダークネス）のページを取得した際に見えた無関係のデータであり、不二子BTとは無関係のため当然未使用（データ混入防止の確認記録として明記）

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 設定空間を`SETTINGS`配列で保持し、確率テーブルもオブジェクト（`{1: ..., 2: ..., 4: ..., ...}`）で持たせることで、5段階設定の機種にも対応できる形に一般化した（[革命機ヴァルヴレイヴ2](../2026-09-06-valvrave-2/)のパターンを踏襲）
- 数値入力は`parseField`で空欄=`null`（データなし）と0回=`0`（確認された0回）を明確に区別し、各チャンネルは自分自身の入力欄が空欄でない場合のみ尤度計算に加える（[モンスターハンターライズ](../2026-09-07-monhun-rise/)のパターンを踏襲）
- チップUI・尤度計算の基本パターン、およびフィードバックウィジェットは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲
