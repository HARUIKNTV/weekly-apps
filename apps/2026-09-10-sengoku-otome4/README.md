# L戦国乙女4「戦乱に閃く炯眼の軍師」設定判別ツール

「L戦国乙女4 戦乱に閃く炯眼の軍師」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4395#anc-point)（設定判別・推測ポイント自体の最終更新: 2025/03/12、ページ全体の最終更新日は2026/09/05だが該当箇所以降の更新は無関係な基本情報の追記）に掲載されている判別要素をそのままの分類（AT終了画面→エピソードボーナス→獲得枚数表示）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出する。

**注意（機種の区別について）**: 本サイトには既に「L戦国乙女5 業火を穿つ宿焔の双刃」の判別ツール（[apps/2026-09-08-sengoku-otome5/](../2026-09-08-sengoku-otome5/)、DMM machines/5009）が存在するが、本ツールはそれとは別の先行機種「L戦国乙女4 戦乱に閃く炯眼の軍師」（DMM machines/**4395**、導入開始日2023年09月04日、型式名L戦国乙女4S3）を対象とした、独立した新規ツールである。両機種はシリーズが異なるだけでなく判別要素・数値データも一切共通しない。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-sengoku-otome4/

## 機能

- **数値データ**（①）: 以下8系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - 総G数ベースの当選率（初当り＝戦国乙女ボーナス＋AT直撃 合算／うちAT直撃当選回数／ゾーン外ボーナス当選回数）— 総G数は共有。初当り合算は一撃のみ掲載、AT直撃はDMM掲載、ゾーン外ボーナスはDMM・一撃で完全一致
  - 巫女カウンター0pt到達時の乙女アタック当選率 — DMM・一撃の両方に完全一致するテーブルが掲載
  - 乙女アタック直撃当選率（チャンス目・強チェリー契機）— DMM・一撃とも同値
  - オウガイバトル1戦目勝利期待度 — DMM・一撃とも同値
  - 戦国乙女ボーナス継続ゲーム数（40G以上の比率）— DMM「実質戦国乙女ボーナスゲーム数割合」＝一撃「継続ゲーム数の振り分け」と完全一致
  - エピソードボーナス：ウジマサ・ヒデアキ発生率 — DMM掲載の選択率テーブルを数値チャンネル化
  - AT終了画面：モトチカ＆ソウリン＆ドウセツ＆モトナリの選択率 — DMM掲載の選択率テーブルを数値チャンネル化
  - エンディング シークレットトーク：チャンスキャラ（敵3人）選択率 — DMM掲載の選択率テーブルを数値チャンネル化
- **判別要素**（②）: AT終了画面（設定3・5示唆／設定2・4示唆のキャラ組み合わせ2種＋可/吉/良/優/極スタンプ5種）・エピソードボーナス（カンスケ奇数示唆／ソウリン偶数示唆）・獲得枚数表示（222〜666枚OVER）の計14要素を、DMMの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と強さ（tier）に応じて参考程度の重みだけを加える
  - なお、DMMに設定別の具体的な選択率テーブルが掲載されている「モトチカ等」（AT終了画面）と「ウジマサ・ヒデアキ」（エピソードボーナス）は、あいまいな示唆チップではなく①の専用数値チャンネルとして数値化したため、重複計上を避けるため②のチップには含めていない
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「戦国乙女4」設定差・設定判別要素](https://1geki.jp/slot/l_otome_keigan/0/)（2026/02/25更新）を確認したところ、CZ「乙女アタック」突入率・「戦国乙女ボーナス」の継続ゲーム数・「オウガイバトル」の初戦勝率・ゾーン外のボーナス当選は、いずれもDMMぱちタウンの内容と数値まで完全に一致していた。一撃側にのみ掲載されていた**「ボーナスとATを合算した初当り確率」**（設定1: 1/272.2〜設定6: 1/217.1）は、DMMには存在しない独立した合算テーブルだったため新たに数値チャンネルとして採用した。一方、一撃の「通常時のAT直撃発生率」はDMMの「通常時・AT直撃確率」と同じ条件（(超)強カワループ滞在外）を謳いながら数値が食い違っていたため、DMM側の数値のみを採用し一撃側は不採用とした（詳細は次項）。

## データについて

以下は両サイトを確認したが、理由があって採用しなかった項目：

- **一撃「通常時のAT直撃発生率」**（設定1: 1/9776.9〜設定6: 1/5132.2）: DMMの「通常時・AT直撃確率」（設定1: 1/10922.7〜設定6: 1/5461.3）と、どちらも「（超）強カワループ滞在外」という同一の条件を明記しているにもかかわらず数値が大きく食い違っていた。同一チャンネルとして扱うと二重計上になり、かつ数値差の原因（両社の自社調査手法の違いか）を特定できないため、より詳細な条件説明があるDMM側の数値のみを採用し、一撃側は不採用とした。
- **AT終了画面「モトチカ＆ソウリン＆ドウセツ＆モトナリ」の高設定示唆［弱］チップ**: DMMに設定別の具体的な選択率（33.3%〜40.0%）が掲載されていたため、あいまいな「示唆」チップではなく①の専用二項尤度チャンネルとして数値化し、②のチップとしては重複計上を避けるため未採用とした。
- **エピソードボーナス「ウジマサ」「ヒデアキ」個別の高設定示唆チップ**: 同様に発生率テーブル（約20%〜約33%）が存在するため①の数値チャンネルとして採用し、②のチップとしては重複計上を避けるため未採用とした。
- **エンディング シークレットトークで1人目に紹介されると示唆となる残り4キャラ**（イエヤス・ノブナガ・ウジマサ・ヨシテル、いずれも「高設定に期待」とのみ記載）: 「敵3人」のみ設定別選択率（約1%〜約25%）が判明しているが、他4キャラは具体的な数値の記載がなく定性的な「高設定に期待」としか書かれていないため、ハード除外・示唆重みのいずれにも数値化できず未採用とした。
- **一撃「登場キャラ・枚数表示・終了画面での設定示唆」の各説明**（エピソードボーナスキャラ／獲得枚数3桁ゾロ目／AT終了画面スタンプ／エンディングキャラ紹介）: いずれもDMM側でより具体的な数値・キャラ名付きで判別要素として掲載済みの内容と一致するクロスチェック的な記述であり、追加の新情報を含まないため個別要素としては未採用とした（内容の一致は確認済み）。
- **DMM「ボーナス30G以上当選時のボーナスゲーム数振り分け」**（ボーナス準備中の昇格抽選前の中間テーブル、設定1: 87.5/10.2/2.3%〜設定6: 81.1/14.1/4.7%）: 準備中の昇格抽選を経た後の最終的な継続ゲーム数を示す「実質戦国乙女ボーナスゲーム数割合」テーブル（DMM・一撃で完全一致）の方がプレイヤーが実際に目にする結果を反映しているため、そちらを①の数値チャンネルに採用し、中間テーブルの方は未採用とした。
- **立ち回りポイント**（DMM・一撃とも、「天井」のスルー回数リセット条件など）: 設定判別要素ではなく実戦上の立ち回り情報のため対象外とした。
- **打-WIN LITE利用時の1000ゲーム毎の設定示唆**（一撃）: 専用アプリ利用時のみ出現する要素であり、本ツールが想定する「実戦データの手入力」という枠組みに合わないため未採用とした。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 実装パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲：`numericInputs`配列（id列挙順）→イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→`render()`内の分割代入、の3点の並び順を完全一致させて配線漏れを防止
- 空欄安全性: `parseField(el)`ヘルパーが空欄を`null`（データなし＝そのチャンネルをスキップ）、非空欄を非負整数として返す。総G数を共有する3チャンネル（初当り・AT直撃・ゾーン外ボーナス）は、それぞれ自分自身のk欄が`null`でないか（＝空欄でないか）を個別にチェックしてから尤度計算に加える実装を[モンハンライズ 設定判別ツール](../2026-09-07-monhun-rise/)の`render()`からそのまま踏襲。これにより「1つのk欄だけ空欄で残した」場合に「0回確認できた」と誤解釈されるのを防いでいる
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 「初当り回数（戦国乙女ボーナス＋AT直撃 合算）」「うちAT直撃当選回数」「ゾーン外ボーナス当選回数」は同じ「総G数」を母数とする独立した二項分布のため、`totalG`の入力欄は1つだけ用意し、それぞれの当選回数を別欄で入力する形にした（東京喰種ツールの下段リプレイ・AT直撃グループと同じパターン）
