# スマスロ 吉宗 設定判別ツール

「吉宗（スマスロ）」（サボハニ、機種ID 4778、2025年04月21日導入）の設定判別を助ける計算ツール。**2026年04月06日導入の「真打 吉宗」（大都技研、機種ID 4983）とは別機種です。** ページタイトルが「吉宗」単独（「真打」の付かない旧作＝サボハニ製の初代スマスロ版）であることを確認したうえで採用しました。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4778#anc-point)（2026/08/18更新）と[一撃「吉宗（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_yoshimune/0/)（2026/07/07更新）の両方を全文確認したうえで、公開されている判別要素をDMMぱちタウンの分類順（終了画面系→小役確率→直撃当選）のまま反映し、実戦データと花札の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-yoshimune-original/

## 機能

- **数値データ**（①）: 総G数を母数とする4指標を独立した二項尤度チャンネルとして入力可能
  - **ボーナス初当たり確率**（一撃のみに設定1〜6の完全テーブルが掲載）
  - **共通俵出現率**（左1stで右下がりに揃う俵。ダイトモでのカウントを推奨）
  - **通常時リーチ目出現率**（高確率・鷹狩り・連続演出中を除く。1回でも出現すれば高設定の期待大）
  - **純ハズレ前兆発生率**（本前兆・フェイク前兆が1:1のため合算値で判定）
  - 4指標とも母数（総G数）が共通のため、1つの見出しにまとめて入力できます
- **判別要素**（②）: ボーナス終了画面の花札（枠色7種）をDMMぱちタウンの分類のままタップ式カウンターで記録
  - 金文字表示の「〜濃厚」（銅枠＝2以上濃厚／銀枠＝3以上濃厚／金枠＝4以上濃厚／ピンク枠＝5以上濃厚／虹枠＝6濃厚）は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「高設定示唆」（黒枠：青短＝弱、赤短＝強）は確定情報ではないため、ハード除外はせず出現回数と強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

DMMぱちタウンと一撃、両方のページを全文確認したところ、共通俵出現率・通常時リーチ目出現率・純ハズレ前兆発生率（本前兆／フェイク前兆／合算）・ボーナス終了画面の花札の示唆内容は、両サイトで数値・内容ともに完全に一致していた（花札の枠内絵柄の表記のみ「ピンク枠（桜）」〔DMM〕／「紫枠（桜に幕）」〔一撃〕で揺れがあるが示唆内容＝設定5以上濃厚は同一。本ツールはDMM表記に統一）。

一撃側にのみ掲載されていたのが**ボーナス初当たり確率の設定1〜6完全テーブル**（1/378.9〜1/292.4）。DMMぱちタウンの「設定判別・推測ポイント」欄にはこのテーブルの掲載がなく（機種概要のグラフ画像のみでテキスト値の記載なし）、一撃側でのみ確認できたため、本ツールでは一撃の値を採用し、`P_AT_INITIAL`のコメントにその旨を明記した。

なお、通常時リーチ目出現率は定義上「高確率・鷹狩り・連続演出中を除く」母数だが、プレイ中に除外分だけを正確に数えるのは非現実的なため、本ツールでは近似として総G数を母数に採用している（コード内コメントに明記）。純ハズレ前兆発生率も同様に、背景抽選の性質上は正確な母数がハズレ消化数寄りになるが、総G数を近似母数として扱っている。

## データについて

以下は本文を確認したうえで、あえて数値チャンネル・判別要素チップのいずれにも採用しなかった項目とその理由。

- **通常モード移行率**（［設定変更時］／［通常A・通常B・天国A］／［天国B］／［天国準備］の4パターン×5モードの遷移率テーブル、DMM・一撃とも設定差データあり）：プレイヤーが現在どの内部モードに滞在しているかをリアルタイムかつ正確に把握することは実質不可能であり（ステージ演出等の間接的な手がかりしかない）、入力自体が非現実的なため対象外とした。
- **鷹狩りモード示唆演出**（リール変則始動・鷹の羽の出現パターン）：これらは滞在している「鷹狩りモード（A〜E）」の示唆であり、設定（1〜6）そのものの判別要素ではないため対象外とした。
- **流鏑馬演出・ゲーム数消化時の前兆／夕方ステージ**（42G〜49G・98G〜105G・200G・300G台・400G台・600G・800G台の各タイミングでの示唆）：これらは「通常モード（通常B以上・天国準備）」の示唆であり、設定そのものの判別要素ではないため対象外とした。
- **ボーナス終了画面のPUSHボイス**：滞在している通常モードや鷹狩りモードの示唆であり、設定の判別要素ではないため対象外とした。
- **奥方出現・ちび姫の特定パターン**：「前兆のチャンス」「高確率濃厚」というゲーム内状態の示唆であり、設定そのものの判別要素ではないため対象外とした。
- **ボーナス中の演出法則**（吉宗BIGのカットイン強弱、爺BIGのキーン告知パターン、姫BIGのイコライザー、BIG中の7揃い高確テーブルなど）：いずれも「1G連（出玉上乗せ）」への期待度を示すものであり、設定差データではないため対象外とした。
- **裏鷹狩り中のレア役成功率**：「全設定共通」と明記されており、設定差データではないため対象外とした。
- **小役確率（レア役確率：チェリー・松・チャンス目・解除チェリー）**：DMM側の表に「レア役確率は全設定共通」と明記されており、設定差データとしては利用できないため対象外とした。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 参照実装として[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)の白／黒／赤パレットのCSS（`<style>`ブロック）をそのまま流用し、HTMLの骨格（ヘッダー→広告枠→①数値データ→②判別要素→広告枠→③結果→出典→免責事項→広告枠→フッター）とJSアーキテクチャ（`logBinomLikelihood`・`computeCandidateSettings`・`buildChips`・`render`のソフトマックス正規化）も踏襲した
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 空欄の数値フィールドは「未入力（データなし）」として扱い、「0回観測」とは区別する。`parseField(el)`ヘルパーが空欄なら`null`を返し、各チャンネルの`logBinomLikelihood`呼び出しはそのチャンネル自身のフィールドが`null`でないことを個別にチェックしてからゲートする（[スマスロ モンスターハンターライズ 設定判別ツール](../2026-09-07-monhun-rise/)の`render()`と同じパターンを踏襲）。これにより、共有の総G数（`totalG`）だけ入力して他のK値を空欄にした場合でも、「0回」と誤って計算されることはない
- `numericInputs`配列（要素の並び順）→ イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→ `render()`内の分割代入、の3点の並び順が一致していることを確認済み
- 4つの数値チャンネル（ボーナス初当たり・共通俵・通常時リーチ目・純ハズレ前兆）はすべて母数（総G数）が共通のため、1つの見出しにまとめている（判別要素は本機種では花札1カテゴリのみのため、見出しの分割は発生しない）
