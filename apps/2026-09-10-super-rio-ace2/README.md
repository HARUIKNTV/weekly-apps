# スマスロ スーパーリオエース2 設定判別ツール

山佐（山佐ネクスト）「スマスロ スーパーリオエース2」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4984#anc-point)（2026/09/08更新）に掲載されている判別要素を分類（終了画面サイン／ケロットトロフィー／獲得枚数表示／エンディング中PUSHボイス）のまま反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

## 一撃（1geki.jp）とのクロスチェック

[一撃「スーパーリオエース2（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_sp_rioace2/0/)（2026/06/23更新）を確認したところ、両ソースの掲載内容はおおむね一致していた。

- ボーナス直撃当選率・スイカ成立時のノワールルーム成功率・規定リプレイ(50回)到達時のハワードゲーム当選率・リナサイン出現率の4テーブルは、設定1〜6の数値が両サイトで完全に一致していたためそのまま採用
- 初当たり（ボーナス/AT）確率・ノワールルーム突入率（基礎突入率）の完全な1〜6テーブルは一撃側にのみ掲載されていたため、一撃を出典として採用
- ケロットトロフィー（銅／銀／金／ケロット柄／虹）と獲得枚数表示（246枚OVER／456枚OVER／666枚OVER／803枚OVER）は両ソースで一致
- エンディング中PUSHボイス（黄/緑/赤/虹ランプ）の示唆区分も両ソースで一致。ただしDMM側に載っていた「設定1 vs 設定6のボイス振り分け割合（青59.0%→45.0%等）」は設定2〜5の値が欠落しておりチップの重みには使わず、区分（弱/中/強/濃厚）のみをチップとして採用

## 機能

- **数値データ**（①）: 以下4系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - 初当たり・ボーナス直撃・ノワールルーム突入（総G数ベース、3チャンネルを同じ総G数入力で共有）
  - 規定リプレイ数(50回)到達時のハワードゲーム当選率
  - スイカ成立時・次回ノワールルーム成功当選率
  - リナサイン出現率（ボーナス終了画面到達回数ベース）
- **判別要素**（②）: ボーナス終了画面サイン、ケロットトロフィー、獲得枚数表示、エンディング中PUSHボイスの全15項目を、DMM／一撃の分類のままカテゴリラベル付きでタップ式カウンターに記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/中/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて

以下は両ソースで確認できたが、今回は採用を見送った：

- **設定変更時ボーナススルー回数振り分け**（DMM掲載: 0回1.6%／1回7.8%／2回3.1%／3回20.3%／4回67.2%）— 設定変更直後のみ有効な一回性の分布であり、実戦中の継続的な二項尤度チャンネルとしては使えないため見送り
- **リール枠エフェクトの矛盾検出演出**（DMM掲載: ハズレ時は「高設定のチャンス」、本前兆時は「ハズレたがフェイク」濃厚）— 発生条件・出現率の具体的な記載がなく定量化できないため見送り
- **エンディング中PUSHボイスの色別振り分け率**（設定1 vs 設定6のみDMMに記載、青59.0%→45.0%／黄30.0%→35.0%／緑10.0%→16.0%）— 設定2〜5の値が欠落しており完全な1〜6テーブルが組めないため、チップの区分情報（弱/中/強/濃厚）のみ採用し数値チャンネルとしては見送り

## 技術メモ

- HTML/CSSの骨格・配色（白/黒/赤基調）・JS計算ロジック（`logBinomLikelihood`によるチャンネルごとの二項対数尤度合算とソフトマックス正規化、`ITEMS`配列によるチップ生成）は `apps/2026-09-06-tokyo-ghoul-slot-checker/` を踏襲
- 空欄安全性: `parseField()`ヘルパーで「未入力（null）」と「0回観測」を明確に区別し、総G数を共有する3チャンネル（初当たり／ボーナス直撃／ノワールルーム突入）もそれぞれ自分のk欄が空欄なら計算をスキップする（`apps/2026-09-07-monhun-rise/`のパターンを採用）
- 依存ライブラリなしの単一HTMLファイル。ビルド不要で、そのまま静的ホスティング可能
