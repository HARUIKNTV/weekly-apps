# L邪神ちゃんドロップキック 設定判別ツール

「L邪神ちゃんドロップキック」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5020#anc-point)（2026/09/08更新、全文）に掲載されている判別要素をそのままの分類（CZ関連→TUC→終了画面系→ボーナス消化中）で反映した。DMMぱちタウン側にはAT（人生シアター）初当たり・ボーナス初当たりの設定別数値テーブル自体が掲載されていない（実際にページを確認したところ、通常時の小役確率も「全設定共通」と明記されているのみで、設定差のある初当たり確率は数値化されていなかった）ため、この2つの数値チャンネルのみ[一撃「邪神ちゃんドロップキック（スロット）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_jashinchan/0/)（2026/08/31更新、全文）に掲載されている完全な設定1〜6テーブルから採用した。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-08-jashin-chan/

## 一撃（1geki.jp）とのクロスチェック

DMMぱちタウンと一撃の両方を全文読み比べた結果、判別要素（CZ前半のハズレ対応アイテム、TUC設定示唆シール、AT終了画面、クジラッキートロフィー、小悪魔ボーナス中のキャラ紹介）の示唆内容はすべて完全に一致していた。数値データについては、一撃側にのみAT初当たり確率（設定1: 1/758.2〜設定6: 1/606.2）とボーナス初当たり確率（設定1: 1/253.1〜設定6: 1/210.0）の完全な設定1〜6テーブルが掲載されており、DMM側にはこれに相当する数値テーブルが存在しなかったため、この2チャンネルは一撃の値のみを採用した。

なお、DMMぱちタウン側の「タワシ／タライ／落雷」の示唆表現は「HITで設定1否定」、一撃側は「当たれば設定2以上!?」となっており、文言は異なるが実質的に同じ内容（設定1のみを除外する）だったため、DMMの`deny`（否定）形式で統一して実装した。

## 機能

- **数値データ**（①）: AT（人生シアター）初当たり確率・ボーナス初当たり確率（いずれも一撃調べ、総G数ベースの2チャンネル）を独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: DMMぱちタウンの分類のまま、以下5カテゴリ・全45種類をカテゴリラベル付きの1つのリストにまとめてタップ式カウンターで記録
  - **CZ前半のハズレ対応アイテム**（3種: タワシ・タライ・落雷）— いずれも特定キャラにHITすれば設定1を否定
  - **TUC設定示唆シール**（全7種）— 芽依・遊佐＆氷ちゃん・キョンキョン＆ランラン・ぴの＆ぽぽろんなどの奇偶示唆と、リエール＆ペルセポネ1世（設定4以上濃厚）・エキュート＆アトレ（設定6濃厚）の金文字濃厚パターン
  - **AT終了画面**（10種）— ミノス・メデューサ・ぺこら・ぽぽろん・ゆりねA/Bの示唆パターンと、悪だくみ／水着／パジャマ／全員集合の濃厚パターン
  - **クジラッキートロフィー**（5種: 銅・銀・金・クマノミ柄・虹）— 初当りの小悪魔ボーナスを除く全ボーナス終了画面で出現し得る濃厚パターン
  - **小悪魔ボーナス中のキャラ紹介**（20種）— 8キャラの通常示唆＋3キャラの弱示唆＋2キャラの強示唆、邪神ちゃん脳内キャラ5種の否定パターン、パーフェクト邪神ちゃん（4以上濃厚）・悪魔コスゆりね（6濃厚）の濃厚パターン
  - 金文字表示の「〜濃厚」「〜否定」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて

以下は両サイトを確認したが、理由があって採用しなかった項目：

- **小悪魔ボーナス中のキャラ紹介のパターン別の法則**（両サイト掲載）: 「1回のボーナスで高設定示唆キャラが2回登場で設定2以上示唆、3回で設定3以上示唆、4回で設定4以上濃厚」「1回のボーナスでエキュートとアトレが登場で設定2以上濃厚」という、単発の出現回数ではなく「1回のボーナス消化中」という時間区切りの中での複数キャラ同時カウントを要する法則。本ツールの単純な累積カウンター方式ではボーナス単位の区切りを扱えないため、誤集計を避けて採用しなかった
- **CZ前半のハズレ対応アイテム「落雷」の出現しやすさ傾向**: 「高設定ほどハズレ成立時に落雷が出現しやすい」という記述のみで、具体的な設定別の数値・比率は両サイトとも非掲載のため未採用
- **AT直撃当選・AT引き戻し当選**（一撃）: いずれも「設定差あり!?」と記載があるのみで、東京喰種ツールのケースとは異なり具体的な設定別数値テーブルが一撃・DMMともに非掲載だったため未採用
- **エピソードボーナス直撃確率**（DMM）: 「全設定共通 1/19840.0」と明記されており設定差がないため対象外
- **小役確率**（DMM解析情報通常時）: リプレイ・ベル・スイカ・邪神ちゃん揃いなどいずれも「全設定共通」と明記されており、判別要素として使う意味がないため対象外
- **クジラッキーの「ラッキーカスタム」**（一撃）: 「ホールが独自に出現バランスを調整できる」機能がある旨の注記があり、設定差データとしての信頼性が下がるため、示唆の強さ自体は変更せずそのまま採用しつつ、この注記自体は本文には反映していない

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: AT初当たり・ボーナス初当たりそれぞれの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 実装パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲：`numericInputs`配列（id列挙順）→イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→`render()`内の分割代入、の3点の並び順を完全一致させて配線漏れを防止
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する仕組みは東京喰種・いざ番長の両ツールと共通
- 空欄の数値フィールドは「未入力（データなし）」として尤度計算をスキップし、「0回観測」とは区別する（`parseField`）。片方だけ空欄のまま総G数だけ入力された場合に誤って0回と解釈しないための安全策
