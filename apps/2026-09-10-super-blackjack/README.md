# スマスロ「スーパーブラックジャック」設定判別ツール

セブンリーグ（山佐グループ）のスマスロ「スーパーブラックジャック（型式名: LスーパーブラックジャックSLDC）」の設定判別ツールです。DMMぱちタウン「[スマスロ スーパーブラックジャック 設定判別・推測ポイント](https://p-town.dmm.com/machines/4712#anc-point)」（2026/09/09更新）を主なデータソースとし、一撃（1geki.jp）「[スーパーブラックジャック（スマスロ）設定差・設定判別要素まとめ](https://1geki.jp/slot/l_sbj/0/)」（2026/08/03更新）で数値・示唆内容をクロスチェックしています。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-super-blackjack/

## 機能

- **① 数値データ**: 以下の独立した確率チャンネルを、二項分布の対数尤度（log-likelihood）で計算します。空欄の項目は「データなし」として扱われ、0を入力した場合のみ「0回」として計算に含まれます。
  - ボーナス初当り確率（総G数ベース）
  - 斜めスイカ確率（総G数ベース、上と共通の総G数を使用）
  - ボーナス高確率への移行率（総G数ベースの集計値、上と共通の総G数を使用）
  - リオチャンス高確率突入確率（総G数ベース、上と共通の総G数を使用）
  - 斜めスイカからのストックタイム直撃当選率（斜めスイカ成立回数を分母として使用）
  - チャンス目成立時のボーナス直撃当選率
  - チャンス目成立時のボーナス高確移行率（通常滞在時、チャンス目成立回数を分母として上と共通）
- **② 判別要素**: 出現したらタップしてカウントするチップ形式。以下の4カテゴリ、計25個の要素を収録。
  - ケロットトロフィー（銅・銀・金・ケロット柄・虹の5段階、いずれも「◯以上濃厚」のハード確定要素）
  - ダイスチェック（示唆通りに外れた場合。ゾロ目の予告回数が外れることで下限設定が濃厚になる5パターン）
  - ハワイステージ中の違和感演出（下パネルの消灯・点滅パターンによる6段階の濃厚要素）
  - ボーナス関連キャラ示唆（トランプ役／ボーナス終了画面／エピソード・エンディングボーナスに共通で出現するキャラクター示唆。クラーク・ティファニー／イルエル・ローザ・ハワード・ミント・リオ・リナの弱/通常/強の「示唆」と、リオ＆リナ（ジョーカー）＝5以上濃厚、リオ＆リナ＆ミント＝6濃厚のハード確定コンボ）
- **③ 結果**: 全チャンネルの対数尤度を合算し、ハード要素で候補設定を絞り込んだ上でsoftmax正規化して設定1〜6の期待度バーを表示します。

## 1geki.jp クロスチェックについて

一撃（1geki.jp）のページでは、DMMぱちタウンと同一の数値（ボーナス初当り確率・斜めスイカ確率・ストックタイム直撃当選率・ボーナス高確移行率・100G到達時の内部状態移行率・ケロットトロフィーの示唆内容など）が独立に掲載されており、両者が一致することを確認した上でツールに反映しています。またキャラクター示唆（クラーク／ティファニー／ローザ／ハワード／ミント／リオ／リナの弱・通常・強のティア分け）は1geki.jp側のより詳細な記載を採用しました。

## データについて

以下は発見したものの、理由がありツールには反映していません。

- **ボーナス高確率滞在時のボーナス当選率【全役トータル】**（設定1〜3: 50.0%、設定4・5: 53.6%、設定6: 57.2%）: 「ボーナス高確率」という不可視の内部状態に入っている間の全スピン数と当選数を正確に区別して記録する必要があり、プレイヤーが実戦中にリアルタイムで追跡するのは現実的に困難なため見送りました。
- **ボーナス高確率滞在時のレア役/小役連以外でのボーナス当選率**（設定1: 約1.0%、設定6: 約1.6%）: 設定2〜5のデータが「???」として非公開のままであり、6設定分の完全なテーブルが存在しないため見送りました。
- **BBスルー最大規定回数振り分け**（1スルー〜4スルーの4区分パーセンテージ）: 単純な二項分布（n回中k回成功）に落とし込めないカテゴリカルな分布であり、かつ「スルー回数の上限がどこで発動したか」を毎回のボーナス消化ごとに正確に記録する必要があるため、本ツールのアーキテクチャとは相性が悪く見送りました。
- **100G/200G/400G/600G/800G/300G/500G/700G/900G到達時の内部状態移行率（偶数・奇数の百の位ごとの個別テーブル）**: より詳細な内部挙動のデータですが、既に採用している集計値「ボーナス高確率への移行率（総G数ベース）」と実質的に同じ現象を計測しており、個別テーブルまで採用すると二重計上になる上、プレイヤーが到達G数の百の位を逐一記録する必要があり実用性が低いため、集計値チャンネルのみを採用しました。

## 技術メモ

本ツールは [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) のCSS・HTML構成・JS計算ロジック（`logBinomLikelihood` による二項分布対数尤度、`computeCandidateSettings` によるハード要素の候補絞り込み、`buildChips` によるチップUI生成、softmax正規化）をベースに作成しました。空欄フィールドの扱い（`parseField` で `null` を返し、「未入力」と「0回」を区別してチャンネルごとに独立してゲーティングする方式）は [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/) の実装パターンを踏襲しています。フィードバックウィジェット（画面右下の💬ボタン、FormSubmit.co経由）も同ツールからそのまま流用しています。
