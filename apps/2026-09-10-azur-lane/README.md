# スマスロ アズールレーン THE ANIMATION 設定判別ツール

「L アズールレーン THE ANIMATION」（京楽、2025年08月04日導入）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4847#anc-point)（2026/09/05更新）に掲載されている判別要素をそのままの分類（海戦ボーナス・AT終了画面→玉ちゃんトロフィー→獲得枚数表示→加賀バトル勝利時のPUSHボイス→明石チャレンジ成功時の告知ゲーム数→加賀バトル前半失敗時のキャラ紹介シナリオ）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-azur-lane/

## 機能

- **数値データ**（①）: 以下の系統をそれぞれ独立した二項尤度チャンネルとして入力可能（総G数を共有する4系統は「総G数は上と共通」の見出しでまとめ、入力欄の重複を避けている）
  - **AT「アズールレーンRUSH」初当り確率**（総G数ベース。DMMぱちタウンには合算値の完全な設定1〜6テーブルが掲載されていないため、一撃（1geki.jp）掲載の完全テーブルを採用）
  - **ボーナス初当り確率（合算）**・**青7揃い（海戦ボーナス）確率**（いずれも総G数ベース。青7揃いはボーナスの中でも高設定ほど選ばれやすい特に示唆性の強いチャンネル）
  - **共通ベル・弱チェリー・弱スイカ成立回数**（総G数ベース。3役とも独立した小役で、それぞれ個別の入力欄を用意）
  - **明石チャンス成功時の海戦ボーナス当選率**（総G数とは独立した母数＝明石チャンス成功回数ベース）
- **判別要素**（②）: 海戦ボーナス・AT終了画面（示唆キャラ5種）、玉ちゃんトロフィー（5色）、獲得枚数表示（4種）、加賀バトル勝利時のPUSHボイス（天井到達時のみ発生する専用ボイス2種）、明石チャレンジ成功時の告知ゲーム数（天井到達時の残りゲーム数奇偶、2種）、加賀バトル前半失敗時のキャラ紹介シナリオ（4種）——計20種類をDMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「アズールレーン（スマスロ）」設定差・終了画面・設定判別要素まとめ](https://1geki.jp/slot/l_azurlane/0/)（2026/02/16更新）を全文確認したところ、掲載されている数値・示唆内容はDMMぱちタウンの内容と完全に一致していた（ボーナス初当り、青7揃い確率、共通ベル・弱チェリー・弱スイカ確率、玉ちゃんトロフィー、加賀バトル前半失敗時のキャラ紹介シナリオとその振り分け、加賀バトル勝利時のPUSHボイス、明石チャレンジ成功時の告知ゲーム数、AT終了時の状態移行）。

一撃側にのみ掲載されていたのが**AT「アズールレーンRUSH」初当り確率（合算値）の設定1〜6完全テーブル**（設定1: 1/598.9 〜 設定6: 1/467.5）。DMMぱちタウンのページには海戦ボーナスや青7揃いの個別確率は掲載されているが、ボーナス経由・直撃経由などを含めた「AT自体の初当り確率」の完全な設定別テーブルは見当たらず、一撃側でのみ確認できたため、本ツールでは一撃の値を採用し`P_AT_INITIAL`のコメントにその旨を明記した。

なお一撃の「加賀バトル前半失敗時のキャラ紹介」表では瑞鶴の示唆が「設定4･示唆」と表記が一部欠落していたが、DMMぱちタウン側で「設定4・6示唆」と明記されており、シナリオ選択率の数値（設定4:1.6%、設定6:1.9%など）もこの解釈と整合していたため、DMM側の表記を採用した。

## データについて

以下は本文を確認したうえで、あえて数値チャンネル・判別要素チップのいずれにも採用しなかった項目とその理由。

- **海戦ボーナス◯回目までのAT当選期待度**（1回目/3回目まで/5回目まで/7回目までの設定1〜6完全テーブル）：同一セッション内のボーナス消化が積み重なるほど参照範囲が変わる累積・依存確率であり、独立した二項試行の繰り返しとして扱うと同一セッション内のボーナス消化を過剰カウントしてしまうため未採用。
- **AT終了後の内部状態（超高確）移行率**（設定1〜6完全テーブル、設定1:0.4%〜設定6:0.8%）：DMMぱちタウン自身が「内部状態なので判別は難しい」と明記しており、プレイヤーが超高確突入を直接判定する手段がレア役非経由での脅威海域ステージ到達という間接的な観測に限られるため、タップカウンターや数値入力に落とし込むには不確実性が大きすぎると判断し未採用。
- **ボーナス規定回数示唆のAT終了画面**（ピクニック／仲良し4人／最後の晩餐風／セイレーン）：これらは次回ボーナスの規定回数（残りスルー回数）を示唆するものであり、設定（1〜6）そのものの判別要素ではないため対象外とした。
- **テンパイボイス**（青7・白7揃い時の「真なる無双を見せてやる！」「あなたの碧き航路に祝福を」など）：示唆内容が「青7揃いか白7揃いか」という別軸の条件に依存しており、入力を複雑にしないためのシンプルさを優先して未採用。またAT当選期待度寄りの示唆でAT濃厚パターンを含み、設定判別要素としては副次的と判断した。
- **加賀バトル前半のチャンスアップ回数別AT期待度**：AT当選の期待度を示すものであり、設定差データではないため対象外。
- **ロングフリーズ確率**：DMMぱちタウンに掲載されているのは「1/161319.4」という単一の値のみで、設定別の内訳が確認できなかったため対象外。
- **天城バトルの成功期待度・海戦モードの移行率・ループ率振り分け**：いずれも設定によらない共通テーブル（設定差なし）であることが本文中に明記されているため対象外。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能。CSS・HTML骨格・JSアーキテクチャ（`logBinomLikelihood`・`computeCandidateSettings`・`buildChips`・`render`・ソフトマックス正規化）は[apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)から流用
- 空欄安全性: `parseField()`ヘルパーで空欄を`null`（＝データなし）として扱い、`0`を明示入力した場合のみ「0回」として計算に反映する。各チャンネルは自分自身のk欄が`null`でない場合にのみ尤度計算へ寄与する（[apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)のパターンを踏襲）
- 尤度計算: 各二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 総G数を共有する4チャンネル（AT初当り／ボーナス初当り／青7揃い／共通ベル・弱チェリー・弱スイカ）は、`totalG`の入力欄を最初の見出しにのみ配置し、以降の見出しには「総G数は上と共通」と明記してk欄のみを追加。JS側では`numericInputs`配列の同じ`totalG`要素を全チャンネルの尤度計算で共有している
