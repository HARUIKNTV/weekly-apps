# スマスロ「攻殻機動隊」設定判別ツール

サミー「スマスロ 攻殻機動隊」（2026年2月2日導入）の設定判別ファンツールです。DMMぱちタウンの機種ページ [「スマスロ 攻殻機動隊」設定判別・推測ポイント](https://p-town.dmm.com/machines/4931#anc-point)（2026/09/09時点で参照）に掲載の確率表・示唆演出データをもとに、入力した実戦データから各設定（1〜6）の期待度を二項対数尤度の合算→softmaxで算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-koukaku-kidoutai/

## 機能

- **① 数値データ**: 以下8つの独立したチャンネル（それぞれ異なる分母 n を持つため、見出しを分けています）
  - AT初当たり確率・CZ出現率（総G数ベース、共通の総G数を分母とするため見出しを共有）
  - S.A.M.視覚フラグ保有率（白の境界到達時）
  - タチコマS.A.M.当選率（CZ失敗後の200G/400G到達時、合算値）
  - AT当選時の引き戻しストック当選率（1個・2個ストック合算）
  - 設定変更・AT終了後の高確以上移行率（高確+超高確の合算）
  - 殲滅ZONE「紫」発展時のAT直撃確率
  - CZ後のモード移行率（通常Aへの移行率。高設定ほど通常A以外へ移行しやすい）
  - AOI（アタック・オン・インシデント）後の裏上位AT当選率
  - 空欄は「データなし」として扱われ、その項目だけ計算対象から除外されます（0回として扱うと誤判定を招くため）。
- **② 判別要素**: 6カテゴリ・25個の示唆演出をタップでカウント。金文字の「濃厚/否定」は候補設定をハード除外・確定し、斜体の「示唆」は弱／通常／強の重みだけを加える参考情報として扱います。
- **③ 結果**: 設定1〜6ごとの期待度バーと、現在の候補・最有力設定のサマリーを表示します。

## 1geki.jp とのクロスチェック

一撃（1geki.jp）の [「攻殻機動隊（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_kokaku/0/)（2026/09/02更新）と数値を突き合わせ、以下の表がDMM側と完全に一致することを確認しています。

- CZ出現率（設定1〜6）
- S.A.M.視覚フラグ保有率
- タチコマS.A.M.当選率（200G/400G合算）
- 引き戻しストック当選率（1個・2個ストック合算）
- 設定変更・AT終了後の高確移行率（DMMの「通常／高確／超高確」3分割の合算値と一撃の「高確+超高確」合算値が一致）
- 殲滅ZONE「紫」発展時のAT直撃確率
- 裏上位AT当選率（AOI後）

AT初当たり確率・CZ後のモード移行率（通常A率）は一撃側にのみ完全な1〜6表が掲載されていたため、そちらを採用しています。

## データについて（見つけたが採用しなかった項目）

- **殲滅ZONE「青〜赤」発展時のCZ以上当選期待度**: DMM側の表に欠損（設定2行が1マスしか値を持たず、他の設定の緑・赤発展時の値が取得できなかった）があり、正確な6設定分の数値が確認できなかったため採用を見送りました。
- **タチコマのUIアクション（手を振る／縦揺れ／横になる／大きくなる）**: これらは「S.A.M.視覚フラグを保有しているか」という別のゲーム内隠しフラグを示唆するものであり、設定そのものの期待度に直結する数値ではないため、本ツールの判別要素からは除外しました。
- **モードのみを示唆する演出（後姿素子＝モードB以上濃厚、公安9課赤枠＝モードC以上濃厚、電脳素子紫枠＝モードC以上濃厚[強]、ポーカー＝高モード示唆、2ndGIG＝白の境界権利保有時専用）**: いずれも「モード」（内部状態）を示唆するものであり、設定への言及がないため除外しました。ただしアオイ（金枠）のみ「モードD濃厚＋設定4以上濃厚」と設定への直接言及があったため採用しています。
- **エンディング上パネル色の「緑（奇数＆高設定示唆）」「赤（偶数＆高設定示唆）」**: 2つの示唆軸が組み合わさっており、単純な設定集合として表現すると誤った絞り込みになりかねないため、確度の高い単軸の色（青・黄・紫・虹）のみ採用しました。
- **青空単体・青空+笑い男マーク（CZ終了画面の復活パターン）**: 基本パターン、または再抽選演出の説明であり、設定示唆を伴わないため除外しました。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/` をベースに、CSS（白×黒×赤の配色、カード/チップ/バーのレイアウト）とJS構成（設定別確率配列、`logBinomLikelihood`、`computeCandidateSettings`、`buildChips`、`render`、softmax正規化）を踏襲しています。空欄フィールドの扱いは `apps/2026-09-07-monhun-rise/` の `parseField` パターン（空欄=null=「データなし」として当該チャンネルをスキップし、0件確定と誤読しない）を採用しました。
