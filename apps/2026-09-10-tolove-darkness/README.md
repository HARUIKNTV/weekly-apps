# L ToLOVEるダークネス 設定判別ツール

スマスロ「L ToLOVEるダークネス」（オリンピアエステート、2024/06/03導入）の設定判別ファンメイド計算機です。[DMMぱちタウン「L ToLOVEるダークネス」設定判別・推測ポイント](https://p-town.dmm.com/machines/4571#anc-point)（2026/08/31更新）を主データソースとし、[一撃「トラブル（スロット）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_toloveru_darkness/0/)（2026/03/11更新）で数値データと示唆要素をクロスチェックして作成しました。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-tolove-darkness/

## 機能

- 数値データ（AT「楽園計画」初当り確率、ハーレムモード中のウィスパー選択率）を入力すると、各設定の対数尤度をもとに設定期待度を算出
- ST終了画面（ハルルナスタンプ）・獲得枚数表示・隠れ凪の示唆演出をタップ式チップでカウントし、金文字の「濃厚」要素は候補設定を確定、斜体の「示唆」要素は参考程度の重みだけを加算
- 空欄の入力項目は「データなし」として扱われ、「0回観測」と誤認して計算に悪影響を与えないようにガード
- この機種は**設定1が存在しない5段階設定（設定2・3・4・5・6）**であるため、`SETTINGS = [2, 3, 4, 5, 6]` のオブジェクトキー方式で設定1を完全に除外（`apps/2026-09-06-valvrave-2/index.html` と同じパターン）

## 1geki.jpとのクロスチェック

- 「5段階設定/設定1非搭載」の記載を1geki側でも確認し、DMMぱちタウンのハーレムモード中枚数決定ゾーン比率表（設定2〜6の5列）と整合していることを確認
- AT「楽園計画」初当り確率（設定2: 1/352.0 〜 設定6: 1/311.1）は1geki側にのみ掲載されていた数値のため、そちらを出典として採用
- ST終了画面（ハルルナスタンプ：美柑／吉／良／優／極）と獲得枚数表示（456/555/666枚OVER）はDMM・1geki両方で同内容の記載を確認
- 隠れ凪の示唆（1000Gごとのセリフ・枠色）は1geki側のみに掲載。1geki自身が「濃厚!?」と疑問符付きで表記し断定を避けていたため、本ツールでもハード除外（濃厚）ではなく soft/weak の「示唆」として弱めの重みのみを加算する扱いにした

## データについて

以下は両サイトで確認したが、設定差の数値が公開されていない、または本文のみで表として整理されていなかったため採用を見送った：

- **天井ゲーム数のゲーム数契機当選率**：DMM・1geki双方とも「高設定ほどゲーム数契機で当たりやすい」という定性的な記述のみで、設定別の具体的な確率テーブルは非公開だったため除外
- **小役確率・CZ確率**：DMMの解析情報に掲載されているが、いずれも設定差のない全設定共通の確率として記載されていたため対象外（判別要素として意味を持たない）
- **ボーナス出現率グラフ**：DMM機種ページ上部にグラフ画像として存在するが、数値がテキストで公開されていないため取り込めず

これら以外の「設定判別・推測ポイント」に掲載された全項目（ST終了画面スタンプ、枚数決定ゾーンのウィスパー選択率、獲得枚数表示、隠れ凪の示唆）はツールに反映済みです。設定1のデータは存在しないため、いかなる項目についても補完・推測による捏造は行っていません。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/index.html` をベースに、CSS（白・黒・赤基調のテーマ）、HTML骨格（①数値データ／②判別要素／③結果のカード構成、広告スロット、フィードバックウィジェット）、JS設計（`logBinomLikelihood` による二項対数尤度、`computeCandidateSettings` によるハード除外、`buildChips` によるチップUI、softmax正規化）をそのまま踏襲しています。設定1が存在しない5段階設定への対応は `apps/2026-09-06-valvrave-2/index.html` の `SETTINGS = [...]` オブジェクトキー方式を採用し、欠損設定の補間は一切行っていません。空欄フィールドの安全な扱い（`parseField` ヘルパーで空欄を `null` として区別し、各チャンネル自身のフィールドが非nullであることをゲート条件にする）は `apps/2026-09-07-monhun-rise/index.html` の `render()` パターンを踏襲しています。
