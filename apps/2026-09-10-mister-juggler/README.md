# ミスタージャグラー 設定判別ツール

「ミスタージャグラー」（北電子、Aタイプ・ジャグラー系の新シリーズ、2024年7月22日導入開始）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「ミスタージャグラー」](https://p-town.dmm.com/machines/4588#anc-point)（2026/09/05更新）に掲載されているブドウ確率の公表スペック値と、[一撃（1geki.jp）「ミスタージャグラー」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_mrjuggler/0/)（2025/04/09更新）に掲載されているBIG確率・REG確率の公表スペック値をもとに、二項分布の尤度計算により設定期待度を算出します。

## A-type機種としての特殊な扱いについて

このサイトの他のツール（スマスロ系AT機）は、ストーリー性のある専用の終了画面・エンディング演出・示唆演出（金文字濃厚、虹背景など）を多数搭載しており、それらを②判別要素のチップリストとしてカウントする設計になっている。

しかし「ミスタージャグラー」はAT・CZ・ストーリー要素の一切ない純粋なAタイプ機種であり、そうした専用の示唆演出は存在しない。DMMぱちタウンの機種ページに掲載されているプレミアムパターン（レバーON時の上下パネル消灯、第3停止後の全消灯、Mr.フラッシュなど）はすべて「プレミアムパターンはすべてBIG濃厚！」と明記されている通り、設定を絞り込むための「示唆」ではなく出目上の直接情報（大当り確定演出）にすぎない。そのためこの機種では、②判別要素をチップリストではなく短い説明文のみとし、①数値データにある3つの独立した二項尤度チャンネル（ブドウ確率・BIG確率・REG確率）による判別を中心に据えている（[マイジャグラーⅤ](../2026-09-10-my-juggler-5/)・[ゴーゴージャグラー3](../2026-09-10-gogo-juggler-3/)と同じ設計方針）。これはバグではなく、Aタイプ機種の判別方法の実態に合わせた意図的な設計。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-mister-juggler/

## 機能

- **数値データ**（①）: 通常時総G数を共通の分母として、ブドウ成立回数・BIG当選回数・REG当選回数の3つを、それぞれ独立した二項尤度チャンネルとして入力可能
  - 空欄の項目は「データなし」として扱われ計算から除外される。0を入力した場合のみ「0回」として計算に反映される（`parseField()`によるnull安全設計）
- **判別要素**（②）: A-type機種のため専用の示唆演出が存在しないこと、およびチェリー・ピエロ・ベル確率を採用しなかった理由を説明する注記のみを表示。チップリストは意図的に省略している
- 数値データの入力状況に応じて、現在の最有力設定候補をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

一撃「ミスタージャグラー」の[設定判別・設定差まとめページ](https://1geki.jp/slot/s_mrjuggler/0/)（2025/04/09更新）に掲載されている「BB確率･RB確率/ボーナス合算」表（全設定分の公表スペック値）と、DMMぱちタウンの[機種ページ](https://p-town.dmm.com/machines/4588#anc-point)（2026/09/05更新）・[特集記事「ミスタージャグラーの設定差はこれを見ればOK！」](https://p-town.dmm.com/specials/3661)（2024/07/28更新）を突き合わせて確認した。

- 一撃の表では設定6のBB確率・RB確率がともに1/237.4で一致しており、DMM特集記事本文の「設定6はBIGとREGの比率が1対1になる」という記述と完全に整合した。またDMM特集記事の「BR合算確率は1/156.4〜1/118.7」という記述も、一撃のボーナス合算列（設定1: 1/156.4、設定6: 1/118.7）と一致した。信頼性の高い一撃側の表をBIG確率・REG確率としてそのまま採用した
- ブドウ確率はDMMぱちタウンの機種ページ（「解析情報通常時 > 小役関連 > 小役確率」表、ガリぞう調べ）に全設定分（1/6.29〜1/5.96）が掲載されており、そのまま採用した

### 採用した3チャンネル（ブドウ・BIG・REG）と、あえて採用しなかったデータ

課題設計として「合成確率（BIG+REG）」「BIG確率」「REG確率」「ブドウ確率」「チェリー確率」のうち、重複しない組み合わせを選ぶ必要があった。今回は**ブドウ確率＋BIG確率＋REG確率**の3チャンネルを採用し、以下は意図的に不採用とした：

- **合成確率（ボーナス合算）**: BIG確率とREG確率を独立チャンネルとしてすでに採用しているため、合成確率を加えると同じボーナス当選情報を二重にカウントしてしまうため不採用
- **チェリー確率・ピエロ確率・ベル確率**: **全設定（設定1〜6）分の公式スペック表がDMMぱちタウン・一撃のいずれにも見当たらなかった**ため不採用（CRITICAL RULE: 欠けている設定を絶対に捏造しない）。DMMぱちタウンの機種ページの「小役確率」表には、設定1のみチェリー1/37.24・ピエロ1/420.1・ベル1/655.4という数値が掲載されているが、設定2〜6の欄は空欄のままで非公開。判明しているのは以下の部分的な実戦値のみ：
  - DMMぱちタウン特集記事：設定5＝チェリー1/40.5（79回/3206G）、設定6＝チェリー1/33.8（99回/3349G）
  - 一撃 設定6実戦データページ：設定6＝チェリー1/38.4（172回/6604G、ボーナス非同時当選分）

  これらはいずれも「設定5・6のみ」の実戦サンプルであり、設定1〜4の値は一切判明していない。仮にこの実戦値だけでチェリーをチャンネル化すると、設定1〜4の尤度に寄与せず実質的に「高設定（5・6）かどうか」しか判別できないうえ、ユーザーに「全設定を判別できる項目」であるかのような誤解を与えかねないと判断し、数値データからは完全に除外した。カード②の注記でその理由を明示している

## データについて

- ブドウ確率はDMMぱちタウンの公表スペック値（全設定分・ガリぞう調べ）
- BIG確率・REG確率は一撃(1geki.jp)の公表スペック値（全設定分、DMM特集記事の記述内容と整合を確認済み）
- チェリー確率・ピエロ確率・ベル確率は前述の理由により本ツールでは採用していない。上記の実戦値はあくまで参考情報であり、本ツールの計算には一切使用されていない
- 本機は全6設定（設定1〜6）が存在する機種であり、設定そのものが欠けているわけではない（[apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/)のような`SETTINGS`配列による設定除外は不要）。一方でチャンネル自体を、全設定分のデータが存在しないという理由でまるごと不採用にしている

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS（白・黒・赤基調のパレット）とHTML骨格（ヘッダー／広告枠／カード①②③／出典／免責事項／フッター、AdSenseスクリプトタグの位置を含む）およびページ末尾のフィードバックウィジェット（`.fb-fab`〜FormSubmit.co送信スクリプト）をそのまま踏襲した単一HTMLファイル。依存ライブラリなし、ビルド不要
- **A-type向けの適応点**: [apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)・[apps/2026-09-10-gogo-juggler-3/](../2026-09-10-gogo-juggler-3/)と同じく、②判別要素はチップリスト方式（`ITEMS`配列＋`buildChips()`）を丸ごと省略し、短い説明文のみに置き換えた。`render()`は「3チャンネルの対数尤度を合算してソフトマックス的に正規化する」だけのシンプルな構成
- 尤度計算: [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`render()`にある`parseField(el)`パターンを採用。空欄は`null`を返し、各チャンネルはその欄が`null`でないことを個別に確認してから対数尤度計算に加算する。`numericInputs.forEach((el) => el.addEventListener('input', render));` の後に `render();` を呼び出す構成も踏襲している
- ブドウ・BIG・REGとも同じ「通常時総G数」を分母として共有する設計（1geki.jpの設定判別ツールや他の解析サイトの標準的なUIパターンに合わせた）
