# スマスロ「痛いのは嫌なので防御力に極振りしたいと思います。」設定判別ツール

サミー「痛いのは嫌なので防御力に極振りしたいと思います。」（通称：防振り）のファンメイド設定判別計算機です。

出典: [DMMぱちタウン「スマスロ痛いのは嫌なので防御力に極振りしたいと思います。」設定判別・推測ポイント](https://p-town.dmm.com/machines/4566#anc-point)（machine ID: 4566、最終更新日 2026/09/05、取得日 2026/09/10）

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-itai-nowa-iya/

## 機能

- ① 数値データ入力欄（総G数・各種契機ごとのn/k）から、独立した二項対数尤度チャンネルを積み上げて設定ごとの尤度を計算
  - ボーナス合算確率／上段ベル確率／中段チェリー確率（総G数ベース）
  - エピソードボーナス直撃当選率（ヒドラ目契機、総G数ベース）
  - ヒドラ目契機の高確率ZONE（CZ）当選率（通常滞在時／高確滞在時を別チャンネルとして分離）
  - チェリー・スイカ契機の高確率ZONE当選率（高確滞在時のみ）
  - BET高確率ZONE移行率（初当りボーナス後・エピソードボーナス除く）
  - ゲーム数契機の高確率ZONE当選率（150G／300G／450G／650Gの4ゾーンを個別チャンネルとして分離）
  - 高確率ZONE（防御状態以外）の継続ゲーム数振り分けにおける20G以上選択率
- ② 判別要素チップ（タップでカウント）
  - 「濃厚／否定」はハード確定要素として候補設定を絞り込み（サミートロフィー5段階・ボーナス終了画面・サブ液晶セリフ・ボーナス中キャラ紹介・獲得枚数表示）
  - 「示唆」はソフト要素として対数尤度に小さめの重みを加算するのみ（弱／通常／強の3段階、同一要素は最大3回までカウント）
- ③ 結果カードでSoftmax正規化した設定1〜6の期待度バーと、現在の候補設定・最有力設定のサマリーを表示
- 空欄の数値項目は「データなし」として扱われ、そのチャンネルの計算をスキップ（0件確定として扱わない）
- 全ページ共通の意見・要望フォーム（フローティング💬ボタン、FormSubmit.co経由でメール送信）

## データについて

DMMぱちタウンの「設定判別・推測ポイント」は本機について完全な設定1〜6のテーブルを公開しており（2026/09/05更新時点で「準備中」「調査中」の記載なし）、本ツールで採用した数値チャンネルはすべて設定1〜6の値が揃っているため、欠測設定を除外する`SETTINGS`パターンは今回は不要だった。

一撃（1geki.jp、[防振り設定差・設定判別要素まとめ](https://1geki.jp/slot/l_bofuri/0/)、最終更新日 2025/12/09）で同じ各数値をクロスチェックし、DMM側の数値と完全に一致することを確認した（ボーナス合算確率・上段ベル確率・中段チェリー確率・ヒドラ目契機CZ当選率・EPBB直撃当選率・BET高確率ZONE移行率・ゲーム数契機CZ当選率・継続ゲーム数20G選択率など）。上段ベル確率の1geki側テーブルはテキスト抽出上、設定2・3のセルが空欄に見えたが、これは同値セルの表示上の省略（DMM側で設定1〜3とも1/18.3と明記）によるもので、実際の欠測ではない。

以下は見つけたが本ツールには採用しなかった要素（欠測ではなく、複雑化を避けるための取捨選択）:

- **サミートロフィーの消化ゲーム数別出現率テーブル（1〜5000G／5001〜7000G／7001〜8000G／8001G以上の4区分）**: DMM側に非常に詳細な区分別テーブルが存在するが、「銅トロフィー以上が出現したか」を各区分ごとに数値入力させるのは①のフィールド数が過大になるため、②の判別要素チップ（トロフィー色ごとの濃厚チップ）に一本化した。
- **防御状態中の高確率ZONE継続ゲーム数振り分け（20G／無限選択率）**: 通常時版（防御状態以外）と同型のテーブルだが、ユーザーが「防御状態中かどうか」を正確に判別しにくく、通常時版と重複するチャンネルになるため割愛した。
- **機械神／大天使メイプルの「期待度アップ」ニュアンス**: 機械神は「設定2否定」、大天使メイプルは「設定1・3否定」というハード否定部分のみ判別要素チップに採用し、同時に示唆される「設定5以上期待度アップ」「設定4・6期待度アップ」という追加のソフト示唆は、同一の1回の観測を二重に加点することになるため採用しなかった。
- **無限CZ選択率（300G以降ゾーンでCZ当選した場合限定）**: 1geki.jpのみに掲載されている追加チャンネルで、「300G以降のゾーンでCZ当選」という条件付き確率のため、既存のゲーム数契機チャンネルと相関が強く、判定精度への寄与が小さいと判断し割愛した。
- **天使ZONE／暴虐ZONE中の当選率など特殊状態系の数値**: 通常時の設定判別に使う基本チャンネルではなく、特化ゾーン中の立ち回り情報のため対象外とした。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/`をベースに実装。CSS（白/黒/赤パレット）・HTML骨格（ヘッダー／広告スロット／カード①②③／出典／免責事項／フッター）・JS設計（設定別確率配列 → `logBinomLikelihood` → `computeCandidateSettings`（ハード濃厚/否定による候補絞り込み） → `buildChips`（判別要素チップ生成） → `render`（Softmax正規化して結果バー描画））をそのまま踏襲している。

空欄フィールドの扱いは`apps/2026-09-07-monhun-rise/`の`parseField`パターンを採用し、空欄を`null`として各チャンネルの対数尤度計算を個別にスキップする（「未入力」と「0件観測」を混同しない）。

フィードバックウィジェット（フローティング💬ボタン、FormSubmit.co送信）は`apps/2026-09-06-tokyo-ghoul-slot-checker/`の実装をそのまま流用している。
