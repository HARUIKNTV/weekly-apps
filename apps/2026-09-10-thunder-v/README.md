# スマスロ サンダーV 設定判別ツール

スマスロ「サンダーV」（エレコ、2026年3月2日導入）の設定判別ファンメイド計算機です。[DMMぱちタウン「スマスロ サンダーV」設定判別・推測ポイント](https://p-town.dmm.com/machines/4943#anc-point)（2026/09/10更新）を主データソースとし、BB・RB当選回数、ベルA/B・チェリーB・スイカA/Bの小役成立回数、ボーナスゲーム中の停止形（ベル下段/上段揃い・リーチ目）といった数値データと、終了画面の示唆演出の出現回数を入力すると、対数尤度（二項分布）と softmax によって設定ごとの期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-thunder-v/

## 機能

- **① 数値データ**：BB・RB当選回数（総G数ベース）／ベルA・ベルB・チェリーB・スイカA・スイカB成立回数（総G数は上と共通）／ボーナスゲーム消化G数ベースのベル下段揃い・ベル上段揃い・リーチ目（崩れ目）停止回数、の3つのグループに分けて入力。空欄の項目は「データなし」として扱われ、計算から除外されます（0回と誤認しません）。
- **② 判別要素**：BB終了画面のレアパターン（設定2以上濃厚）、RB終了画面のイッカククン出現（設定5以上濃厚）をタップカウンター形式で記録。
- **③ 結果**：設定1・2・5・6の4候補について、入力データに基づく期待度を棒グラフで表示し、最有力設定と現在の候補範囲を要約します。

## データについて

本機種は2026年3月2日導入とまだ新しく、DMMぱちタウン・一撃（1geki.jp）ともに2026年9月10日時点で**設定1・2・5・6の4段階分の数値しか公開されていません**（設定3・4の欄は両サイトとも空欄）。そのためこのツールは `SETTINGS = [1, 2, 5, 6]` として4候補のみを扱う構成にしています（`apps/2026-09-06-valvrave-2/` と同じ4/5段階設定パターン）。設定3・4のデータが両サイトで公開され次第、追加を検討してください。

### 1geki.jp とのクロスチェック

[一撃「サンダー（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_thunder_v/0/)（2026/05/18更新）はDMMぱちタウンと基本的に同一の数値（小役確率・ボーナス確率・ボーナスゲーム中の停止形）を掲載しており、相互に整合性を確認できました。1geki.jp側は「ベルA・チェリーB・RB」を最速判別の3要素として推奨しており、本ツールでもこの3項目を含む全チャンネルを実装しています。また両サイトとも「終了画面の示唆は出現比率が不明であり、非出現をもって低設定と断定するのは危険」と明記しているため、本ツールでは出現時のみ候補を絞り込む `hard/only` 型として扱い、非出現からは推測しない設計にしています。

### 見つかったが採用を見送ったデータ

- **チェリーA・リプレイの成立確率**：両サイトとも「設定差なし」と明記されているため、設定判別チャンネルとしては採用していません（入力項目にも含めていません）。
- **赤7BB／VBBの契機別内訳（リプレイ・チェリー・スイカ・リーチ目役A～E経由）**：契機ごとの確率は判明しているものの、「単独＋リーチ目役の合算」が実質的にBB確率と重複するうえ、特定のリーチ目役だけを狙う打ち方では正確な契機の見分けが難しいと両サイトが明記しているため、上位互換であるBB・RB合算確率（総G数ベース）のみを採用しました。
- **パネルフラッシュ・雷鳴演出・スパークチャレンジのパーセント表示**：いずれも当該ゲームの成立役（レア役の種類）を示唆する演出であり、設定差要素ではないため対象外としました。
- **天井G数・ゾーン**：DMMぱちタウン側が「調査中」としており、判明済みデータがないため未実装です。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/` を土台とし、CSS（白/黒/赤の配色、カード型レイアウト、チップUI）と全体のHTML構成、フィードバックウィジェット（`.fb-fab` / `.fb-panel`、FormSubmit.co経由の送信）をそのまま踏襲しています。設定が4段階（1・2・5・6）のみ公開されている点は `apps/2026-09-06-valvrave-2/`（設定3が存在しない5段階機種）の `SETTINGS` 配列パターンを流用しました。また、共有の総G数（および共有のボーナスゲーム消化G数）に対して複数のk値を入力させる設計のため、`apps/2026-09-07-monhun-rise/` の `parseField()` ヘルパーを採用し、空欄フィールドを「未入力（計算対象外）」として扱い「0回」と誤認しないようにしています。
