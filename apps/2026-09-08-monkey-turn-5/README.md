# スマスロ モンキーターンV 設定判別ツール

スマスロ「モンキーターンV」の設定判別を、プレイ中に集めた数値データと示唆演出の出現回数から支援するファンメイド計算機です。DMMぱちタウン「スマスロモンキーターンV」設定判別・推測ポイント（https://p-town.dmm.com/machines/4450 、2026/09/04更新）を主な情報源とし、独立した二項対数尤度チャンネルとタップ式カウンターチップをsoftmaxで統合して設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-08-monkey-turn-5/

## 機能

- **① 数値データ**：AT初当たり確率（総G数ベース）、AT終了画面の黒メダル出現率・即優出突入率（AT終了回数ベース）、AT直撃当選率（強チェリー・強チャンス目契機）、ライバルモード（榎木／蒲生／浜岡）移行時の内訳、激走チャージ中のEXアイテム獲得率（ボート・弱チェリー／弱チャンス目／強チャンス目契機、それぞれ独立集計）を入力すると、設定ごとの対数尤度を積み上げます。
- **② 判別要素**：AT終了画面のSGメダル・ケロットトロフィー、サブ液晶の設定示唆舟券、激走チャージ終了時のサブ液晶タッチ、ATラウンド開始画面、AT中の獲得枚数表示、AT直撃（弱レア役契機）、エンディング中のサブ液晶ボイスをタップ式カウンターで記録。金文字の「濃厚/否定」は候補設定をハード確定・除外し、斜体の「示唆」は小さな重みだけを加える参考情報として扱います。
- **③ 結果**：①②の情報をsoftmaxで統合し、設定1・2・4・5・6（この機種には設定3が存在しません）ごとの期待度をバーで表示します。
- 空欄の数値項目は「未入力」として扱われ、「0回」と誤解釈されることはありません（`parseField` によるblank-safety処理）。

## データについて

- DMMぱちタウンに加えて、一撃「モンキーターン（スマスロ）」設定差・設定判別要素まとめ（https://1geki.jp/slot/l_monkeyturn5/0/ 、2026/08/03更新）を突き合わせて数値を確認しました。特に**AT初当たり確率**（設定1: 1/299.8 〜 設定6: 1/222.9）はDMM側に完全な表がなく、一撃側のデータのみを採用しています。
- ライバルモード「榎木・蒲生・浜岡」は設定差があり、「モノクロ波多野・洞口・青島」は全設定共通（示唆なし）と両サイトが明記しているため、共通の3種は判別要素から除外し、差のある3種のみをライバルモード移行回数に対する条件付き確率としてチャンネル化しました。
- AT直撃当選率は契機ごとに扱いを分けています。弱レア役（ボート・弱チェリー・弱チャンス目）契機のAT直撃は設定1・2で確率0%（発生自体がありえない）と両サイトが明記しているため、これは数値チャンネルではなく「4以上濃厚」のハード判別チップとして実装しました。一方、強レア役（強チェリー・強チャンス目）契機のAT直撃は全設定で発生しうる連続的な確率（0.4%〜6.3%）のため、通常の数値チャンネルとしています。

### 見つけたが採用しなかったデータ

- **黒メダル出現後のケロットトロフィー内訳（銅/金/ケロット柄/虹の条件付き出現率）**：黒メダル出現直後1回のみ出現率がアップする特殊な条件付き分布で、シンプルな独立二項モデルでは正確に表現できないため見送りました。トロフィーの色そのもの（銅=2以上濃厚など）は通常のハード判別チップとして採用しています。
- **青メダル／黄メダルの出現比率**：条件付き比率（青50%/黄50%など）はほぼ全設定で拮抗しており非単調（設定4だけ50/50に戻るなど）なため、示唆の強さが実測値と対応しづらく、ソフト判別チップ（青=偶数示唆、黄=高設定示唆[弱]）として簡略化しました。
- **激走チャージ性能の平均確率「1/94（設定1）」**：設定1の値しか公開されておらず、他設定の値が不明な不完全データのため除外しました。
- **通常A/通常B/天国モードの選択率、CZ「超抜チャレンジ」の発生率**：一撃側が「詳細は現在調査中」と明記している未確定情報のため見送りました。
- **AT後1ゲーム目のレア役成立による通常B以上示唆**：示唆対象が「設定」ではなく「内部モード」であるため対象外としました。
- **予想屋・ライバルヘルメット・ステージチェンジなどの示唆演出**：いずれも「周期天井」や「ライバルモード」を示唆するものであり、設定そのものを示唆する要素ではないため対象外としました。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/` の白・黒・赤配色のCSS／HTML骨格と、独立二項対数尤度チャンネル＋タップ式カウンターチップをsoftmaxで統合するJSアーキテクチャをそのまま踏襲しています。設定3が存在しない5段階設定の機種であるため、`apps/2026-09-06-valvrave-2/` で採用された `SETTINGS = [1, 2, 4, 5, 6]` 配列とオブジェキー方式の確率テーブル（`P_XXX[s]`）を採用し、さらに `apps/2026-09-07-monhun-rise/` で修正された `parseField()` によるblank-safety処理（空欄を「0回」ではなく「データなし」として扱い、対応するチャンネル自体をスキップする）を組み合わせています。
