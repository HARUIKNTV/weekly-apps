# モグモグ風林火山 大海戦の巻 設定判別ツール

スマスロ「モグモグ風林火山 大海戦の巻」（NET／2026年09月07日導入）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5059#anc-point)（2026/09/10更新）に掲載されているAT終了画面の示唆・濃厚テーブルと、機種概要欄・解析情報に掲載されているCZ合算出現率のテーブルをもとに、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-mogumogu-furinkazan/

## 機能

- **数値データ**（①）: 「CZ合算出現率（モグモグ大戦＋モグラ叩き合算）」と「AT初当たり確率」を、共通の総G数を分母とする2つの独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: DMMぱちタウン「AT終了画面の示唆」テーブルに掲載された全6種類（青2種・緑・ピンク・紫・金）をタップ式カウンターで記録
  - 金文字表示の「4以上濃厚」「6濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「奇数/偶数設定示唆」「高設定示唆［弱/強］」は確定情報ではないため、ハード除外はせず出現回数とtierに応じた参考程度の重みだけを加える
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「モグモグ風林火山（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_mogdai/0/)（2026/08/26更新）を確認したところ、「CZ合算出現率」「AT初当たり確率」の設定1〜6の数値はDMMぱちタウン側（機種概要欄・解析情報）と完全に一致していた（例: CZ合算出現率は設定1が1/324、設定6が1/287。AT初当たり確率は設定1が1/431、設定6が1/358）。この2チャンネルは両サイトで裏付けが取れているため信頼度が高いと判断し採用した。

一撃側にも「AT終了画面」「エンディング中のレア役」の存在についての言及はあるが、「実戦上、複数のAT終了画面を確認した。何かしらを示唆していると推察される」という記述にとどまり、色・キャラクターごとの具体的な設定対応表は掲載されていなかった。判別要素（②）はDMMぱちタウン側の具体的なテーブルのみを採用している。

## データについて（見つけたが採用しなかったもの）

以下はDMMぱちタウン・一撃の両サイトで見つけたが、理由があり今回は採用しなかった：

- **AT終了画面「オレンジ（モグ玄）」「赤（騎乗モグ玄）」**: DMMぱちタウンの表記が「SPモードに1つ（2つ）以上当選 or 設定2（3）以上濃厚」という**OR条件**になっており、SPモード側の当選のみでも出現しうるため、単純な「設定n以上濃厚」のハード除外条件としては採用できないと判断してスキップした
- **エンディング中のレア役成立時の画面**: DMM・一撃の両サイトとも「設定を示唆する」「設定示唆と推察される」という記述のみで、色・パターンと設定の具体的な対応表が掲載されていなかったためスキップした
- **モグラ叩き当選率**: DMMぱちタウンに掲載されているのは「設定1」の値のみで、設定2〜6の値が掲載されていない不完全なテーブルのためスキップした
- **モグモグ超海戦当選率**、**制覇ロード（引き戻し）期待度**: いずれも「設定1」の値のみが掲載されており、他設定の値が不明なためスキップした
- **忍アタック高確移行率、忍アタック当選率、参戦チャンス当選率、撃破ポイント獲得率、SPモード当選率、CZ当選時のAT書き換え当選率、モグモグ大海戦当選率**: これらはいずれも設定差のない（またはページ上で設定差が明示されていない）機械的な抽選率のテーブルで、そもそも設定判別に使える数値ではないためスキップした

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- UI・CSS・JSのアーキテクチャは `apps/2026-09-06-tokyo-ghoul-slot-checker/` をベースに踏襲（白黒赤パレットのCSSを完全流用、`logBinomLikelihood`／`computeCandidateSettings`／`buildChips`／`render`のソフトマックス正規化構成も同一）
- 空欄フィールドの安全な扱いは `apps/2026-09-07-monhun-rise/` の `parseField()` パターンを踏襲: 空欄は「データなし（そのチャンネルをスキップ）」を意味し、「0回観測」とは区別して扱う。CZ当選回数・AT初当たり回数のどちらか一方だけ空欄でも、もう片方のチャンネルだけを正しく計算に反映できる
- 尤度計算: CZ合算出現率・AT初当たり確率それぞれの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 今回の機種は判別要素の掲載数がDMMぱちタウン上でも6種類とかなり少なく、数値チャンネルも完全なテーブルが2種類のみ（CZ合算出現率・AT初当たり確率、しかも両方とも総G数を共通の分母とする）だったため、機能としてはシンプルな構成になっている。データが薄い場合は無理に数値チャンネルを水増しせず、正直に少ない構成のまま公開する方針とした
