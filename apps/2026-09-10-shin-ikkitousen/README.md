# スマスロ「L 真・一騎当千」設定判別ツール

Daiichi『L 真・一騎当千』（導入日: 2024/10/07）の設定判別（設定示唆）を、数値データと示唆演出の出現回数から推測するファンメイド計算機です。

- データ出典: [DMMぱちタウン「L 真・一騎当千」設定判別・推測ポイント](https://p-town.dmm.com/machines/4650#anc-point)（2026/08/28更新時点の内容を反映。機種ID 4650）
- 公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-shin-ikkitousen/

対象機種は2024年10月導入済みの現行スマスロで、DMMぱちタウンの「設定判別・推測ポイント」は「準備中」「調査中」ではなく実データが公開済みであることを確認した上で作成しています。

## 機能

- **① 数値データ**: 総G数を分母とした「1枚or11枚ベル確率」「闘士決戦（CZ）初当り確率」「AT初当り確率」の3チャンネルを二項対数尤度で評価。空欄の項目は計算から除外されます（「0回」と「未入力」を区別）。
- **② 判別要素**: DMMぱちタウン掲載順のまま、以下8カテゴリ・計45個のタップ式カウンターチップを用意。
  - AT終了画面（一騎当千RUSH終了画面）
  - 勾玉の導き（引き戻しゾーン）の継続G数
  - 闘士決戦（CZ）中の特定ダメージ
  - 当千ボーナス中のキャラ紹介演出
  - 獲得枚数表示
  - エンディング：孔明の看板（レア役成立時）
  - キャラ図鑑
  - 設定変更時のモード（天国モード即当選で設定1否定）

  金文字の「濃厚/否定」はハード除外（候補から確定的に除外）、斜体の「示唆」はソフトウェイト（対数尤度に小さめの重みを加算するのみ）として扱います。
- **③ 結果**: 6設定それぞれの相対期待度を softmax 化したバーで表示。ハード除外された設定は「除外」と表示されます。

## 1geki.jp とのクロスチェックについて

[一撃「L 真・一騎当千」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_shin_ikkitosen/0/)（2025/12/09更新）も全文確認し、DMMぱちタウンの内容と突き合わせました。

- 闘士決戦初当り確率・当千ボーナス中のキャラ紹介演出・獲得枚数表示・孔明の看板など、大部分の項目は両サイトで数値・示唆内容が一致していました。
- **AT初当り確率**は1geki.jpのみに設定1〜6の完全なテーブル（1/321・1/311・1/292・1/246・1/232・1/222）が掲載されていたため、こちらを採用しています（DMMぱちタウン側には対応する設定別テーブルが見当たりませんでした）。
- 当千ボーナス中の「趙雲」の示唆について、DMMぱちタウンは「設定2以上濃厚」、1geki.jpは「設定1否定!?」と表現していましたが、これは論理的に同じ主張（設定2以上濃厚 ⇒ 設定1否定）であり矛盾はありません。より強い主張であるDMMぱちタウン側の「設定2以上濃厚」（ハード除外）を採用しました。

## データについて

以下は公開ページ内で見つけたものの、本ツールには採用しなかったデータです（理由付き）。

- **闘士ポイント高確移行率**（ベル・単チェリー・2連チェリー・弱スイカ契機）: 設定差の記載がなく、全設定共通の抽選値として説明されていたため、設定判別チャンネルとして使えませんでした。
- **闘士決戦・こうめいちゃんす・バーストアタックのランクアップ当選率**: ページ内に「抽選値は共通」と明記されており、設定差なし。
- **天国モード移行率（トータル／設定変更時、5カテゴリ分布）**: 設定1〜6で完全な数値（例: トータル 0.7%/0.6%/0.6%/2.5%/2.5%/2.5%）が公開されていますが、プレイヤーが「内部的に天国モードに滞在したか」を都度正確に判定するのは通常困難なため、数値チャンネルとしては採用しませんでした。代わりに、DMM・1geki双方が明言している「設定変更後、天国モードで即当選した場合は設定1否定」という一点のみをハード除外チップ（②「設定変更時のモード」）として反映しています。
- **闘士決戦初当り確率・モード別ゲーム数振り分けテーブル（通常A〜D・天国、100G〜1000G刻み）**: モード推測（天井狙い）向けの情報であり、設定判別との直接対応が薄いため対象外としました。
- 設定を跨いで欠損しているテーブル（一部設定のみ数値が掲載され他設定が空欄になっているもの）は見つかりませんでした。今回採用した数値・示唆はすべて設定1〜6が揃った完全なデータのみです。

## 技術メモ

本ツールは `apps/2026-09-06-tokyo-ghoul-slot-checker/` の実装をベースに、CSS（白/黒/赤の配色）・HTML骨格・JS計算ロジック（`logBinomLikelihood` による二項対数尤度＋softmax正規化、`buildChips` によるカテゴリ別カウンターチップ生成）をそのまま踏襲しています。

空欄フィールドの扱いは `apps/2026-09-07-monhun-rise/` の `parseField` パターン（空欄は `null` を返し、各チャンネルは自身のフィールドが非nullの場合のみ計算に加算）をそのまま採用し、「未入力」と「0回観測」を明確に区別しています。

フィードバックウィジェット（画面右下の💬ボタン、FormSubmit.co経由）も参照実装から変更なしでそのまま移植しています。
