# スマスロ「ケロット5BT」設定判別ツール

山佐ネクスト「スマスロケロット5BT」（2026年7月6日導入、型式名: LBケロット5ND05H）向けの設定判別ツールです。BB以上・RB当選回数、ボーナスカラー（赤7頭／白7頭）比率、通常時の小役確率、オレンジ成立時のボーナス同時当選率などの数値データと、終了画面・ケロットトロフィー・カットインなどの示唆演出の出現回数から、各設定（1〜6）の尤度を独立な二項対数尤度チャンネルの合算＋softmaxで算出します。

データの一次情報は [DMMぱちタウン「スマスロケロット5BT」設定判別・推測ポイント](https://p-town.dmm.com/machines/5015#anc-point)（2026/09/08更新）です。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-kerot-5-bt/

## 機能

- **① 数値データ**: 以下の数値を入力すると、二項分布の対数尤度として各設定の尤もらしさに反映されます。空欄の項目は「データなし」として扱われ、計算から除外されます（0を入力した場合のみ「0回」として計算）。
  - ボーナス確率（総ゲーム数ベース）: BB以上（SBB＋BB）当選回数／RB当選回数
  - ボーナスカラー（赤7頭／白7頭）の比率: 頭色を確認したボーナス回数のうち赤7頭の回数
  - 小役確率（通常時ゲーム数ベース）: ベル・チェリー・平行オレンジ・斜めオレンジ・確定役の各成立回数
  - 平行オレンジ／斜めオレンジ成立時のボーナス同時当選率（分母はそれぞれの成立回数を再利用）
- **② 判別要素**: 出現演出をタップしてカウント。金文字の「濃厚／否定」は設定候補をハード確定・除外し、斜体の「示唆」は参考程度の重みだけを加算します（区分は下記「データについて」参照）。
  - ボーナス終了画面（スーパーBIG・異色BIG消化後のPUSH後）: 青エフェクト①②／赤エフェクト／銀・金①・金②エフェクト
  - ケロットトロフィー（REG終了画面）: 銅／銀／金／ケロット柄／虹
  - ボーナス確定画面（虹河ラキモード中のみ）: ①アイドル／②魔法少女／③メイド
  - フリーズ: ロングフリーズ（4以上濃厚）
  - RB中の目押しチャレンジ カットイン: 赤／銀／金①／金②（山佐キャラあり）
- **③ 結果**: 設定1〜6ごとの相対期待度をバー表示。濃厚・否定要素と矛盾する設定は「除外」表示になります。

## 1geki.jp とのクロスチェック

[一撃「ケロット5（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/lb_kelot5/0/)（2026/07/29更新）も確認し、以下の点でDMM側のデータと一致することを確認しました。

- ボーナス確率（SBB／BB／RB、設定1〜6）の数値がDMM側の比率（%）から逆算した値と一致。
- ボーナスカラー（赤7頭／白7頭）比率が完全に一致（例: 設定1は赤55.0%／白45.0%）。
- 小役確率（ベル・チェリー・オレンジ・確定役）の数値が完全に一致。
- 終了画面・トロフィー・カットインの示唆内容も同一（1gekiは「ラキモード選択中」の確定画面を「アイドル／魔法少女／メイド／水着」の名称で掲載、DMMは「①／②／③」表記だが示唆内容は一致）。

1geki.jp側にのみ記載されていた「ロングフリーズ発生確率」は設定ごとの具体的な数値が「???」（未判明）のままだったため、本ツールでは採用せず、DMM側の「発生時点で設定4以上濃厚」という濃厚要素のみをチップとして採用しています。

## データについて

以下は情報として見つかったものの、本ツールには採用しませんでした。

- **小役契機のボーナス実質確率（当選契機役×ボーナス色×ボーナス種別の組み合わせ表）**: DMM側に非常に詳細な組み合わせ表が掲載されていますが、契機役・色・ボーナス種別を全て正確に記録する必要があり実戦での入力が非現実的なため採用を見送りました。同じ情報は「ボーナス確率」「小役確率」「オレンジ同時当選率」のチャンネルで簡略化した形でカバーしています。
- **レア役合算確率（チェリー以上）**: ベル・チェリー・平行オレンジ・斜めオレンジ・確定役の個別確率を既にチャンネルとして採用しているため、合算値を追加すると二重カウントになるため除外しました。
- **チェリー成立時／ベル成立時のボーナス同時当選期待度**: チェリーは1.3%→1.2%、ベルは0.085%→0.079%と設定差が非常に小さく、実戦データでは統計的に区別困難なノイズレベルと判断し採用を見送りました（平行・斜めオレンジ側は設定差が比較的大きいため採用）。
- **確定役成立時のボーナス同時当選期待度**: 全設定で100%固定（同時当選が確定）であり、設定差の情報を持たないため採用対象外です。
- **フタバボーナスの出現率**: 「高設定ほど出現しやすい」との記述はあるものの、具体的な設定別数値がDMM・1geki双方とも未掲載（推察ベース）のため採用を見送りました。
- **通常時演出の期待度（コガエル演出・バトル演出・ラキ☆バレなど）**: いずれもボーナス当選期待度を示すものであり、設定差の情報ではないため対象外としました。

## 技術メモ

`apps/2026-09-06-tokyo-ghoul-slot-checker/` の実装をベースに、CSS（白／黒／赤の配色）・HTML構造（数値データ／判別要素／結果カードの3カード構成＋広告枠）・JSアーキテクチャ（設定別配列・`logBinomLikelihood`・`computeCandidateSettings`・`buildChips`・`render`のsoftmax正規化）をそのまま踏襲しています。

また `apps/2026-09-07-monhun-rise/` の `parseField` パターンを採用し、数値欄が空欄の場合は「そのチャンネルのデータなし」として計算から除外し、「0回」と誤解釈しないようにしています（各チャンネルは自身のk欄が非nullであることを個別にゲートしてから対数尤度を加算）。

フィードバック用の💬フローティングウィジェットも同ツールからそのまま複製しており、FormSubmit.co経由でメールクライアントを使わずに意見・要望を送信できます。
