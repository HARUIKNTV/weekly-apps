# スマスロ ハナビ 設定判別ツール

「スマスロ ハナビ」（アクロス、型式名 L/ハナビ/KM、導入開始日 2026年02月02日）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4928#anc-point)（2026/09/10更新）に掲載されている小役確率・ボーナス確率・終了画面の判別要素をもとに、実戦データの入力から設定期待度を算出します。シリーズ機種の「新ハナビ」（型式名別・導入開始日2021年07月05日、DMM machines/3911）とは異なる別機種であることをDMM機種ページのタイトル・型式名・機種IDで確認済みです。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-hanabi/

## この機種の特徴：公開データが設定1・2・5・6の4段階分のみ

DMMぱちタウン・一撃（1geki.jp）のどちらのページでも、ボーナス確率・小役確率・BIG/REG中の小役確率・RT中のハズレ確率・ボーナス同時当選期待度など、すべての設定別テーブルが**設定1・2・5・6の4列のみ**で構成されており、設定3・4の数値はサイト内のどこにも一切掲載されていない。本ツールもこれに合わせて`SETTINGS = [1, 2, 5, 6]`という設定空間で計算しており、結果表示にも設定3・4は出てこない（実機に設定3・4が存在しないという意味ではなく、公開されている実戦データがこの4段階分にとどまっているという意味）。

## 機能

- **数値データ**（①）: 以下の7つのグループ・21項目をそれぞれ独立した二項尤度チャンネルとして入力可能
  - ボーナス確率（総G数・BIG当選回数・REG当選回数）
  - 通常時の小役成立回数（風鈴A・風鈴B・氷A・チェリーA2・チェリーB、総G数は上と共通）
  - BIG中の小役確率（BIG中消化G数・風鈴A[平行揃い]・風鈴B[斜め揃い]・バラケ目）
  - REG中の小役確率（REG中消化G数・1枚役・バラケ目）
  - 花火チャレンジ中のハズレ確率
  - 花火ゲーム中のハズレ確率
  - チェリーBのボーナス同時当選率
- **判別要素**（②）: REG終了画面のピースマーク出現（設定2以上濃厚）をタップ式カウンターで記録
- 空欄の項目は「データなし」として扱われ計算に影響しない（`parseField`によるblank-safety。0を入力した場合のみ「0回」として扱う）
- 広告枠を3か所設置（ヘッダー直下728×90、判別要素と結果の間300×250、フッター上728×90）— プレースホルダー表示のみ
- モバイル表示時の日本語の不自然な改行を防ぐCSS（`word-break: keep-all`）を適用

## 一撃（1geki.jp）とのクロスチェック

[一撃「ハナビ（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_hanabi/0/)（2026/04/03更新）を確認したところ、DMM側には明記されていなかった**ボーナス確率（BB確率・RB確率・合算）**の設定別テーブルが掲載されていたため、これを①のボーナス確率チャンネルの数値として採用した（DMM側は各ボーナスの「実質確率」の内訳表は掲載しているが、単純な出現率テーブルは一撃の方が見やすく確認しやすかったため）。その他の小役確率・BIG/REG中の小役確率・RT中のハズレ確率・ボーナス同時当選期待度の各テーブルはDMMと一撃で完全に一致しており、相互に裏付けが取れた。

## データについて（見つけたが採用しなかった項目）

以下はDMM・一撃の両サイトで見つけたものの、**特定の設定（列）の数値が欠落していた**、または実測が非現実的なため未採用とした項目。欠落設定を補完・推測することは行っていない。

- **氷B成立率**（通常時）: 設定1のみ「1/1560.4」と記載があり、設定2・5・6は空欄（値の記載なし）。他の小役のように4設定分そろっていないため未採用
- **リプレイ成立率**（通常時）: 設定1のみ「1/7.3」の記載があり、設定2・5・6は空欄のため未採用
- **REG中の風鈴・共通15枚**: 設定1のみ数値があり（風鈴1/1.2、共通15枚1/32.8）、設定2・5・6は空欄のため未採用（同テーブルの「1枚役」「バラケ目」は4設定分そろっているため、②に採用済み）
- **花火チャレンジ中／花火ゲーム中の通常リプレイ・移行リプレイ・RTリプレイ**: ハズレ確率と一部重複する複合的な指標で、列の対応関係（どの数値がどの役に対応するか）がテーブル上で曖昧な箇所があり、確実に判別できるハズレ確率に一本化するため未採用
- **チェリーA1成立率**（通常時）: 設定1〜6で「1/99.4・1/99.4・1/99.4・1/99.3」とほぼ横ばいで実質的な設定差がごく僅かであり、プレイ中の体感カウントでは誤差に埋もれてしまうため未採用
- **チェリーA1・リプレイ・風鈴Aのボーナス同時当選期待度**: DMM・一撃とも4設定分の数値は掲載されているが、いずれも出現率が0.06%〜0.60%程度と極めて低く、かつ「同時当選」かどうかをプレイ中に見分けるのが難しいため、同じ表の中で差が大きく実戦的に追いやすい**チェリーBの同時当選期待度のみ**を採用した
- **ドンBIG／赤七BIG／REGの「単独・リプレイ・特殊リプレイ・チェリーB・リーチ目役」ごとの実質確率**: いずれも1/1000〜1/16384程度の非常に稀な複合条件付き確率で、母数を正確に集計するには数万〜数十万G規模のサンプルが必要になり実戦的に入力できないため未採用（この情報の大枠は①のボーナス確率・チェリーB同時当選チャンネルでカバーしている）
- **たまやチャレンジのパーセント表示・遅れ/消灯の有無・三連花火演出**: いずれも「その1ゲームの当否（ボーナス同時当選かどうか）」を示す演出であり、機械の設定そのものを示唆する情報ではないため対象外
- **1枚役成立回数別・ピースマーク出現率**（2回以下／3or4回／5回以上）: ②のチップは「ピースマーク出現＝設定2以上濃厚」という単純な確定情報のみを反映しており、1枚役の成立回数に応じた出現率の詳細（3.1%/10.0%/25.0%）までは②の設計上モデル化していない

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 設定空間を`SETTINGS = [1, 2, 5, 6]`配列で保持し、確率テーブルもオブジェクト（`{1: ..., 2: ..., 5: ..., 6: ...}`）で持たせることで、公開データが4段階分にとどまる機種にも対応できる形に一般化した（[革命機ヴァルヴレイヴ2](../2026-09-06-valvrave-2/)のSETTINGS配列パターンを踏襲）
- 空欄フィールドを「データなし」として扱う`parseField`によるblank-safety、および同じ総G数を共有する複数チャンネルのうち入力済みのものだけを計算対象にするパターンは[モンスターハンターライズ](../2026-09-07-monhun-rise/)を参照実装として踏襲
- チップUI・尤度計算・フィードバックウィジェットの基本パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲
