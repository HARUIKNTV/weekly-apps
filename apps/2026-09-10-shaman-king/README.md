# スマスロ シャーマンキング 設定判別ツール

「スマスロ シャーマンキング」（2025年2月3日導入、型式：L/SHAMANKING/SS）の設定判別ツール。DMMぱちタウン「[スマスロ シャーマンキング（パチスロ）設定判別・天井・ゾーン・解析・打ち方・ヤメ時](https://p-town.dmm.com/machines/4719)」（最終更新日：2026/09/03）の「設定判別・推測ポイント」セクションに掲載されている実データをもとに作成。同セクションは「準備中」ではなく、初当り確率・共通ベルA確率・AT直撃当選率・エピソードボーナス選択率・規定リプレイカウンタ・憑依合体バトル勝率・終了画面示唆・エンディング示唆など、設定1〜6の完全な数値テーブルと示唆演出一覧が公開されている。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-shaman-king/

## 機能

- **① 数値データ**：総G数・シャーマンファイト初当り回数・通常時初当り回数・共通ベルA成立回数・AT直撃当選回数・エピソードボーナス当選回数・弱チェリー/スイカ高確移行率・規定リプレイカウンタ（「10」「99」選択率）・リプレイ5回成立時のCZ以上当選率・憑依合体バトル勝率、の10項目を入力すると二項対数尤度で各設定の尤度を積算。
- **② 判別要素**：AT終了画面（パッチ族／葉＆アンナ／ハオ／全員集合など）、上位CZ「たまおのこっくりさん占い」中の特定文字、AT中の獲得枚数表示（246/256/356/456/555/666 OVER）、エンディングCongratulations文字色、エンディング消化中のサブ液晶キャラ、の5カテゴリ・31チップをタップでカウント。「濃厚/否定」はハード除外、「示唆」は弱/通常/強の重み付けのみ。
- **③ 結果**：Softmax正規化した設定1〜6の期待度バーと、現在の候補・最有力設定のサマリーを表示。

## 1geki.jp とのクロスチェック

一撃「[シャーマンキング（スロット/スマスロ）設定差・設定判別要素まとめ](https://1geki.jp/slot/l_shamanking/0/)」（最終更新日：2025年12月09日）と全項目を突き合わせ、両サイトで完全に一致する設定1〜6の数値のみを採用した。特に以下は突き合わせで判明した点：

- 「初当り時のエピソードボーナス選択率」は1geki.jpのテーブル抽出では設定2の値が空欄に見えたが、DMMぱちタウン側の同項目（初当りボーナス種別振り分け）で設定2＝0.4%（設定1と同値）と明記されており、実際は設定1〜6すべて揃った完全データであることを確認した。
- 「憑依ポイントごとのCZ以上当選期待度」表の1000pt列と、「発展パート移行時の勝利抽選」表の残りHP2・HP1列は、設定1の行にのみ数値（100%、67.2%、85.2%）が記載され、設定2〜6は空欄だった。これは全設定共通値のため2行目以降を省略した表組みであり、値が欠落しているわけではないと判断（設定間で差がなく判別に使えないため、そもそもツールには採用していない）。

## データについて

以下は元データを確認したが、理由によりツールへの採用を見送った：

- **シャーマンファイト予選中のAT当選率（1〜6G目、対戦相手別）**：ファウスト・蓮・ホロホロそれぞれ個別の数値テーブルがあるが、プレイヤーが対戦相手ごと・ゲーム目ごとに勝敗を正確に記録するのは実用上困難なため見送り。
- **憑依ポイント帯別のCZ当選率／CZ種別振り分け（0〜595pt、600〜1000ptの細分表）**：完全な数値データはあるものの、既に採用した「リプレイ5回成立時のCZ以上当選率（全pt合算）」で近い情報を簡潔に捕捉できるため、UIの複雑化を避けて見送り。
- **憑依合体バトルの残りHP別勝利率（対戦相手不問の発展パート抽選）**：残りHPを正確に把握しながらのカウントは難易度が高く、既に採用した「憑依合体バトル・トータル勝利率」で代替できるため見送り。
- **ボーナス高確率中のボーナス当選期待度（役別）**：設定差がほぼない（50.9%〜51.2%で横ばい）ため判別要素として無意味と判断し見送り。
- **巫門遁甲ポイント関連**：設定変更時／有利区間移行時の初期ポイントに関する演出だが、公開データ上は設定差の記載がなく判別要素ではないため見送り。

## 技術メモ

CSS・HTML骨格・JSアーキテクチャ（`logBinomLikelihood`／`computeCandidateSettings`／`buildChips`／`render`、および二項対数尤度のSoftmax正規化方式）は [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) を踏襲。空欄と「確認して0回だった」を区別する `parseField` ヘルパーおよび共有n（総G数）グループでの個別null判定ゲートは [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/) のパターンを採用した。本機種は設定1〜6が揃った完全な6段階機種のため、`SETTINGS = [...]` によるオブジェクトキー方式（[apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/) 参照）は使用していない。フィードバックウィジェット（フローティング💬ボタン、FormSubmit.co経由）も同ファイルから変更なしで流用。
