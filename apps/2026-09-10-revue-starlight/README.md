# スマスロ「L 少女☆歌劇 レヴュースタァライト -The SLOT-」設定判別ツール

[DMMぱちタウン「L 少女☆歌劇 レヴュースタァライト -The SLOT-」設定判別・推測ポイント](https://p-town.dmm.com/machines/4706#anc-point)（2026/09/05更新）を主な一次情報源とし、[一撃「レヴュースタァライト（スロット）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_revuestarlight/0/)（2026/03/19更新）で数値の相互確認を行って作成したファンメイド設定判別ツールです。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-revue-starlight/

## 機能

- ① 数値データ: 総G数ベースの各種確率（CZ当選／AT初当り／BIG合算／ボーナス合算／特定役+ボーナス同時当選）、AT直撃当選率（強チェリー・チャンス目契機）、LEDランプ紫点灯率の3グループを個別入力。空欄は「未観測（データなし）」として扱われ、0回として計算されることはありません。
- ② 判別要素: AT終了画面タッチボイス／ボーナス終了画面／獲得枚数表示の3カテゴリ・計14チップ。金文字の「濃厚/否定」はハード除外（候補確定）、斜体の「示唆」は参考程度のソフト加点のみ。
- ③ 結果: 二項対数尤度の合算をsoftmax正規化し、設定1・2・4・5・6（本機種は公開データ上、設定3の情報が存在しないため5段階）の期待度バーと最有力設定を表示。

## 1geki.jpとのクロスチェックについて

両サイトの数値は完全に一致していました（CZ出現率、特定ボーナス【青7BB】【RB】の同時当選確率、ボーナス実質確率、LEDランプ発光色割合、AT終了画面ボイス／ボーナス終了画面の出現率振り分けなど）。相違があったのは「レヴュースタァライト[AT]初当り確率」で、これは一撃側のみが独立した表として掲載していたため（DMM側は個別のAT初当り確率表を持たず、CZ・直撃等の複合抽選として記載）、一撃の数値をそのまま採用しました。

## データについて

以下は両サイトで見つけたものの、設定差の数値・根拠が不十分または不明瞭だったため、ツールには反映していません。

- **REG終了画面の「上記以外」パターン**: 「華恋＆ひかり」（デフォルト）、「真矢＆クロディーヌ＆なな」「純那＆まひる＆香子＆双葉」（CZ/ATストックのチャンス）以外の画面が出れば「高設定のチャンスかも!?」と記載されているのみで、具体的な出現率や対象設定の内訳が非公開のため除外。
- **AT直撃高確移行率（300G/600G付近）**: 「約23%」という数値が設定1のみで、DMM側も「移行率自体に設定差が設けられている可能性もある」と明記しており他設定の値が非公開のため除外。
- **CZ抽選テーブル別・10pt到達時の期待度**: テーブル1・テーブル2が「調査中」で未公開のため除外（テーブル3・4のみ判明）。
- **累計ポイント天井振り分け**: 0pt〜500ptの全区分が「調査中」で数値が一切非公開のため除外。
- **1G連フリーズ発生確率**: 「調査中」で非公開のため除外（恩恵・契機は判明しているが確率が不明）。
- **赤7BIG／青7BIG／REGの個別実質確率**: DMM・一撃とも表の列構成に矛盾があり（設定2以降で青7BIGとREGの列が入れ替わって見える等、テキスト抽出上も数値の対応関係を確定できなかった）、誤った数値を採用するリスクがあるため個別の内訳は採用せず、代わりに矛盾のない「BIG合算確率」「ボーナス合算確率」の2つを採用しています。

## 設定3について

本ツールは `SETTINGS = [1, 2, 4, 5, 6]` として設定3を計算対象から完全に除外しています。これはDMMぱちタウン・一撃の両サイトとも、設定判別に関するすべての表（ボーナス確率、CZ出現率、AT直撃当選率、LEDランプ発光色割合、終了画面示唆の出現率振り分けなど）が一貫して設定1・2・4・5・6の5列のみで構成されており、設定3の数値がどの表にも一切掲載されていなかったためです。存在しないデータを補間・推測することはせず、公開されている情報のみを使用しています。

## 技術メモ

- HTML/CSS/JS構成・白黒赤のデザインシステム・二項対数尤度によるsoftmax正規化・タップ式チップUIは [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) を土台にしています（フィードバックウィジェットも同ページから流用）。
- 設定3が存在しない5段階設定を扱うオブジェクトキー方式（`SETTINGS = [1, 2, 4, 5, 6]` と `{1: ..., 2: ..., 4: ..., 5: ..., 6: ...}`）の実装パターンは [apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/) を踏襲しています。
- 空欄フィールドを「未観測」として扱う `parseField()` ヘルパーと、各チャンネルを自身のフィールドのnull判定でゲートする方式は [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/) の `render()` 実装を踏襲しています。
