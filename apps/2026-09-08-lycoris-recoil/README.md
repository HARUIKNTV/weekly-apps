# スマスロ リコリス・リコイル 設定判別ツール

「スマスロ リコリス・リコイル」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5033)（2026/09/08更新）に掲載されている判別要素をそのままの分類（サミートロフィー→リコリスラッシュ終了画面→上位ラッシュ終了画面）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-08-lycoris-recoil/

## 機能

- **数値データ**（①）: CZ当選率・リコリスラッシュ確率（いずれも総G数を共通の母数とする合算値）を、1つの見出しの下で2つの独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: サミートロフィー（5色）、リコリスラッシュ終了画面（共通の示唆キャラ／千束ラッシュ終了時／たきなラッシュ終了時でそれぞれ意味が変わる「たきな私服」「千束私服」を区別）、上位ラッシュ（リコリスラッシュW）終了画面——計19種類をDMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「リコリコ（スロット/スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_lycoreco/0/)（2026/09/07更新）を全文確認したところ、CZ出現率（1/198.7〜1/169.4）とサミートロフィーの示唆内容はDMMぱちタウンの内容と完全に一致していた。

一撃側にのみ掲載されていたのが**リコリスラッシュ確率の設定1〜6完全テーブル**（設定1: 1/328.8 〜 設定6: 1/256.7）。DMMぱちタウン側は「ボーナス出現率」というグラフ画像のみでテキストの完全テーブルが見当たらなかったため、本ツールでは一撃の値を採用し、`P_RUSH`のコメントにその旨を明記した。

## データについて

本機種は2026年9月7日導入の新台（今回の確認時点で導入からわずか1〜2日）のため、公開されている設定差データはまだ限定的。以下は本文を確認したうえで、あえて数値チャンネル・判別要素チップのいずれにも採用しなかった項目とその理由。

- **ファーストリコリス（幼少期CZ）確率**：DMM・一撃とも設定1（1/3965.0）と設定6（1/2084.8）の2点のみが判明しており、設定2〜5は「???」「現状不明」扱い。2点だけでは6設定分の二項尤度チャンネルを構成できないため未採用（今後設定2〜5が判明次第、追加候補）。
- **リコリスラッシュ直撃確率**：同様に設定1（1/22429.5）と設定6（1/6263.7）の2点のみで、設定2〜5は不明のため未採用。
- **プロローグのエピソード（Time will tell①／The more the merrier／Repay evil with evil／Time will tell②）**：「エピソードの種類で設定を示唆」とあるが、DMM・一撃とも各エピソードの具体的な示唆内容は「調査中」「詳細不明」のため、どのエピソードがどの設定を示唆するか判別不能。チップ化を見送った。
- **エピソードボーナスの種類**（リコリスラッシュ中4種／上位ラッシュ中4種）：同じく「エピソードの種類で設定を示唆」とあるだけで、具体的な示唆内容がDMM・一撃とも「調査中」のため未採用。
- **筐体上部ランプの発光色（青／黄／緑／赤）**：ボーナス中・エンディング中のレア役成立時に発光するとの記載はあるが、色ごとの示唆内容がDMM・一撃とも「調査中」「詳細不明」のため未採用。
- **たきなリコリス制服／千束リコリス制服**（ラッシュ終了画面・上位ラッシュ終了画面の両方に登場）：DMM側で「デフォルト」表示と明記されており、設定示唆のない標準パターンのためチップ化しなかった。
- **謎Vストック**：「初当たり時のVストック所持率は高設定ほど優遇」とあるが、具体的な確率や段階分けが示されておらず定量化できないため未採用。
- **小役確率・変換高確移行率・小役変換時のCZ当選率・上位CZ成功率・上位ラッシュ抽選率など**：DMM側の表はいずれも設定ごとの内訳がなく単一の共通値のみだったため、設定差データとしては利用できず対象外。
- **設定6の勝率（一撃調べ、約8割）**：単一の統計値であり6設定分の二項尤度チャンネルを構成できないため未採用。

新台特有の事情として、上記のとおり数値チャンネルは「CZ当選率・リコリスラッシュ確率」の1系統（2チャンネル）のみ、判別要素チップも比較的少なめの19種類にとどまっている。**今後DMM・一撃のページが更新され設定2〜5のファーストリコリス確率／直撃確率や各種示唆内容の詳細が判明した場合は、追加のアップデートを検討されたい。**

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) を参照実装として、CSS（白背景・ほぼ黒文字・赤アクセント1色のデザイン）を完全に踏襲した
- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: CZ当選率・リコリスラッシュ確率それぞれの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 空欄フィールドの安全対策として [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/) と同じ`parseField(el)`パターンを採用：空欄は`null`（＝そのチャンネルは計算対象外）、入力済みは0以上の整数として扱い、`k`側の入力欄が空欄のまま総G数だけ入力されるケースを「0回観測」と誤解釈しないようにしている
- CZ当選率とリコリスラッシュ確率は同じ総G数を母数とするため`field-group-label`を1つにまとめ、2つの`k`入力欄をその下に並べている（[apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCZ・エピソードボーナスの入力欄と同じパターン）
- リコリスラッシュ終了画面の「たきな私服」「千束私服」は、千束ラッシュ終了時とたきなラッシュ終了時で示唆内容（濃厚⇔示唆弱）が入れ替わる仕様のため、あえて`cat`を分けて別チップとして扱い、ユーザーがどちらのラッシュが終了したかを意識して正しい方をタップできるようにしている
