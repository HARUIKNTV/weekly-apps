# スマスロ バイオハザード5 設定判別ツール

「スマスロ バイオハザード5」（Enterrise、型式「Lバイオハザード5ZE」、2025年3月3日導入）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4754#anc-point)（2026/09/07更新）に掲載されている判別要素をそのままの分類（終了画面系＝エンタトロフィー／AT終了画面／エンディングのセリフ／獲得枚数表示）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

## バイオハザードRE:3との違いについて

本サイトには既に「[スマスロ バイオハザードRE:3 設定判別ツール](../2026-09-10-biohazard-re3/)」がありますが、これは**別機種**です。

- **バイオハザード5**（本ツール）: DMMぱちタウン機種ID `4754`、2025年3月3日導入、型式「Lバイオハザード5ZE」
- **バイオハザードRE:3**: DMMぱちタウン機種ID `4974`、2026年5月11日導入（バイオハザード5の後継機）

DMMぱちタウンの「シリーズ機種」欄でも両者は別ページとして明確に区別されている。タイトル・メタ説明・判別要素の内容が混同されないよう、本ツールでは冒頭に「バイオハザードRE:3とは別機種です」の注記を入れている。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-biohazard-5/

## 機能

- **数値データ**（①）: AT「ハザードラッシュ」初当り確率・CZ（パニックゾーン＆ウェスカーゾーン合算）当選率（総G数を共有する同じ見出しにまとめて入力）、インフェクション当選率（AT開始時、AT当選回数を母数とする独立した見出し）——3系統をそれぞれ独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: エンタトロフィー（終了画面系）、AT終了画面、エンディング（レア役成立時のセリフ）、獲得枚数表示の全27要素を、DMMぱちタウンの分類のままカテゴリラベル付きでタップ式カウンターに記録
  - 金文字表示の「〜濃厚」「〜否定」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「バイオ5（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_biohazard5/0/)（2026/03/09更新）を確認したところ、CZ確率（パニックゾーン単体・合算とも）とエンタトロフィー／AT終了画面／エンディングセリフ／獲得枚数表示の示唆内容は、DMMぱちタウンの内容と完全に一致していた。

一撃側のインフェクション当選率の表は設定2の行の数値表示が抜け落ちていた（レイアウト崩れとみられる）が、DMMぱちタウン側の同テーブルには設定2の値（中段揃い16.7%・トータル33.2%、設定1と同値）が欠落なく掲載されていたため、DMM側の完全な1〜6テーブルを採用した。

一撃にのみ掲載されていた**AT「ハザードラッシュ」初当り確率**（設定1〜6の完全なテーブル）は、DMM側に対応する機種概要欄の記載がなかったため、一撃の数値をそのまま採用した。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- ベースは[apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS・HTML骨格・JSアーキテクチャ（`logBinomLikelihood`・`computeCandidateSettings`・`buildChips`・`render`・ソフトマックス正規化）をそのまま踏襲
- 空欄安全性: `parseField(el)`ヘルパーで空欄を`null`として扱い、「未入力」と「0回観測」を区別（[apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`render()`と同じパターンを採用）。各チャンネルは自分自身のk値フィールドが非nullの場合のみ尤度計算に寄与する
- 尤度計算: 各二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持
- AT初当り・CZ合算の2チャンネルは同じ母数（総G数）を共有するため同一の`field-group-label`にまとめ、インフェクション当選率はAT当選回数という別の母数を使うため独立した見出しを設けた
