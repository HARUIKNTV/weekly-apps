# スマスロ BIRDIE WING 設定判別ツール

スマスロ「BIRDIE WING -Golf Girls' Story-」（ユニバーサルブロス、2026年6月8日導入）向けの設定判別ファンメイド計算機です。

[DMMぱちタウン「スマスロ BIRDIE WING -Golf Girls' Story-」設定判別・推測ポイント](https://p-town.dmm.com/machines/4996)（最終更新日：2026/09/09時点で取得）を一次ソースとし、そこに掲載されている「設定判別・推測ポイント」（終了画面系のサブ液晶カード、ウイングボーナス中のキャラ紹介シナリオ、獲得枚数表示による示唆など）は準備中・調査中ではなく実データとして公開されていることを確認した上で作成しています。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-birdie-wing/

## 機能

- ① 数値データ：総G数・通常時初当たり回数（WB・BB・EPB合算）・ST初当たり回数（BB・EPBのみ）を入力すると、設定1〜6ごとの二項対数尤度を計算します。
- ② 判別要素：以下の3カテゴリ・計30個の示唆演出をタップしてカウントできます。
  - ウイングボーナス中のキャラ紹介シナリオ（No.2〜No.9、8種）
  - バーディーボーナス終了時サブ液晶カード［イヴ周期］（10種）
  - バーディーボーナス終了時サブ液晶カード［葵周期］（8種）
  - バウンティクイーンボーナス中の獲得枚数表示（246/456/555/666枚OVER、4種）
- ③ 結果：数値データ＋判別要素をソフトマックス正規化し、設定1〜6の期待度をバーで表示します。「濃厚/否定」要素は候補を確定・除外するハード判定、「示唆」要素はあくまで参考程度の重み付けのみのソフト判定として区別しています。

## 1geki.jp とのクロスチェック

[一撃「バーディーウイング（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_birdie/0/)（最終更新日 2026年06月05日）には、設定1〜6の完全な数値表（通常時初当たり確率・ST初当たり確率）が掲載されており、本ツールの②数値データはこちらを一次ソースとして採用しました（DMMぱちタウン側の該当ページには数値表がグラフ画像として掲載されており、テキストとして抽出できなかったため）。

- 通常時の初当たり確率：設定1 1/266.7 〜 設定6 1/255.9
- ST初当たり確率：設定1 1/421.2 〜 設定6 1/377.3

また、質的な示唆演出（キャラ紹介シナリオ・サブ液晶カード・獲得枚数表示）については、DMMぱちタウンと1geki.jpの記載内容が完全に一致していることを確認済みです。さらに[なな徹「バーディーウイング（スマスロ）設定判別（設定差・示唆演出）まとめ」](https://nana-press.com/kaiseki/machine/1157/37211/)（最終更新日 2026/06/12）でも同一の数値・示唆内容が掲載されていることを確認し、三者間でのクロスチェックを行っています。

## データについて

以下は「見つかったが採用しなかった」データです。理由とともに記載します。

- **ユニバプレート（サブ液晶）の示唆**：DMMぱちタウンのページに「銅＝2以上濃厚／銀＝3以上濃厚／金＝4以上濃厚／花火柄＝5以上濃厚／虹＝6濃厚」という記載がありましたが、ページ自体に「※示唆内容は、他機種を参考にした推察」「※数値等自社調査」と明記されており、本機種での確定情報ではなく他機種からの類推（純粋な推測）であるため、サイト方針に従い採用を見送りました。
- **サブ液晶のROUNDプレートの色（オレンジ/赤/帯電）**：当該周期のボーナス昇格演出やカップインモードの示唆であり、設定示唆ではなく「周期内のチャンス演出」の位置づけのため対象外としました。
- **レオ・亜室・ユーハの単独キャラ示唆**：ウイングボーナス中のキャラ紹介シナリオNo.1〜9に内包される情報（レオ/亜室の出現、ユーハの先頭出現などはいずれかのシナリオ番号に対応）であるため、二重カウントを避けるためシナリオ番号ベースの示唆演出のみを採用し、キャラクター単体でのチップ化はしていません。
- **通常時のカップインストック以上濃厚演出（レンズフレア演出・打ち抜き演出など）**：設定示唆ではなく「カップインストック獲得」という展開の示唆であり、設定判別要素ではないため対象外としました。

## 技術メモ

UI・アーキテクチャ（白/黒/赤パレットのCSS、数値データ→判別要素チップ→結果バーのカード構成、`logBinomLikelihood`によるソフトマックス正規化、フィードバックウィジェット）は `apps/2026-09-06-tokyo-ghoul-slot-checker/` を踏襲しています。空欄フィールドの安全な扱い（`parseField`で「未入力」と「0件確定」を区別し、各チャンネルを自身のフィールドがnullでない場合のみゲートする）は `apps/2026-09-07-monhun-rise/` のパターンをそのまま採用しました。本機種は1geki.jpに設定1〜6の完全な数値表が公開されていたため、`apps/2026-09-06-valvrave-2/` の欠番設定除外パターン（`SETTINGS = [1, 2, 4, 5, 6]`）は使用していません。
