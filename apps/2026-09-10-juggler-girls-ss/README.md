# ジャグラーガールズSS 設定判別ツール

「ジャグラーガールズSS」（北電子、型式名SジャグラーガールズSS-KH、Aタイプ・ジャグラー系、2024年4月8日導入開始）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「ジャグラーガールズSS」](https://p-town.dmm.com/machines/4540#anc-point)（2026/09/10更新）に掲載されているブドウ確率などの数値データをもとに、二項分布の尤度計算により設定期待度を算出します。

## A-type機種としての特殊な扱いについて

このサイトの他のツール（スマスロ系AT機）は、ストーリー性のある専用の終了画面・エンディング演出・示唆演出（金文字濃厚、虹背景など）を多数搭載しており、それらを②判別要素のチップリストとしてカウントする設計になっている。

しかし「ジャグラーガールズSS」はAT・CZ・ストーリー要素の一切ない純粋なAタイプ機種であり、そうした専用の示唆演出は存在しない。実際にDMMぱちタウンの演出情報ページを確認したところ、搭載されている専用プレミアムは「テンパイスポットライト」（赤7テンパイ時にリール上部のスポットライトが点灯すればBIG濃厚）の1つのみで、これは出目上の「大当り濃厚」を示す直接情報であり、設定を絞り込むための「示唆」演出ではない。そのためこの機種では、②判別要素をチップリストではなく短い説明文のみとし、①数値データにあるブドウ確率・BIG確率・REG確率の3つの独立した二項尤度チャンネルによる判別を中心に据えている（[マイジャグラーⅤ](../2026-09-10-my-juggler-5/)・[ゴーゴージャグラー3](../2026-09-10-gogo-juggler-3/)と同じ設計方針）。これはバグではなく、Aタイプ機種の判別方法の実態に合わせた意図的な設計。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-juggler-girls-ss/

## 機能

- **数値データ**（①）: 通常時総G数を共通の分母として、ブドウ成立回数・BIG当選回数・REG当選回数の3つを、それぞれ独立した二項尤度チャンネルとして入力可能
  - 空欄の項目は「データなし」として扱われ計算から除外される。0を入力した場合のみ「0回」として計算に反映される（`parseField()`によるnull安全設計）
- **判別要素**（②）: A-type機種のため専用の示唆演出が存在しないこと、およびチェリー確率を採用しなかった理由を説明する注記のみを表示。チップリストは意図的に省略している
- 数値データの入力状況に応じて、現在の最有力設定候補をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「ジャグラーガールズSS（6号機）」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_jag_girls/0/)（2025/12/09更新）を確認したところ、DMMぱちタウンには掲載されていない「ボーナス確率」表（BB確率・RB確率・ボーナス合算、全設定分の公表スペック値）が掲載されていた。DMMぱちタウンの機種ページ本体は「解析情報ボーナス時：準備中」となっておりボーナス確率の数値表を持たないため、この一撃側の表をBIG確率・REG確率としてそのまま採用した。

- 一撃「ボーナス確率」表（設定1: BB 1/273.1・RB 1/381.0、設定6: BB 1/226.0・RB 1/252.1など、全6設定分）を採用
- DMMぱちタウンの「小役確率」表（ブドウ確率、全6設定分の公表スペック値：設定1〜4は1/5.98、設定5は1/5.88、設定6は1/5.83）を採用
- 一撃には設定6のみの実戦値としてブドウ1/5.89（1554回）・チェリー1/34.04（269回）も掲載されていたが、これらは実戦値であり、かつチェリーは設定6分しか判明していないため、本ツールのチャンネルには使用していない（ブドウは全設定分の公表スペック値をDMM側から採用済みのため実戦値は不要）

### 採用した3チャンネル（ブドウ・BIG・REG）と、あえて採用しなかったデータ

課題設計として「合成確率（BIG+REG）」「BIG確率」「REG確率」「ブドウ確率」「チェリー確率」「ピエロ確率」「ベル確率」のうち、重複しない組み合わせを選ぶ必要があった。今回は**ブドウ確率＋BIG確率＋REG確率**の3チャンネルを採用し、以下は意図的に不採用とした：

- **合成確率（ボーナス合算）**: BIG確率とREG確率を独立チャンネルとしてすでに採用しているため、合成確率を加えると同じボーナス当選情報を二重にカウントしてしまうため不採用
- **チェリー確率**: **全設定（設定1〜6）分の公式スペック表がDMMぱちタウン・一撃のいずれにも見当たらなかった**ため不採用（CRITICAL RULE: 欠けている設定を絶対に捏造しない）。判明しているのは一撃の設定6実戦値（1/34.04・269回、ボーナス非同時当選分）のみで、設定1〜5の値は一切判明していない
- **ピエロ確率・ベル確率**: DMMぱちタウンの「小役確率」表には設定1の値（いずれも1/1092.27）しか掲載されておらず、設定2〜6の欄は空欄（未公開）だった。全設定分のデータが揃っていないため、CRITICAL RULEに従い不採用とした

## データについて

- ブドウ確率はDMMぱちタウンの公表スペック値（全設定分の数値が確認できる）。BIG確率・REG確率は一撃の「ボーナス確率」表（全設定分の公表スペック値）を採用した
- チェリー確率・ピエロ確率・ベル確率は前述の理由により本ツールでは採用していない。上記の実戦値・部分値はあくまで参考情報であり、本ツールの計算には一切使用されていない
- 機械割（打ち方ごとの機械割、市場調査値97.0%〜107.5%）もDMMぱちタウンに掲載されているが、二項尤度チャンネルとしては使用していない（複数の役・演出成立を合算した結果指標であり、単一の二項分布として扱うのは不適切なため）

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS（白・黒・赤基調のパレット）とHTML骨格（ヘッダー／広告枠／カード①②③／出典／免責事項／フッター、AdSenseスクリプトタグの位置を含む）をそのまま踏襲した単一HTMLファイル。依存ライブラリなし、ビルド不要
- **A-type向けの適応点**: [apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)と同じく、②判別要素はチップリスト方式（`ITEMS`配列＋`buildChips()`）を丸ごと省略し、短い説明文のみに置き換えた。`computeCandidateSettings()`のようなハード除外ロジックも不要となり、`render()`は「3チャンネルの対数尤度を合算してソフトマックス的に正規化する」だけのシンプルな構成にした
- 尤度計算: [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`render()`にある`parseField(el)`パターンを採用。空欄は`null`を返し、各チャンネルはその欄が`null`でないことを個別に確認してから対数尤度計算に加算する
- 本機種は全6設定（設定1〜6）が存在し、かつ採用した3チャンネル（ブドウ・BIG・REG）はいずれも全設定分の公表スペック値が判明しているため、[apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/)の`SETTINGS`配列による設定除外パターンは不要だった。一方でチェリー・ピエロ・ベルというチャンネル自体を、全設定分のデータが存在しないという理由でまるごと不採用にした点は[ゴーゴージャグラー3](../2026-09-10-gogo-juggler-3/)と同様の判断
- BIG・REG・ブドウとも同じ「通常時総G数」を分母として共有する設計（1geki.jpの設定判別ツールや他の解析サイトの標準的なUIパターンに合わせた）
