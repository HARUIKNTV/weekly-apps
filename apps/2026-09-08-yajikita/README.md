# スマスロやじきた道中記参る！ 設定判別ツール

「スマスロ やじきた道中記参る！」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5027#anc-point)（2026/09/08更新、全文）と[一撃「やじきた（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_yajikita/0/)（2026/08/28更新、全文）の両方を読み込み、両サイトに掲載されている完全な設定1〜6テーブルと示唆演出を反映して構築した。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-08-yajikita/

## 機能

- **数値データ**（①）: 以下4系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - AT初当たり確率（1/473.9〜1/318.3）・CZ「関所チャレンジ」出現率（1/231.1〜1/157.5）— 一撃のみに設定1〜6の完全なテーブルが掲載（DMM側は「その他」欄に設定1の値のみ記載のため不採用）、総G数を共有
  - 関所チャレンジ本前兆移行時の温泉ステージ移行率（4.7%〜11.7%、DMM・一撃両方に掲載、値は完全一致）
  - まいるチャージ終了時（規定まいる非到達）の温泉ステージ移行率（4.7%〜11.7%、DMM・一撃両方に掲載、値は完全一致）
- **判別要素**（②）: あっぱれチャンス（茜の連打パターン）、AT終了画面、ユニバプレート、エンディングのレア役時通行手形、獲得枚数表示の計5カテゴリ・19種類の演出を、DMMぱちタウンの分類順（あっぱれチャンス→終了画面系→エンディング→獲得枚数表示）のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外（あっぱれチャンス4種・ユニバプレート5種・獲得枚数表示5種）
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と強さ（すべてnormal tier）に応じて参考程度の重みだけを加える（AT終了画面3種・通行手形2種）
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

DMMぱちタウンと一撃の両方を全文読み比べた結果、重複する数値テーブル（温泉ステージ移行率2系統・あっぱれチャンスの示唆内容・AT終了画面・ユニバプレート・通行手形・獲得枚数表示の示唆内容）はすべて完全に一致していた。**AT初当たり確率**と**CZ「関所チャレンジ」出現率**は一撃側にのみ設定1〜6の完全なテーブルが掲載されており（DMM側は「設定差があると思われるポイント（詳細は調査中）」欄に別の指標として設定1の値のみ言及）、一撃のテーブルを採用した。

## データについて

以下は両サイトを確認したが、理由があって採用しなかった項目：

- **AT直撃当選確率**: DMM・一撃とも設定1の値（1/12302.7）のみが判明しており、設定2〜6は「???」扱いで数値が存在しない。高設定ほど優遇とは記載されているが具体的なテーブルがないため未採用とした。
- **関所チャレンジ・AT中のボーナス合算確率**: 同じくDMM・一撃とも設定1の値（1/906.8）のみが判明しており、設定2〜6が不明のため未採用とした。
- **獲得枚数表示の2222／3333／4444おーばー**: DMM・一撃の表にいずれも項目名のみ掲載され示唆内容が空欄（設定差データが存在しない）だったため、判別要素には含めなかった（555／666／1111／5555／6666おーばーの5種のみ採用）。
- **通常時の高確以上（高確ショート＆ロング・超高確）移行率**: DMMの「設定差があると思われるポイント（詳細は調査中）」欄に記載があるのみで、具体的な設定別数値テーブルが存在しないため未採用とした。
- **モード示唆系の演出・連続演出（白／赤タイトル）の期待度・違和感演出・鏡の地名表示・前兆抜け時のセリフ示唆・カルタ示唆**: いずれも滞在モード（内部状態）や周期到達までの残りまいる、集中状態・わっしょいチャンス・ボーナスの当選示唆など、隠し設定そのものではなくゲーム内の状態を示すものであり、設定判別要素にはあたらないため対象外とした。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5、本機はすべてnormal）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 実装パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲：`numericInputs`配列（id列挙順）→イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→`render()`内の分割代入、の3点の並び順を完全一致させて配線漏れを防止
- 「AT初当たり確率」「CZ「関所チャレンジ」出現率」の2チャンネルは母数が同じ「総G数」のため、`totalG`の入力欄は1つだけ用意し、field-group-labelの見出しに両者を併記して重複入力を避けた（東京喰種ツール・いざ番長ツールと同じパターン）
- 「関所チャレンジ本前兆移行時」と「まいるチャージ終了時」の温泉ステージ移行率はそれぞれ独立した分母（本前兆移行回数／まいるチャージ終了回数）を持つ別抽選のため、専用の見出しと入力欄（N・Kペア）を分けた
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
