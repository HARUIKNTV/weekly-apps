# スロット ソードアート・オンライン（初代SAO）設定判別ツール

「スロット ソードアート・オンライン」（初代SAO、DMM機種ID 4352）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4352#anc-point)（2026/08/21更新）と[一撃「SAO（スロット）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_sao/0/)（2025/12/09更新）の両方を読み込み、両サイトに掲載されている設定1〜6テーブルと示唆演出を反映して構築した。

**注意（SAOⅡとの違い）**: 本サイトには後継機「[ソードアート・オンラインⅡ設定判別ツール](../2026-09-08-sao2/)」（SAO2、DMM機種ID **5025**）が別途存在する。本ツールはそれとは異なる**初代機**（DMM機種ID **4352**、タイトルに「Ⅱ」を含まない）専用であり、混同しないよう機種名・URLともに明確に分離している。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-sao-1/

## 機能

- **数値データ**（①）: 以下9つの見出し（計12系統の独立した二項尤度チャンネル）をそれぞれ入力可能
  - ボーナス初当り確率・CZ当選率・謎当たり当選率・共通ベル出現率 — 総G数ベースの4チャンネルを共有の「総G数」入力欄でまとめて算出
  - 弱チェリー／スイカ／強レア役 それぞれ成立時のCZ・ボーナス当選率を、通常滞在時／高確滞在時で完全に分けて入力（計6チャンネル、レア役ごとに母数が異なるため見出しも個別）
  - エピソードボーナス当選率（ボーナス直撃経由／CZ成功経由をそれぞれ独立入力。母数が異なるため見出しを分離）
- **判別要素**（②）: SAO終了画面（5種）、ミニキャラ（スワイプ、7種）、おうちモード中のコスプレ（3種）、獲得枚数表記（2種）、AT(SAO)突入画面（1種）の計5カテゴリ・18種類の演出を、DMMぱちタウン／一撃の分類順のままカテゴリラベル付きでタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外（計14種）
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/通常/強］の強さに応じて参考程度の重みだけを加える（計4種）
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

DMMぱちタウンと一撃の両方を全文読み比べた結果、**謎当たり当選率（トータル）**と**共通ベル出現率**は両サイトで設定1・設定6の数値が完全に一致していた（DMM側のページ抜粋では設定2〜5の行が省略されていたが、テーブル自体は同一のものと判断）。

**ボーナス初当り確率・CZ当選率・レア役契機（弱チェリー／スイカ／強レア役）のCZ/ボーナス当選率（通常・高確それぞれ）・エピソードボーナス当選率**は一撃側に設定1〜6の完全なテーブルが掲載されており、DMM側で確認できた設定1・設定6の端点の値とも一致したため、一撃のテーブルをそのまま採用した。

**SAO終了画面・ミニキャラ（スワイプ）・おうちモード中のコスプレ・獲得枚数表記・AT(SAO)突入画面**の示唆演出は、DMM・一撃の両方に同内容の記載があり、「〜以上確定!?」表記を金文字（濃厚）の`hard`要素として、明確な奇数/偶数・高設定示唆のみを`soft`要素として扱った。

## データについて

以下は両サイトを確認したが、理由があって採用しなかった項目：

- **超高確滞在時の弱チェリー／スイカ／強レア役当選率**: 一撃側に「設定2〜6は共通値のみ記載（設定別詳細は省略）」と明記されており、設定1のみ個別の値、設定2〜6はひとまとめの値しか公開されていない。設定ごとに区別できないため、誤った補間を避けて未採用とした。
- **CZ失敗時のシナリオ移行率**（内部状態A1/A2・B1/B2・C1/C2・D1/D2間の移行率）: DMM側に記載はあるが、設定1と設定6の端点のみが例示され、設定2〜5の具体的な数値が確認できなかった。一撃側には該当データの掲載もなかったため、中間設定の値が不明として未採用とした。
- **CZ当選時の初期ポイント振り分け**: DMM側に「高設定ほど高ポイント振り分け傾向」という記載はあるが、0pt〜16ptの内部状態別テーブルが複雑で、設定1〜6個別の完全な数値として整理された形での掲載が確認できなかったため、数値チャンネルとしては未採用とした。
- **おうちモード中のコスプレ出現率（数値テーブル）**: DMM側に「サボハニ1.0%（設定4）」のように一部設定の出現率が記載されていたが、設定1〜3・5などの値が確認できず全設定分のテーブルとして揃っていなかった。そのため数値チャンネルにはせず、一撃で明記されている「〜以上確定!?」の定性的な濃厚要素（②の判別要素）としてのみ反映した。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 実装パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲：`numericInputs`配列（id列挙順）→イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→`render()`内の分割代入、の3点の並び順を完全一致させて配線漏れを防止
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMM・一撃の分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 「ボーナス初当り確率」「CZ当選率」「謎当たり当選率」「共通ベル出現率」の4チャンネルはすべて母数が同じ「総G数」のため、`totalG`の入力欄は1つだけ用意し、見出しでグルーピングして重複入力を避けた（東京喰種・SAO2ツールと同じパターン）
- 空欄の数値フィールドは「未入力（判定に使わない）」であり「0件観測」とは区別する必要があるため、[スマスロモンハンライズ 設定判別ツール](../2026-09-07-monhun-rise/)の`parseField`パターンをそのまま踏襲：`el.value.trim() === '' ? null : ...`で空欄を`null`として保持し、`render()`内で各チャンネルは自分自身の入力欄が`null`でないことを個別にチェックしてから尤度計算に加える（例: `if (totalG > 0 && bonusKRaw !== null) l += ...`）。総G数だけ入力してボーナス初当り回数を空欄にした場合に「0回」と誤判定されることはない
- 見つかったデータはすべて設定1〜6の完全なテーブルとして確認できたため、[スマスロヴァルヴレイヴ2 設定判別ツール](../2026-09-06-valvrave-2/)の`SETTINGS = [...]`オブジェクト方式（欠落設定の除外）は今回は不要だった。一部設定のみ判明していた項目（超高確テーブル、コスプレ出現率テーブルなど）は補間・捏造せず、そのまま数値チャンネルから除外している（詳細は「データについて」参照）
