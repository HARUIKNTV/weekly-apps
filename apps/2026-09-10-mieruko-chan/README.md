# スマスロ見える子ちゃん 設定判別ツール

「見える子ちゃん」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5042)（2026/09/09更新）に掲載されている判別要素を、終了画面・エンディングの示唆画面／REG中のキャラ紹介／獲得枚数表示の分類のまま反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

## 一撃（1geki.jp）とのクロスチェック

[一撃「見える子ちゃん（スロット/スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_mierukochan/0/)（2026/09/07更新）を確認したところ、CZ初当り確率・弱レア役契機のCZ当選率（通常／CZ高確）・レア役契機のCZ高確移行確率はDMMぱちタウンの数値と完全に一致していた。

一撃側にのみ、DMMには掲載されていなかった**ボーナス初当り確率**（設定1: 1/294.1 〜 設定6: 1/241.3）の1〜6完全テーブルが掲載されていたため、これを採用してCZ初当り・CZ高確移行と同じ「総G数ベース」のグループにまとめて追加した。また一撃の「REGボーナス中のキャラクター紹介順」表により、DMM側では文章のみだった4パターンの示唆内容（奇数／偶数／奇数×高設定／偶数×高設定）を正確な設定範囲として確定できた。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-mieruko-chan/

## 機能

- **数値データ**（①）: 以下3系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - 弱レア役契機のCZ当選率（通常滞在時） — 通常滞在時の弱レア役成立回数とCZ当選回数
  - 弱レア役契機のCZ当選率（CZ高確滞在時） — CZ高確滞在時の弱レア役成立回数とCZ当選回数（通常時とは母集団が異なるため独立した見出し）
  - CZ初当り・ボーナス初当り・レア役契機のCZ高確移行率（総G数ベース） — 同じ総G数を分母とする3チャンネルをまとめて入力
- **判別要素**（②）: 終了画面・エンディングの示唆画面（8種）、REG中のキャラ紹介（4パターン）、獲得枚数表示（3種）の計15項目を、DMMぱちタウン／一撃の分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/通常/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて（見つかったが採用しなかったもの）

- **機械割（97.8%〜114.9%）**: DMMぱちタウンに設定1・6の両端値のみ掲載されており、設定2〜5の値がわからないため不完全なデータとして不採用
- **ボーナス確率の内訳（BB合算／RB／ボーナス合算）**: 一撃に1〜6の完全テーブルはあったが、採用した「ボーナス初当り確率」と定義が重なる可能性が高く（同じCZ経由のボーナス当選を異なる分母で二重に数えるリスクがある）、統計的な二重カウントを避けるため片方（ボーナス初当り確率）のみ採用した
- **ロングフリーズ発生率**: 発生契機（中段チェリーの一部）は判明しているが、設定差を示す具体的な確率テーブルが両サイトとも未掲載のため不採用
- **規定ゲーム数消化契機のCZ高確移行率（テーブルA〜D）**: ゲーム数ゾーン（50/150/300/450/600/750G）ごとの移行率で、内部的な「テーブル」区分に依存し設定差そのものを示す数値ではないため不採用
- **ステージ示唆（神社（昼）＝CZ高確示唆、神社（夜）＝前兆示唆）**: 設定差ではなく内部状態（CZ高確・前兆）を示す演出のため不採用
- **ジャッジゲームの心音演出（段階別成功期待度）**: CZ成功期待度であり設定差の演出ではないため不採用
- **屋上／ユリア／化け物／ハナ（ボーナス終了画面）**: それぞれ「次回BIG以上期待度」「天井短縮」「CZ高確ループ濃厚」「次回テーブルD濃厚」を示す演出で、設定差を示さないため不採用
- **獲得枚数表示「3535枚OVER」**: 一撃に「???」と記載され示唆内容が未確定のため不採用

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能。CSS・HTML骨格・JSアーキテクチャは [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) を踏襲
- 尤度計算: 各チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 空欄安全対策: `parseField()`で空欄を`null`として扱い、各チャンネルの対数尤度計算はその**チャンネル自身の入力欄**が非nullであることをゲート条件にしている。総G数ベースの3チャンネル（CZ初当り／ボーナス初当り／CZ高確移行）はいずれもnとして同じ総G数を使うが、個々のk欄が空欄なら「0回だった」と誤解釈せずそのチャンネルだけを計算からスキップする（[apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`render()`パターンを踏襲）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMM／一撃の分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 「弱レア役契機のCZ当選率」は通常滞在時とCZ高確滞在時で母集団（n）が異なるため、あえて別々の`field-group-label`に分離。一方、CZ初当り・ボーナス初当り・CZ高確移行の3チャンネルは同じ総G数を共有するため1つの見出しにまとめている
