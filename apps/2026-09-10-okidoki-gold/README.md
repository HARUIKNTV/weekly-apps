# 沖ドキ！GOLD 設定判別ツール

パチスロ「沖ドキ！GOLD」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4258#anc-point)（2026/08/26更新）に掲載されている数値データ（BIG/REG確率・チェリーB確率・確定役B確率・チェリー/スイカ契機のボーナス当選率）から、二項分布の尤度計算で設定期待度を算出する。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-okidoki-gold/

## 一撃（1geki.jp）とのクロスチェック

[一撃「沖ドキゴールド」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_okidoki_gold/0/)を確認したところ、チェリーA/B確率・確定役A/B確率のテーブルはDMMぱちタウンの数値と完全に一致していた。さらに[nana-press「沖ドキゴールド(GOLD)」設定判別ページ](https://nana-press.com/kaiseki/machine/478/12869/)で三者クロスチェックを行い、以下を確認した。

- **BIG確率・REG確率**: DMMぱちタウンには「実戦検証」の実戦値（設定1・5・6のみ）しか掲載がなかったが、1geki.jp／nana-pressの両方に設定1・2・3・5・6の完全な公式スペック表が掲載されており、数値も一致していたためこちらを採用
- **チェリーA/B確率・確定役A/B確率**: DMMぱちタウン・1geki.jp・nana-press三者で数値が完全一致。この過程で「チェリーAは1/52.5固定、確定役Aは1/8192.0固定で全設定共通（設定差はB側のみ）」であることをnana-pressの表で確認し、A側を判別要素から除外する判断に活用した
- **チェリー/スイカ契機のボーナス当選率（通常A・B滞在時）**: DMMぱちタウンのみに掲載。1geki.jp・nana-pressには記載がなかったが、DMM側の値自体は設定ごとに一貫した傾向（設定が上がるほど微増）を示しており、単独ソースながら採用した

## 機種について

「沖ドキ！GOLD」は2022年12月19日導入のユニバーサルブロス製ノーマルタイプ。シリーズ最高峰の期待枚数を誇る新モード「金ドキモード」（次回天国以上確定・滞在中の示唆は一切なし）が特徴。設定1〜6のうち**設定4は存在しない5段階設定**（設定1・2・3・5・6）。

## 機能

- **数値データ**（①）: 「ボーナス（BIG/REG）・チェリーB・確定役B成立回数（総G数ベース）」「チェリー契機のボーナス当選率（通常A・B滞在時）」「スイカ契機のボーナス当選率（通常A・B滞在時）」の3系統・計6チャンネルを、それぞれ独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: 本機は公開データ上、演出による「設定◯以上濃厚」のようなハード確定/否定要素が見当たらなかったため、チップ式カウンターUIは搭載せず、代わりに①の数値データを充実させるよう促す注記カードを配置（詳細は下記「データについて」参照）
- 空欄の数値フィールドは「データなし」として扱い、そのチャンネルの計算をスキップ（0回出現と誤認しない`parseField`パターンを採用）
- 数値データを組み合わせて、現在の最有力設定をリアルタイム表示（一様事前分布のソフトマックス正規化）
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）
- サイト共通のフィードバックウィジェット（右下の💬ボタン、FormSubmit.co経由でメール操作不要のまま意見を送信）を搭載

## データについて（掲載を見送った項目とその理由）

DMMぱちタウン・1geki.jp・nana-press三者のページを精読した上で、以下の項目は「掲載はあるが判別要素として採用しなかった」ものとして意図的に除外した。

- **設定4は存在しない**: この機種は設定1・2・3・5・6の5段階設定で、三ソースすべての全テーブルが一貫して設定4の列を欠いている（`SETTINGS = [1, 2, 3, 5, 6]`として実装）
- **チェリーA確率（1/52.5固定）・確定役A確率（1/8192.0固定）**: nana-pressの表で全設定共通の値であることを確認。設定差がゼロのため判別要素として意味がなく、対象外とした（チェリー/確定役の「合算」ではなく設定差のあるB側のみを採用）
- **実戦検証（実戦データ）**: DMMぱちタウンに設定1・5・6の実戦収録データ（総G数・BIG/REG回数・スランプグラフ）が掲載されていたが、これは公式スペックではなく特定台の実戦記録であり、かつ設定2・3が欠落した不完全なサンプルのため対象外
- **小役確率（実戦上）**: 同じくDMMぱちタウンに共通ベル・チェリー・スイカの実戦値が設定1・5・6のみ掲載されていたが、上記と同じ理由（実戦記録・設定2/3欠落）で対象外
- **ハイビスカス点灯パターン別・次回モード期待度／ボーナステンパイ音・楽曲変化の示唆／演出法則（遅れ・入賞LEDフラッシュ・先チカ・無音）／GODモード関連演出／1G連確定パターン**: いずれも「通常B以上」「天国以上」「ドキドキ」「超ドキドキ」といった機種内部の**モード**（連チャンしやすさの状態で、設定とは独立にゲーム中変動する）を示唆する演出であり、長期的な**設定**（1〜6）そのものへの言及が見当たらないため対象外
- **モード振り分け（設定変更時: 通常A 50.8%／通常B 9.4%／チャンス 39.8%）・天井短縮抽選（25.0%）**: 設定変更（リセット）時に一度だけ発生する分岐で、値自体が全設定共通のため判別要素にならない
- **有利区間関連・ボーナス同時当選（遅れ発生率）・ボーナス種別振り分け（BIG/REG比率）**: 契機役ごとの内部抽選や有利区間の仕組みの解説であり、設定差の記載がないため対象外

## 技術メモ

[apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS・HTML骨格・JSアーキテクチャ（per-setting配列、`logBinomLikelihood`、`render`、ソフトマックス正規化、フィードバックウィジェット）をベースに構築。ただし本機は設定に直結するハード判別要素（濃厚/否定/示唆演出）が見当たらなかったため、②カードの`buildChips`/`computeCandidateSettings`によるチップUIは搭載せず、[apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)の「数値データのみで判別する」構成を踏襲した。

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 設定4が存在しない5段階設定のため、[apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/)で採用した`SETTINGS`配列パターン（`const SETTINGS = [1, 2, 3, 5, 6]`、確率テーブルは設定番号をキーとするオブジェクト）を踏襲。存在しない設定4の値を補間・推測することは一切していない
- 空欄フィールドの安全な扱いは[apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`parseField`パターンをそのまま採用: 空欄は`null`を返し、各チャンネルの尤度計算は対応する生の入力値が`null`でないことを個別にチェックしてから実行する
- 尤度計算: 各チャンネルの二項分布`P(k|n,p)`の対数尤度を合算し、その後ソフトマックス的に正規化（一様事前分布を仮定）。ハード除外要素がないため`candidates`集合の概念は使わず、常に`SETTINGS`全体を対象に確率を算出する
- 「総G数」を共有する4チャンネル（BIG・REG・チェリーB・確定役B）は同じnを使うため`field-group-label`を1つにまとめ、nが異なる「チェリー契機のボーナス当選率」「スイカ契機のボーナス当選率」はそれぞれ別見出しとした
