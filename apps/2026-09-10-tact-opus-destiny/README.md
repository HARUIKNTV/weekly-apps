# スマスロ「Lタクトオーパス デスティニー」設定判別ツール

「Lタクトオーパス デスティニー」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5000)（2026/09/10更新）に掲載されている判別要素をそのままの分類（BIG終了画面／AT終了画面／隠れ凪／エンディングのレア役カード／獲得枚数表示）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

## 一撃（1geki.jp）とのクロスチェック

[一撃「タクトオーパス」設定差・設定判別・終了画面](https://1geki.jp/slot/l_takt_op_destiny/0/)（2026/05/20更新）を確認したところ、掲載されている数値・示唆内容はDMMぱちタウンの内容とおおむね一致していた。特に「規定ポイント到達時の報酬チャンス当選率」「ムジカートチャンス当選時のAT直撃（書き換え）当選率」「CZ種別振り分け」「チャンスゾーン突入時の一発成功抽選」「オルフェループ中の引き戻し抽選」「終了画面・隠れ凪の示唆内容」はDMMぱちタウンと完全に一致する数値・内容だった。

1geki.jp独自の追加情報として、**AT初当たり確率（設定1: 1/358.5 〜 設定6: 1/297.4）** が総G数ベースで掲載されていたため、DMMぱちタウン側にはない数値チャンネルとして今回新たに採用した。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-tact-opus-destiny/

## 機能

- **数値データ**（①）: AT初当たり確率（総G数ベース）、規定ポイント（999pt）到達時の報酬チャンス当選率、ムジカートチャンス当選時の内訳（AT直撃・種別「運命」選択、共通のムジカートチャンス当選回数を分母に共有）、「巨人」「運命」「バトルオブシカゴ（天国＆地獄）」それぞれ開始時のAT当選率（種別ごとに独立した分母）、オルフェループ（上位AT）引き戻し当選率——計7系統・13入力欄をそれぞれ独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: BIG終了画面、AT終了画面（ハルルナスタンプ）、隠れ凪（打-WIN LITE使用時）、エンディングのレア役成立時のカード、獲得枚数表示のすべての要素（計31種類）を、DMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/中/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて（見つかったが不採用にした要素）

- **AT終了後の通常Cモード移行率**（設定1: 38.2% 〜 設定4-6: 41.1%、DMMぱちタウンに完全なテーブルあり）: 1geki.jpが「設定1と6で比較した場合に約3%前後の差しかなく、複数回のサンプルが集まったとしてもブレやすい数値」と明記しており、差が誤差レベルで判別要素として実用に耐えないため不採用とした。
- **赤7揃いフラグ成立時・赤7揃い当選率**（デスティニーボーナス中、設定1: 7.8% 〜 設定6: 8.0%）: 設定間の差が1%未満で、統計的にほぼ判別に使えないため不採用とした。
- **ムジカートチャンス消化中のAT当選率**（小役成立時の書き換え抽選）・**小役確率**（MB1/MB2内部中）: いずれも「全設定共通」と明記されており、設定差が存在しないため対象外とした。
- **通常時のモード振り分け（設定変更時）・モードごとのCZ天井ゲーム数**: リセット判別用の情報であり、プレイ中の設定判別には直接使えないため対象外とした。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能。CSS・HTML骨格・feedbackウィジェットは `apps/2026-09-06-tokyo-ghoul-slot-checker/` から流用
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／中0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 空欄安全性: `parseField()` が空欄を `null` として返し、各チャンネルの尤度計算は自分自身の入力欄が非nullのときのみ実行される（`apps/2026-09-07-monhun-rise/` と同じパターン）。「ムジカートチャンス当選時の内訳」グループは分母（ムジカートチャンス当選回数）を共有する2つのk入力欄を持つが、それぞれの尤度計算はk欄自体が非nullのときだけ実行するため、片方だけ入力しても他方が「0回」と誤解釈されることはない
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 「巨人」「運命」「バトルオブシカゴ」の開始時AT当選率は、母集団（それぞれの種別への当選回数）が互いに独立でかつ異なるため、`field-group-label`を分けて別チャンネルとして扱っている
