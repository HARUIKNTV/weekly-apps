# 沖ドキ！ゴージャス 設定判別ツール

パチスロ「沖ドキ！ゴージャス」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4673#anc-point)（2026/08/11更新）に掲載されている数値データ（BIG/REG確率・チェリーB確率・確定役B確率・チェリー契機のボーナス当選率）から、二項分布の尤度計算で設定期待度を算出する。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-okidoki-gorgeous/

## 一撃（1geki.jp）とのクロスチェック

[一撃「沖ドキゴージャス」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_okidoki_gorgeous/0/)（2025/12/09更新）を確認したところ、BIG確率・REG確率・チェリーA/B確率・確定役A/B確率のテーブルはDMMぱちタウンの数値と完全に一致していた。さらに[nana-press「沖ドキ！ゴージャス」設定判別ページ](https://nana-press.com/kaiseki/machine/856/25722/)で三者クロスチェックを行い、以下を確認した。

- **BIG確率・REG確率**: 三ソースとも設定1・2・3・5・6の完全な公式スペック表を掲載しており、数値が完全一致（1geki掲載のBB/REG確率をそのまま採用）
- **チェリーA/B確率・確定役A/B確率**: DMMぱちタウン・1geki.jp・nana-press三者で数値が完全一致。「チェリーAは1/44.3固定、確定役Aは1/8192.0固定で全設定共通（設定差はB側のみ）」であることをDMMぱちタウンの明記（「チェリー・確定役ともにBにのみ設定差が存在する。」）で確認し、A側を判別要素から除外する判断に活用した
- **チェリー契機のボーナス当選率（通常A・B滞在時）**: DMMぱちタウン・nana-pressの両方に掲載があり数値が一致（設定1・2:1.1%、設定3・5:1.2%、設定6:1.3%）。DMMぱちタウンの元テーブルはHTMLの`rowspan`により見かけ上「設定2以降が空欄」に見えたため、生のテーブルHTMLを直接取得して`rowspan`を確認し、実際は各設定ごとに個別の値が入っていることを確認した上で採用した
- **スイカ契機のボーナス当選率（通常A・B滞在時）**: DMMぱちタウンに掲載はあるが、同じくテーブルHTMLを確認したところ「設定1〜6すべてが`rowspan="5"`で単一の値（2.8%/7.5%/9.2%/15.0%/19.0%）を共有」しており、本文の注記「レア役契機のボーナス当選率はほぼ設定差ナシ」とも整合したため、設定差ゼロの項目として判別要素から除外した（沖ドキ！GOLDではスイカに設定差があったが、本機では無いことをHTML構造まで確認した上で判断）

## 機種について

「沖ドキ！ゴージャス」は2024年12月2日導入のミズホ製6.6号機（有利区間6000G対応）。基本的なゲーム性は過去シリーズ機を踏襲しつつ、赤ドキモード移行で次回モードがドキドキ以上確定となる新要素を搭載。設定1〜6のうち**設定4は存在しない5段階設定**（設定1・2・3・5・6）。なお同シリーズには「沖ドキ！ゴージャス-30」（型式違いの-30番台、機種ID4674）という別ページも存在するが、本ツールは通常版（機種ID4673、ページタイトル「沖ドキ！ゴージャス（パチスロ）設定判別・天井・ゾーン・解析・打ち方・ヤメ時」）のデータを対象とした。「沖ドキDUOアンコール」「沖ドキGOLD」とはいずれも別機種であり、混同しないよう機種ページのタイトルとURLを確認した上でデータを採取している。

## 機能

- **数値データ**（①）: 「BIG・REG・チェリーB・確定役B成立回数（総G数ベース）」「チェリー契機のボーナス当選率（通常A・B滞在時）」の2系統・計5チャンネルを、それぞれ独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: 本機は公開データ上、演出による「設定◯以上濃厚」のようなハード確定/否定要素が見当たらなかったため、チップ式カウンターUIは搭載せず、代わりに①の数値データを充実させるよう促す注記カードを配置（詳細は下記「データについて」参照）
- 空欄の数値フィールドは「データなし」として扱い、そのチャンネルの計算をスキップ（0回出現と誤認しない`parseField`パターンを採用）
- 数値データを組み合わせて、現在の最有力設定をリアルタイム表示（一様事前分布のソフトマックス正規化）
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）
- サイト共通のフィードバックウィジェット（右下の💬ボタン、FormSubmit.co経由でメール操作不要のまま意見を送信）を搭載

## データについて（掲載を見送った項目とその理由）

DMMぱちタウン・1geki.jp・nana-press三者のページを精読した上で、以下の項目は「掲載はあるが判別要素として採用しなかった」ものとして意図的に除外した。

- **設定4は存在しない**: この機種は設定1・2・3・5・6の5段階設定で、三ソースすべての全テーブルが一貫して設定4の列を欠いている（`SETTINGS = [1, 2, 3, 5, 6]`として実装）
- **チェリーA確率（1/44.3固定）・確定役A確率（1/8192.0固定）**: DMMぱちタウンの明記「チェリー・確定役ともにBにのみ設定差が存在する。」で全設定共通の値であることを確認。設定差がゼロのため判別要素として意味がなく対象外とした（チェリー/確定役の「合算」ではなく設定差のあるB側のみを採用）
- **スイカ契機のボーナス当選率（通常A・B滞在時）**: テーブルHTMLの`rowspan="5"`により設定1〜6で完全に同一の値（2.8%/7.5%/9.2%/15.0%/19.0%）であることを確認。本文の「レア役契機のボーナス当選率はほぼ設定差ナシ」という注記とも一致するため対象外とした
- **モードごとのボーナス確率（通常A・B／引き戻し／チャンス、DMMぱちタウン独自集計）**: 1geki.jp・nana-press採用のBIG/REG確率（総G数ベース、全モード込みの公式スペック値）と測定基準・母数が異なる重複指標であり、同じ総G数を分母に両方を尤度計算へ組み込むと証拠を二重計上して偏りが生じるため、より粒度の細かいBIG/REG確率を採用しこちらは対象外とした
- **ハイビスカス点灯パターン別の示唆／ボーナステンパイ音・楽曲変化の示唆／演出法則（遅れ・入賞LEDフラッシュ・先チカ・無音）／1G連確定パターン／裏ドキモード関連演出**: いずれも「通常B以上」「天国以上」「ドキドキ」「超ドキドキ」といった機種内部の**モード**（連チャンしやすさの状態で、設定とは独立にゲーム中変動する）を示唆する演出であり、ページ全文を`濃厚`・`設定[1-6]...(濃厚|以上|否定)`で機械的に検索しても長期的な**設定**（1〜6）そのものへの言及は一件も見つからなかったため対象外
- **リールロック発生率・ボーナス種別振り分け（BIG/REG比率）・1G連当選率・規定ゲーム数短縮抽選・設定変更時のモード振り分け**: 契機役ごとの内部抽選やモード遷移の仕組みの解説であり、設定差の記載がないため対象外
- **機械割（97.2%〜109.0%）**: 全設定込みのレンジ表記であり、個別設定の値ではないため対象外

## 技術メモ

[apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS・HTML骨格・JSアーキテクチャ（per-setting配列、`logBinomLikelihood`、`render`、ソフトマックス正規化、フィードバックウィジェット）をベースに構築。ただし本機は設定に直結するハード判別要素（濃厚/否定/示唆演出）が見当たらなかったため、②カードの`buildChips`/`computeCandidateSettings`によるチップUIは搭載せず、[apps/2026-09-10-okidoki-gold/](../2026-09-10-okidoki-gold/)の「数値データのみで判別する」構成をそのまま踏襲した（フィールド構成もほぼ同一で、GOLDにあったスイカチャンネルのみ本機には設定差が無いため省いている）。

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 設定4が存在しない5段階設定のため、[apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/)で採用した`SETTINGS`配列パターン（`const SETTINGS = [1, 2, 3, 5, 6]`、確率テーブルは設定番号をキーとするオブジェクト）を踏襲。存在しない設定4の値を補間・推測することは一切していない
- 空欄フィールドの安全な扱いは[apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`parseField`パターンをそのまま採用: 空欄は`null`を返し、各チャンネルの尤度計算は対応する生の入力値が`null`でないことを個別にチェックしてから実行する
- 尤度計算: 各チャンネルの二項分布`P(k|n,p)`の対数尤度を合算し、その後ソフトマックス的に正規化（一様事前分布を仮定）。ハード除外要素がないため`candidates`集合の概念は使わず、常に`SETTINGS`全体を対象に確率を算出する
- 「総G数」を共有する4チャンネル（BIG・REG・チェリーB・確定役B）は同じnを使うため`field-group-label`を1つにまとめ、nが異なる「チェリー契機のボーナス当選率」は別見出しとした
