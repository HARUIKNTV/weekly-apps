# スマスロ とんでもスキルで異世界放浪メシ 設定判別ツール

「スマスロ とんでもスキルで異世界放浪メシ」（コナミアミューズメント、2026/08/03導入）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5030)（2026/09/08更新）に掲載されている判別要素をそのままの分類（ST終了画面のアリストロフィー→スイCZ失敗時の残りゴブリン数→ボーナス終了画面→エンディング中の設定示唆）で反映し、数値データと示唆演出の出現回数から設定期待度を算出します。

## 一撃（1geki.jp）とのクロスチェック

[一撃「とんでもスキルで異世界放浪メシ」設定差・終了画面まとめ](https://1geki.jp/slot/l_tonsuki/0/)（2026/09/02更新）を確認したところ、掲載されている判別要素（ボーナス終了画面のパターン、スイCZ失敗時の残りゴブリン数による示唆、エンディング中のウインドウ色による示唆）はDMMぱちタウンの内容と完全に一致していた。

数値データについては、一撃側に**ボーナス初当たり確率**と**CZ確率**の設定1〜6完全テーブルが掲載されており、CZ確率の値はDMMぱちタウン側の「CZ合算確率」ページと数値まで完全に一致することを確認した（例: 設定1 = 1/216.7、設定6 = 1/189.5）。ボーナス初当たり確率はDMMぱちタウン側では「ボーナス出現率」がグラフ画像のみで具体的な数値の記載がなかったため、一撃の完全テーブルを採用した。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-tondemo-skill/

## 機能

- **数値データ**（①）: 総G数をベースにした「ボーナス初当たり確率」「CZ初当たり確率（合算）」の2チャンネルを、それぞれ独立した二項尤度チャンネルとして入力可能（両者とも総G数を共通の母数とするため、1つの見出しにまとめて表示）
- **判別要素**（②）: アリストロフィー（ST終了画面／銅・銀・金・クローバー柄・虹）、スイCZ失敗時の残りゴブリン数（2体〜6体）、ボーナス終了画面（奇数/偶数パターン・高設定示唆[弱/強]・2以上/4以上/6濃厚パターン）、エンディング中の設定示唆（ウインドウの枠色：青枠スイ/青枠フェル/赤枠/紫枠/金枠/虹枠）の4カテゴリ・計23種類を、DMMぱちタウン／一撃の分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて（見つけたが未採用のもの）

本機種は導入から日が浅く（2026/08/03導入）、公開されている設定差データがまだ限られているため、以下は確認できたものの計算には使用していない。

- **ボーナス出現率（DMMぱちタウンのグラフ）**: 設定別のグラフ画像のみが掲載されており、正確な数値（分母）がテキストとして取得できなかったため見送り。同じ指標の完全な数値テーブルが一撃に掲載されていたため、そちらを採用した。
- **小役確率（スイ役・ムコーダ役・フェル役など）**: DMMぱちタウンに掲載はあるが、通常時／チャンスナビ高確中／ST中の状態差のみで設定差の記載がないため見送り。
- **ソテーコンロの規定ゲーム数示唆・ST終了画面のPUSHボイス示唆・ST終了画面のモード示唆**: いずれも内部的な「モード」（通常A/B/C/D/天国）やCZポイントの蓄積量を示唆するものであり、モードと設定番号を対応づける公式なテーブルが公開されていないため見送り。
- **各種ST（異世界ハンティングタイム／女神スペシャルタイム／超女神スペシャルタイム）のループ率・期待枚数、神託の儀・女神降臨の移行率**: 設定1などの代表値が単発で掲載されているのみで、設定別の内訳データがないため見送り。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- CSS・HTMLスケルトン・JSアーキテクチャ（`logBinomLikelihood`、`computeCandidateSettings`、`buildChips`、`render`、softmax正規化）は [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) をベースに作成
- 空欄安全性（blank-field safety）は [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/) の `parseField()` パターンを採用: 数値欄が空欄の場合は「データなし」としてそのチャンネルの尤度計算を丸ごとスキップし、「0回観測」と誤解釈しないようにしている
- 尤度計算: ボーナス初当たり確率・CZ確率それぞれの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMM・一撃の分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
