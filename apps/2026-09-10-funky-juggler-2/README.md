# ファンキージャグラー2 設定判別ツール

「ファンキージャグラー2」（北電子、Aタイプ・ジャグラー系の代表機種のひとつ）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「ファンキージャグラー2」](https://p-town.dmm.com/machines/3961#anc-point)（2026/08/06更新）に掲載されているREG確率（単独当選＋チェリー同時当選の内訳）などのデータをもとに、二項分布の尤度計算により設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-funky-juggler-2/

## A-type機種としての特殊な扱いについて

このサイトの他のツール（スマスロ系AT機）は、ストーリー性のある専用の終了画面・エンディング演出・示唆演出（金文字濃厚、虹背景など）を多数搭載しており、それらを②判別要素のチップリストとしてカウントする設計になっている。

しかし「ファンキージャグラー2」はAT・CZ・ストーリー要素の一切ない純粋なAタイプ機種であり、そうした専用の示唆演出は存在しない（プレミアム演出やチャンス目はいずれも「大当り濃厚」を示す出目上の直接情報であり、設定を絞り込むための「示唆」ではない）。そのためこの機種では、②判別要素をチップリストではなく短い説明文のみとし、①数値データにある3つの独立した二項尤度チャンネル（ブドウ確率・BIG確率・REG確率）による判別を中心に据えている。これはバグではなく、Aタイプ機種の判別方法の実態に合わせた意図的な設計（[apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)・[apps/2026-09-10-gogo-juggler-3/](../2026-09-10-gogo-juggler-3/)と同じ方針）。

## 機能

- **数値データ**（①）: 通常時総G数を共通の分母として、ブドウ成立回数・BIG当選回数・REG当選回数の3つを、それぞれ独立した二項尤度チャンネルとして入力可能
  - 空欄の項目は「データなし」として扱われ計算から除外される。0を入力した場合のみ「0回」として計算に反映される（`parseField()`によるnull安全設計）
- **判別要素**（②）: A-type機種のため専用の示唆演出が存在しないことを説明する注記のみを表示。チップリストは意図的に省略している
- 数値データの入力状況に応じて、現在の最有力設定候補をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

[一撃「ファンキージャグラー2（ファンジャグ2）」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_funkyjuggler2/0/)（2026/05/03更新）を確認したところ、DMMぱちタウンと突き合わせ可能なデータが掲載されていた。

- 一撃の「設定別ボーナス確率」表（BB確率・RB確率・ボーナス合算、公表スペック値）と、DMMぱちタウンのREG確率の内訳（単独当選＋チェリー同時当選）を突き合わせたところ、**設定1・5・6のいずれでも「単独確率の逆数の和」＝一撃のRB確率と一致**することを確認した（例: 設定6は単独1/356.17＋チェリー同時1/992.97 → 合成確率1/262.1で、一撃のRB確率1/262.1と完全一致）。またBB確率＋RB確率の合成値も一撃自身の「ボーナス合算」列と各設定で一致しており、データの内部整合性が高いことを確認できた。この検証を経て、一撃の「設定別ボーナス確率」表のBB確率・RB確率をそのままP_BIG・P_REGとして採用した
- ブドウ確率は一撃の「実機シミュレーションアプリ全設定TOTAL600万ゲーム実戦値」（1/5.96〜1/5.72、設定間で明確な傾斜あり）を採用。DMMぱちタウンにも近い値（1/5.94〜1/5.67）が掲載されており、大きな乖離はなかった

### 採用した3チャンネル（ブドウ・BIG・REG）と、あえて採用しなかったデータ

- **チェリー確率**: DMMぱちタウンでは「設定1〜6: 1/35.62」という**全設定共通の単一値**として掲載されており、一撃側の実戦値（1/35.46〜1/36.27）も設定と相関しない範囲内のばらつき（600万ゲームサンプルにおける統計的ノイズ）にとどまっていた。したがって本機ではチェリー確率に意味のある設定差が確認できず、②の説明文でも触れず、判別チャンネルとしては不採用とした（[apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)がピエロ・ベル確率を「全設定共通のため不採用」としたのと同じ理由）
- **ボーナス合算確率**: BIG確率とREG確率をすでに独立チャンネルとして採用しているため、合算確率を加えると同じボーナス当選情報を二重にカウントしてしまうため不採用
- **REG確率の単独／チェリー同時当選の内訳**: DMMぱちタウンに掲載されているが、両者の合成値が一撃のREG確率（RB確率）と一致することをクロスチェックで確認済みのため、実装では一撃側の合成値（RB確率）をそのまま1チャンネルとして採用し、内訳を別チャンネル化することはしなかった（情報の二重カウントを避けるため）

## データについて

- 参照元: [DMMぱちタウン「ファンキージャグラー2」設定判別・天井・ゾーン・解析・打ち方・ヤメ時](https://p-town.dmm.com/machines/3961#anc-point)（最終更新日: 2026/08/06）、[一撃「ファンキージャグラー2」設定差・設定判別要素まとめ](https://1geki.jp/slot/s_funkyjuggler2/0/)（最終更新日: 2026/05/03）
- 本機は2021年10月に導入された既存機種で、両サイトとも全6設定分の実戦値・公表スペック値が公開されている（「準備中」「調査中」のようなプレースホルダーではない）ことを確認したうえで実装した
- ブドウ確率・BIG確率・REG確率はいずれも公表されている全6設定分のデータを採用しており、一部設定のみ判明しているようなケースはなかったため、[apps/2026-09-06-valvrave-2/](../2026-09-06-valvrave-2/)にあるような`SETTINGS = [...]`形式の設定除外パターンは今回は使用していない（全機種共通で設定1〜6の6段階）

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS（白・黒・赤基調のパレット）とHTML骨格（ヘッダー／広告枠／カード①②③／出典／免責事項／フッター、AdSenseスクリプトタグの位置を含む）をそのまま踏襲した単一HTMLファイル。依存ライブラリなし、ビルド不要
- **A-type向けの適応点**: [apps/2026-09-10-my-juggler-5/](../2026-09-10-my-juggler-5/)と同じ方針で、②判別要素のチップリスト（`ITEMS`配列＋`buildChips()`）を省略し、短い説明文のみに置き換えた。それに伴い`computeCandidateSettings()`のようなハード除外ロジックも不要となり、`render()`は「3チャンネルの対数尤度を合算してソフトマックス的に正規化する」だけのシンプルな構成
- 尤度計算: [apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`render()`にある`parseField(el)`パターンを採用。空欄は`null`を返し、各チャンネルはその欄が`null`でないことを個別に確認してから対数尤度計算に加算する。これにより「入力欄を1つ空欄にしただけなのに0回発生と誤解釈されて、発生確率の高いブドウなどのチャンネルが不当に歪む」という事故を防いでいる
- 3チャンネルとも同じ「通常時総G数」を分母として共有する設計
