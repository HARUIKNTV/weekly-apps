# スマスロ「L ULTRAMAN 最終決戦」設定判別ツール

「L ULTRAMAN 最終決戦」（京楽/OK!!、2026年7月6日導入）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5048#anc-point)（2026/09/08更新）に掲載されている判別要素をそのままの分類（AT終了画面／玉ちゃんトロフィー／獲得枚数表示）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-ultraman-saishuukessen/

## 一撃（1geki.jp）とのクロスチェック

[一撃「ウルトラマン最終決戦（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_ultraman_sai/0/)（2026/07/03更新）を確認。

- **CZ出現率**はDMMぱちタウン・一撃の両方に設定1〜6の完全なテーブルが掲載されており、数値は完全一致（設定1: 1/272.8 〜 設定6: 1/256.2）。相互チェック済みのため採用。
- **AT初当たり確率**（設定1: 1/445.4 〜 設定6: 1/422.4）と**アクティベーションモード移行率**（設定1: 1/163.0 〜 設定6: 1/154.1）は、一撃側にのみ設定1〜6の完全なテーブルが掲載されていた。DMMぱちタウン側は解析情報のページ内で設定1の値のみを記載する形（例:「突入確率 1/163.0（設定1）」）だったため、完全なテーブルが取れる一撃の数値を採用した。
- 判別要素（AT終了画面・玉ちゃんトロフィー・獲得枚数表示の示唆内容）は両サイトで一致していた（キャラクター名の表記がDMM「ウルトラマン＆ゾフィー／6人／崩壊」、一撃「進次郎＆進／味方集合／初代ウルトラマン」など細部で異なるが、示唆する設定の階層は同一）。本ツールではDMM側の表記を採用した。

## 機能

- **数値データ**（①）: AT初当たり回数・CZ当選回数・アクティベーションモード当選回数を総G数ベースの3つの独立した二項尤度チャンネルとして入力可能（空欄はその演出データなしとして計算から除外）
- **判別要素**（②）: AT終了画面（味方3人A/B・ウルトラマン＆ゾフィー・エド・6人集合・崩壊・ベムラーの7種）、玉ちゃんトロフィー（銅・銀・金・ゼブラ柄・虹の5種）、獲得枚数表示（246枚OVER・456枚OVER・666枚OVERの3種）の計15種類を、DMMぱちタウンの分類のままカテゴリラベル付きでタップ式カウンターに記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて（発見したが未採用のもの）

以下はDMMぱちタウン／一撃の両ページで見つかったが、設定差ツールへの組み込みを見送った項目。

- **AT終了時のボイス**・**エンディング中のレア役成立時のボイス**（DMMぱちタウン「演出情報」・一撃「設定差・終了画面」双方に記載）: 両サイトとも「示唆内容は現状不明」と明記されており、設定差の方向性（奇数/偶数/高設定など）が判明していないため未採用。今後情報が判明次第、追加を検討。
- **アクティベーションモード突入確率**（DMM「AM性能」内: 「1/163.0（設定1）」）、**高確中のアクティベーションモード当選率**（DMM「CZ・AM・AT当選率」内、役ごとの当選率が設定1のみ記載）、**ブレイクモード終了時・スペシウム目高確移行率**（DMM「ブレイクモード」内、設定1のみ記載）: いずれもDMM側では設定1の値のみが公開されており、設定2〜6の値が同ページ内に見当たらなかった。一撃側にも同等の完全テーブルは確認できなかったため、CRITICAL RULE（欠落設定の補完・推測の禁止）に従い、これらの項目は数値チャンネルとして採用しなかった（アクティベーションモード自体の「移行率」は一撃の完全テーブルで別途採用済み — 上記クロスチェック参照）。
- 上乗せ内訳・ブレイクモード規定ポイント振り分け・ウルトラチャレンジの演出法則など、AT/上位AT中の細かい抽選表は多数あるが、いずれも設定差ではなく純増枚数や継続率に関する内部抽選のため対象外。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- ベースは[apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/)のCSS・HTML構成・JSアーキテクチャ（`logBinomLikelihood` / `computeCandidateSettings` / `buildChips` / `render` のソフトマックス正規化）をそのまま踏襲
- 数値データの空欄安全性は[apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/)の`parseField`パターンを採用: 空欄は「そのチャンネルのデータなし」（`null`）として扱い、「0回観測」と混同しないよう各チャンネルは自分自身のフィールドが`null`でないときだけ尤度計算に加える
- 尤度計算: AT初当たり・CZ・アクティベーションモードそれぞれの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持
- AT初当たり・CZ・アクティベーションモードの3チャンネルは同じ総G数（`totalG`）を分母として使うため、厳密には母集団が重複する可能性がある（CZ→AT、AM→CZのルートが一部重なる）。実用上の簡易計算として、東京喰種ツールと同様に独立チャンネルとして割り切って扱っている
