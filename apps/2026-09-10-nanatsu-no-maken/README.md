# スマスロ七つの魔剣が支配する 設定判別ツール

「Lパチスロ 七つの魔剣が支配する（スマスロ ななつま）」の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4709#anc-point)（2026/09/02更新）に掲載されている判別要素をそのままの分類（ST終了画面／プロローグBONUS終了画面／キンバリーBONUS中のキャラ紹介／エンディング中のセリフ／ボイスカスタム）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-nanatsu-no-maken/

## 機能

- **数値データ**（①）: 「ボーナス/ST初当り確率」を、共通の総G数を母数とする2つの独立した二項尤度チャンネル（ボーナス当選回数・ST当選回数）として入力可能
- **判別要素**（②）: ST終了画面、プロローグBONUS終了画面、キンバリーBONUS中のキャラ紹介（背景色）、エンディング中レア役成立時のセリフ、ボイスカスタム（エスメラルダ選択時）の全22要素を、DMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と強さに応じて参考程度の重みだけを加える（「奇数かつ高設定示唆」「偶数かつ高設定示唆」は該当する設定同士の積集合として重みを設定：ゴッドフレイ＝奇数{1,3,5}∩高設定{4,5,6}={5}のみ、カルロス＝偶数{2,4,6}∩高設定{4,5,6}={4,6}）
- 広告枠を3か所設置（ヘッダー直下728×90、判別要素と結果の間300×250、フッター上728×90）— プレースホルダー表示のみ
- モバイル表示時の日本語の不自然な改行を防ぐCSS（`word-break: keep-all`）を適用
- 空欄の入力欄は「未計測」として扱い、その数値チャンネルの尤度計算を丸ごとスキップする（`parseField`で`null`判定）。総G数だけ入力してボーナス当選回数を空欄のままにしても「0回」として誤って不利判定されることはない

## 一撃（1geki.jp）とのクロスチェック（2026-09-10）

[一撃「七つの魔剣が支配する」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_nanatsuma/0/)（2025/12/09更新）を確認したところ、DMMぱちタウンには設定別の完全な数値テーブルが掲載されていなかった**「ボーナス/ST初当り確率」**（設定1: ボーナス1/228.0・ST1/408.3 〜 設定6: ボーナス1/164.7・ST1/272.3、設定1〜6の全6段階が揃った完全なテーブル）が一撃側に掲載されていたため、①数値データの主軸として採用した。ST終了画面・プロローグBONUS終了画面・キンバリーBONUS中のキャラ紹介・エンディングのセリフ・ボイスカスタムの各示唆内容は両サイトの記載が完全に一致していたため、DMMぱちタウンの分類・文言をそのまま②のチップに採用した。

## データについて

- **250G消化時のボーナス当選率**: 両サイトとも「250G消化時のボーナス当選率に設定差あり」（DMM：「250G消化時のボーナス当選率」／一撃：「その他：250Gでのボーナス当選率に設定差あり!?」）と言及があるものの、設定ごとの具体的な数値テーブルは掲載されていなかった（p-townの「ボーナス出現率」欄はグラフ画像表示のみでテキスト抽出不可）。設定ごとの正確な値が不明なため未採用とした
- **ボーナスレベル関連の示唆演出**（キャラルーレット、魔法植物、キンバリーBONUS終了画面のボーナスレベル示唆など）は、いずれも次回ボーナスの種別（プロローグ/キンバリー）や規定ゲーム数を示唆するものであり、設定そのものを示唆する要素ではなかったため未採用
- **ゲーム数消化時のボーナス期待度**（100G消化時約40%など）や**CZ突破時のボーナス期待度**（剣花団チャンス約40%、魔剣チャンス約46%など）も設定差の記載がない共通仕様値のため未採用
- **七つの支配トリガー当選率・ゲーム数上乗せ抽選率**などボーナス/ST中の詳細抽選テーブルは多数公開されているが、いずれも設定差の記載がなく、AT・ボーナス消化中の内部抽選（出玉に関する演出）であって設定判別要素ではないため未採用

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- この機種は設定1〜6の全6段階が揃った通常の機種のため、`SETTINGS`配列によるオブジェクトキー方式ではなく、他の通常機種と同じ配列インデックス方式（`P_BONUS[i]`, `i = s - 1`）で確率テーブルを保持している
- チップUI・尤度計算の基本パターン、および空欄を「未計測」として扱う`parseField`ヘルパーは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲
- フッター直前の意見・要望フォーム（フローティング💬ボタン）はサイト共通のFormSubmit.co連携ウィジェットをそのまま流用
