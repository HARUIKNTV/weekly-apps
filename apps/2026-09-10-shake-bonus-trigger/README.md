# SHAKE BONUS TRIGGER 設定判別ツール

大都技研「SHAKE BONUS TRIGGER」（スマスロ、2025年10月20日導入）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4893#anc-point)（2026/09/06更新）に掲載されている判別要素をそのままの分類（BIG終了画面の色／コパンダトロフィー／REG中の技術介入ボイス）で反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-shake-bonus-trigger/

## この機種の特徴：設定3・4が存在しない

DMMぱちタウン・1geki.jpの全テーブルが設定1・2・5・6の4列で構成されており、設定3・4は存在しない4段階設定の機種。上乗せループ型のボーナストリガー（BT）搭載機で、**偶数設定（2・6）は初当り確率が優遇され、奇数設定（1・5）はBT（ボーナストリガー）の継続率が優遇される**という偶奇で傾向が逆転する珍しい特徴を持つ。本ツールもこれに合わせて`SETTINGS = [1, 2, 5, 6]`という設定空間で計算しており、結果表示にも設定3・4は出てこない。

## 機能

- **数値データ**（①）: 総G数を共通の分母として、BIG確率・REG確率・ベル合算確率・チェリー確率・スイカ合算確率の5つを独立した二項尤度チャンネルとして入力可能。加えて、母数が異なる「BT（ボーナストリガー）継続率」（ボーナストリガーチャンスで引いたJAC総数のうち、継続JAC・SJACだった回数）を別チャンネルとして独立入力できる
- **判別要素**（②）: BIG終了画面の色、コパンダトロフィー、REG中の技術介入ボイス（左リール青7狙え成功時）を、DMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と強さに応じて参考程度の重みだけを加える
- 広告枠を3か所設置（ヘッダー直下728×90、判別要素と結果の間300×250、フッター上728×90）— プレースホルダー表示のみ
- モバイル表示時の日本語の不自然な改行を防ぐCSS（`word-break: keep-all`）を適用

## 1geki.jpとのクロスチェック（2026-09-10）

[一撃「シェイク（スロット）」設定差・設定判別要素まとめ](https://1geki.jp/slot/lb_shake/0/)（2026/07/07更新）を確認したところ、DMMぱちタウンに掲載されているボーナス確率・小役確率・BT中のJAC当選率（トータル継続率含む）・終了画面・トロフィー・REG中ボイスの数値がすべて完全に一致していることを確認した。1geki側では「S-JACは全設定共通の2.5%で当選する」と明記されており、DMM側の表で設定2・5・6のSJAC欄が空欄（1のみ2.5%表記）だった理由が「同一値のセル結合による省略」であって欠落データではないことも、この記載によって裏付けが取れた。

## データについて

- **設定2の「スイカ＋ナディアBIG」同時当選確率**: DMM側では設定1・2ともに1/16384.0と明記されている一方、1geki側の該当表では設定2の欄が空欄になっていた。これはBT中JACの割合表と同様に「設定1と同じ値のセル結合による省略」と判断し、値自体は欠落していないと確認した。ただし本ツールでは以下の理由でこの数値自体を採用しなかった。
- **特定ボーナス同時当選確率（スイカ＋ナディアBIG／ベル＋REG／特殊役I＋ボーナス）**: DMM・1geki双方に設定1・2・5・6すべての数値が掲載されており欠落はないが、いずれも1/1872.5〜1/16384.0という非常に低い確率で、通常のプレイ回数ではほぼ観測できず、かつ判別にはWINチェック（ボーナス入賞時のPUSHボタン確認）による同時当選契機役の特定が必要という高難易度の作業を要求するため、通常プレイヤーが実戦で正確に集計するのは非現実的と判断し未採用とした
- **ベルA/B・スイカA/Bの個別確率**: DMMには停止形（第1停止位置など）で判別するA/B別の内訳テーブルが掲載されているが、リール停止形の識別を要求する複雑な入力になるため、本ツールでは合算値（ベル合算・スイカ合算）のみを採用し、A/B別の入力は設けなかった
- **ボーナス同時当選期待度（ベルA/B・スイカA/Bごとの同時当選率）**: 上記A/B判別が前提となる集計であり、同じ理由で未採用とした
- **継続JAC以上当選時・SJAC期待度（小役ごとの内訳）**: BT中のJAC継続率はすでに①の「BT（ボーナストリガー）継続率」チャンネルで総合的に扱っており、小役ごとの内訳まで分解すると同じ証拠（JAC継続）の二重カウントになるため未採用とした
- **演出モード別の演出期待度＆占有率（NORMAL/AX-STYLE/演出モード共通）**: 設定差ではなくボーナス成立時の演出期待度（すべての設定に共通する値）であり、設定判別要素として使えないため未採用とした
- **天井突入条件**: DMM記載は「なし」であり、天井による絞り込みは行えないため対象外

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 設定空間を`SETTINGS`配列で保持し、確率テーブルもオブジェクト（`{1: ..., 2: ..., 5: ..., 6: ...}`）で持たせることで、4段階設定の機種にも対応できる形に一般化した（[革命機ヴァルヴレイヴ2](../2026-09-06-valvrave-2/)の5段階設定パターンを踏襲）
- 空欄フィールドは「未入力（欠測）」として扱い、0として計算しない（`parseField`関数）。総G数を共有するBIG/REG/ベル/チェリー/スイカの各チャンネルで、一部だけ空欄にしても他のチャンネルの計算には影響しない
- チップUI・尤度計算の基本パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲
