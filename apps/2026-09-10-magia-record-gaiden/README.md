# スマスロ マギアレコード 魔法少女まどか☆マギカ外伝 設定判別ツール

「スマスロ マギアレコード 魔法少女まどか☆マギカ外伝」（ミズホ、2025/04/07導入）の設定判別ファンメイド計算機です。
[DMMぱちタウン「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4745#anc-point)（2026/09/10更新時点）を主データ源とし、[一撃(1geki.jp)「設定差・終了画面」](https://1geki.jp/slot/l_magireco/0/)（2025/12/26更新時点）の数値と突き合わせて採用しています。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-magia-record-gaiden/

## 機能

- 数値データ（総G数ベースのボーナス／マギアラッシュ(AT)初当り確率・弱チェリー出現率、スイカ契機のCZ当選率、有利区間移行時・AT終了時の高確移行率＆モード移行率、BIG終了時の高確移行率、みたまボーナス「ウワサバトル発展」時のAT当選率（報酬レベル2/3別）、エピソードボーナス中の黒江エピソード出現率）を入力すると、設定ごとの二項対数尤度を積み上げて期待度を算出します。
- 空欄の入力欄は「未計測」として扱い、その項目の尤度計算をスキップします（0回成立と誤認しません）。
- 終了画面・ユニバプレート・ストーリー話数順番・キャラ紹介パターン・エンディングカード・エピソードキャラクターの示唆演出をタップ式チップでカウントでき、「濃厚/否定」は候補設定をハード確定・除外、「示唆」は参考程度の重み（弱/通常/強）だけを加算します。
- 全チャンネルをsoftmax正規化し、設定1〜6の期待度バーと現在の候補・最有力設定を表示します。

## 1geki.jpとのクロスチェックについて

1geki.jpの「設定差・終了画面」ページは、DMMぱちタウンと同一の数値（弱チェリー出現率、マギアチャレンジ・黒江チャレンジ出現率、状況ごとの高確移行率、みたまボーナス[ウワサ発展]AT当選率、ストーリー話数順番・エンディングカードの示唆内容）を掲載しており、いずれも一致を確認できました。加えて1geki.jp独自に「ボーナス初当り合算確率」「マギアラッシュ(AT)初当り確率」という総G数ベースの確率表を公開していたため、こちらもツールに採用しています。

## データについて

以下は出典で見つけたものの、理由がありツールへの採用を見送りました。

- **AT直撃確率・AT引き戻し確率（1geki.jp）**: 1geki.jp編集部の実戦データ（数本〜十数G分のサンプル）に基づく参考値で、各設定共通の公式な理論確率テーブルとしては未公開のため採用を見送りました（例：設定1「出現せず」、設定3「出現せず」など、サンプル数が判別に耐えないレベル）。
- **みたまボーナス終了時の高確移行率（DMMぱちタウン）**: 高確+10G/+20G/+30G・トータル移行率いずれも「全設定共通 100%」で、設定間の差が存在しないため計算チャンネルとして採用する意味がありませんでした。
- **魔法少女モードの詳細な振り分け（やちよ/鶴乃/さな/フェリシア/黒江の個別比率）**: 6択の多項分布であり、二項尤度モデルにそのまま組み込めないため簡略化しました。代わりに「いろは/いろは以外」の二値化した振り分けを数値チャンネルとして採用し、各キャラクターの個別傾向（やちよ→設定2、鶴乃→設定3など）はエピソードボーナスのキャラクター示唆チップとして別途カウントできるようにしています。
- **楽曲対応画面・報酬ランクアップ抽選など、AT中の上乗せ性能に関する詳細テーブル**: 設定差の記載がなく（全設定共通）、判別要素ではないため対象外としました。
- **マギアアタックのカード・属性・キャラレベル振り分け**: AT中の上乗せ演出であり、設定差データが公開されていないため対象外としました。

## 技術メモ

本ツールは `apps/2026-09-06-tokyo-ghoul-slot-checker/` のCSS・HTML骨格・JSアーキテクチャ（設定別確率配列＋`logBinomLikelihood`によるベイズ的対数尤度合算、`computeCandidateSettings`によるハード確定/除外、`buildChips`によるタップ式カウンタ、softmax正規化での期待度算出）をそのまま踏襲しています。
空欄フィールドの扱い（`parseField`が空欄を`null`として返し、各チャンネルの計算を自チャンネルのフィールドが非nullの場合のみ実行する方式）は `apps/2026-09-07-monhun-rise/` の実装パターンを採用し、未入力チャンネルが「0回成立」と誤認されないようにしています。
フィードバックウィジェット（画面右下の💬ボタン、FormSubmit.co経由）も同じくtokyo-ghoul-slot-checkerからそのまま流用しています。
