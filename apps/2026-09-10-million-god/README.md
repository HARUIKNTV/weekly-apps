# スマスロ「ミリオンゴッド-神々の軌跡-」設定判別ツール

「スマスロ ミリオンゴッド-神々の軌跡-」（DMMぱちタウン機種ID: 4961）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4961#anc-point)（2026/09/10確認）に掲載されている、設定1〜6が完全にそろった数値テーブルとユニバプレートの示唆内容を反映し、実戦データとプレート出現回数から設定期待度を算出します。

なお本機は「ミリオンゴッド」シリーズの中でも最新の「-神々の軌跡-」（2026年導入のスマスロ版）で、旧機種の「-神々の系譜-」「-神々の系譜-ZEUS ver.」「-神々の凱旋-」とは別機種・別解析データです。DMMぱちタウンでの検索時点でヒットした同シリーズ機種の中で本タイトルが最新・最も情報が充実していたため、これを採用した。

## 一撃（1geki.jp）とのクロスチェック

[一撃「ミリオンゴッド（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_milliongod_kiseki/0/)（2026/09/10確認）を確認したところ、掲載されている数値・示唆内容はDMMぱちタウンの内容と完全に一致していた。さらにナナプレス・ラクパチ・ちょんぼりすた・スロッターズ等の複数の解析サイトを横断して照合したが、いずれも同じ2項目の数値テーブルとユニバプレートの示唆内容のみが「設定1〜6が完全にそろった」形で掲載されており、他の項目は後述のとおり不完全だった。

## 機能

- **数値データ**（①）: AT（GG）初当たり確率（総G数ベース）、Z-ZONE昇格率（非ガイアステージ経由のGG当選時）——独立した母数（n）を持つ2系統をそれぞれ独立した二項尤度チャンネルとして入力可能
- **判別要素**（②）: GG終了画面のユニバプレート（銅・銀・金・花火柄・虹の5段階）をタップ式カウンターで記録
  - すべて「〜以上濃厚」「〜濃厚」の確定情報で、1回でも出現すれば矛盾する設定を候補から確実に除外（ハード除外）
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて

新機種のため解析が発展途上で、複数の解析サイトを確認したが「設定1〜6のうち一部しか判明していない」「調査中」と明記された項目が非常に多かった。以下は発見したものの、不完全・示唆演出と設定の関連が薄いなどの理由で採用を見送った項目：

- **青7の3連・4連時のGG当選率**: 設定1（1.2%/33.2%）と設定2（10.2%/50.0%）のみ判明しており、設定3〜6はすべての解析サイトで「調査中」と明記されていたため未採用
- **ガイアステージ中のZ-ZONE当選率**: 設定1（15.0%）のみ判明しており、設定2〜6は「調査中」のため未採用
- **表モード別GG当選率（低確/通常/天国/超天国）**: サイトによって設定間の値が食い違っており（ある解析は「設定2-6で0.01〜0.04%」とぼかした記載、別の解析は設定ごとに異なる具体値を提示）、信頼できる一致が取れなかったため未採用
- **リプ連（リプレイ3連続）でのGG当選率実戦値**: 実戦サンプル数が小さく（設定ごとに数十試行程度）、公表値ではなく実測ベースの推測値にとどまるため未採用
- **押し順15枚役（下段黄7）の設定差**: 「設定1は1/410相当、設定6は1/35〜130相当」という記載はサイトの独自推測値で、公式解析の裏付けとなる設定1〜6の完全な表が見つからなかったため未採用
- **コイン持ち（ベース）の偶奇差**: 「設定1: 約30.8G/50枚、設定6: 約34.4G/50枚」という記載はあるが設定2〜5の値がなく、傾向の推測にとどまるため未採用
- **GG入賞画面／終了画面のLED色（継続率示唆）**: AT中のループストック継続率を示唆する演出であり、機械の「設定」そのものとは無関係なため対象外
- **ステージ移行（アポロン→アクロポリス→アテナ→ガイア等）や「謎当り」「光の風演出」頻発などの体感的示唆**: 具体的な設定差データの裏付けがない、体感・推測ベースの記述だったため対象外
- **GOD揃い・SP役・赤7揃いなどの確定役確率**: 全解析サイトで「全設定共通」と明記されており設定差がないため対象外（判別要素として意味を持たない）

## 技術メモ

- [apps/2026-09-06-tokyo-ghoul-slot-checker/](../2026-09-06-tokyo-ghoul-slot-checker/) を参考実装として、CSS（白/黒/赤の配色）・HTML骨格・JSアーキテクチャ（`logBinomLikelihood` / `computeCandidateSettings` / `buildChips` / `render` とソフトマックス正規化）をそのまま踏襲
- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 空欄の数値フィールドは「そのチャンネルのデータなし」を意味し「0回観測」とは区別する必要があるため、[apps/2026-09-07-monhun-rise/](../2026-09-07-monhun-rise/) の`render()`にある`parseField`ヘルパー（空欄なら`null`、それ以外は0以上の整数）をそのまま採用し、各チャンネルの尤度計算は自チャンネルの値が`null`でないことをそれぞれ個別にチェックしてから合算している
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 今回は公開データの制約上「示唆」段階（`kind: 'soft'`）のchipが1件も採用できなかったため`ITEMS`はすべて`kind: 'hard'`だが、`TIER_WEIGHT`・`SOFT_CAP`・`softItems`関連のロジックは将来的な解析情報の追加に備えてそのまま保持している
