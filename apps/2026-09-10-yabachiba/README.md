# ヤバチバ 設定判別ツール

パチスロ「ヤバチバ」（型式名：LヤバチバZM／メーカー：ネット、2026年7月6日導入）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/5047#anc-point)（2026/09/10時点）に掲載されている「ベル集中」突入率のデータを反映し、実戦データから設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-10-yabachiba/

## この機種の特徴：設定3が存在しない／判別要素が非常に少ない

- DMMぱちタウン・一撃の全テーブルが設定1・2・4・5・6の5列で構成されており、設定3は存在しない5段階設定の機種。本ツールもこれに合わせて`SETTINGS = [1, 2, 4, 5, 6]`という設定空間で計算しており、結果表示にも設定3は出てこない。
- 本機は**ボーナス初当り確率（約1/398）に設定差がなく**、通常の「初当り確率カウント」による判別ができない。両サイトとも「ベル集中」突入率のみが確度の高い設定推測要素として案内されており、他に信頼できる判別要素（濃厚・示唆演出）はほぼ見当たらなかった。

## 機能

- **数値データ**（①）: 「ベル集中」突入率（通常時消化G数・突入回数）を二項尤度チャンネルとして入力可能
- **判別要素**（②）: 現状、設定差のある濃厚・示唆演出が両サイトとも確認できなかったため、チップは未実装（判明次第追加できる`ITEMS`配列の構造だけ用意）
- 広告枠を3か所設置（ヘッダー直下728×90、判別要素と結果の間300×250、フッター上728×90）— プレースホルダー表示のみ
- モバイル表示時の日本語の不自然な改行を防ぐCSS（`word-break: keep-all`）を適用
- サイト共通の意見・要望フォーム（フローティング💬ボタン、FormSubmit経由でメール受信）を搭載

## 一撃（1geki.jp）とのクロスチェック（2026-09-10）

[一撃「ヤバチバ」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_yabachiba/0/)（2026/07/10更新）を確認したところ、DMMと完全に一致する「ベル集中」突入率テーブル（設定1: 約1/7163〜設定6: 約1/1767）が掲載されており、追加で得られる数値データはなかった。同サイトの以下のページも確認したが、いずれも設定差のある判別要素は見つからなかった。

- [小役確率・通常時のベース](https://1geki.jp/slot/l_yabachiba/4/): 小役確率は設定1のみ掲載（他設定は空欄）。「50枚あたりの消化ゲーム数」は設定1・4・5のみ数値あり（設定2・6は空欄）で、機種全体としても30.7G〜30.9Gとほぼ差がなく判別には使えない
- [点灯パターン/特殊ボイス/演出法則](https://1geki.jp/slot/l_yabachiba/71/): 花笠ランプの変則点滅や特殊ボイスはすべて「黒7以上濃厚」「虹7濃厚」といった**ボーナス種別（BIG/REG/虹7）の示唆**であり、設定差の示唆ではなかった

## データについて（見つけたが採用しなかったもの）

- **ボーナス初当り確率（約1/398）**: DMM・一撃とも「全設定共通、設定差なし」と明記。判別要素として機能しないため非採用
- **小役確率（共通ベル・スイカ）**: DMMの特集記事「【設定6・データ】『ヤバチバ』の設定差を考察！」に設定1（解析値）と設定6（実戦値・約3600G）の2点のみ掲載。設定2・4・5のデータが存在せず、5段階設定の完全なテーブルにならないため非採用
- **「集中状態」突入率の実戦値**: 同特集記事に設定6のみ、しかも約2500G・1回の突入という単一サンプルしか掲載されておらず、他設定との比較ができないため非採用（なお「集中状態」はDMM本体ページの「ベル集中」と同一の状態を指す）
- **ボーナス継続ストック当選率**（設定変更時約75%／ボーナス後100G消化時約42%／弱チェリー0.01%／強チェリー48.90%）: 契機ごとの値のみで設定別の内訳が一切公開されておらず、設定判別には使えないため非採用
- **ボーナス入賞時ボイス・1日1回ボイスの示唆内容**: DMM特集記事で「継続示唆のボイスもあるようだが、詳細は調査中」と明記されており、具体的な設定対応が不明なため非採用
- **50枚あたりの消化ゲーム数**: 上記の通り一撃に設定2・6のデータが欠落しており、かつ差自体が0.2G程度とごくわずかで判別に使えないため非採用

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 設定空間を`SETTINGS`配列で保持し、確率テーブルもオブジェクト（`{1: ..., 2: ..., 4: ..., 5: ..., 6: ...}`）で持たせることで、5段階設定の機種にも対応できる形に一般化（[革命機ヴァルヴレイヴ2](../2026-09-06-valvrave-2/)と同じパターン）
- 空欄の数値フィールドを「未入力（判定に使わない）」として扱う`parseField`ヘルパーを採用し、未入力を「0回観測」と誤解釈しないようにした（[モンハンライズ版](../2026-09-07-monhun-rise/)のrender()と同じブランクセーフ設計）
- CSS・HTML骨格・チップUI・尤度計算・フィードバックウィジェットの基本パターンは[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)を参照実装として踏襲
