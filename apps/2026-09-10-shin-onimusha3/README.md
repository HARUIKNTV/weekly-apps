# スマスロ 新鬼武者3 設定判別ツール

「スマスロ 新鬼武者3」（レオスター、型式名：L新鬼武者3SA、導入開始日：2025年10月06日）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4880#anc-point)（2026/08/28更新）に掲載されている判別要素をそのままの分類（終了画面系／ボイス系／小役契機の当選率関連／エンディング／獲得枚数表示）で反映し、数値データと示唆演出の出現回数から設定期待度を算出します。

## 一撃（1geki.jp）とのクロスチェック

[一撃「新鬼武者3（スマスロ）」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_shinnoni3/0/)（2025/11/14更新）を確認したところ、掲載されている数値・示唆内容はDMMぱちタウンの内容と完全に一致していた（弱レア役契機の鬼斬チャージ当選率／AT「蒼剣RUSH」初当り確率／各種示唆演出）。

- **AT「蒼剣RUSH」初当り確率**は1geki.jpのみに設定1〜6の完全なテーブルが掲載されていたため採用（DMMぱちタウン側は機種概要欄に数値記載がない）。
- **ボーナス中のオールキャストナビ選択率**はDMMぱちタウン側に設定1〜6の完全なテーブルが掲載されていたため採用（1geki.jp側は設定3・5・6が「-」で欠落）。
- 弱チャンス目／押し順弱チャンス目・弱チェリー／弱スイカ契機の鬼斬チャージ当選率（通常時・高確中）は両サイトで数値が完全一致（「鬼斬チャージ」＋「真・鬼斬チャージ」を合算した「トータル」列を採用）。

## 機能

- **数値データ**（①）: 全6系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - AT「蒼剣ラッシュ」初当たり確率（総G数ベース、1geki.jpのみ掲載）
  - ボーナス中のオールキャストナビ選択率（4コマ以内で目押し達成時、DMMぱちタウンのみ完全なテーブルを掲載）
  - 弱チャンス目/押し順弱チャンス目契機の鬼斬チャージ当選率（通常滞在時・高確滞在時をそれぞれ独立した見出しで分離）
  - 弱チェリー・弱スイカ契機の鬼斬チャージ当選率（通常滞在時・高確滞在時をそれぞれ独立した見出しで分離）
- **判別要素**（②）: エンタトロフィー（AT終了画面）、AT終了画面のキャラ演出、AT中の特殊上乗せゲーム数表示、鬼ボーナス中のキャラ紹介（9・10G目）、エンディング中のレア役成立時PUSHボイス、AT中の獲得枚数表示のすべての要素（計40種類）を、DMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」「〜否定」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/通常/強］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## データについて

以下はDMMぱちタウン／1geki.jpの両サイトで確認できたが、本ツールでは採用しなかった（見つけたが未使用のデータ）。

- **通常時のリーチ目出現確率**: 設定1（1/39364.3）のみ判明しており、設定2〜6は両サイトとも「???」または未掲載。設定差の全体像が不明なため、二項尤度チャンネルとしては採用しなかった。
- **強レア役（強ベル・強チェリー・強チャンス目・強リプレイ・強スイカ）の鬼斬チャージ当選率**: 「全設定共通」と明記されており、設定間の差がないため設定判別には使えない。
- **1geki.jp独自の実戦データ（AT当選周期・規定バッサリポイントからの鬼モード移行回数）**: 一撃編集部による実戦サンプルに基づく独自考察であり、公式・準公式の設定差データではなくサンプル数も少ない（数回〜十数回分）ため、確定的な二項尤度チャンネルとしては採用しなかった。
- **鬼ガチチャンス成功当選率・獲得ポイント振り分け・ATゲーム数上乗せ当選率（7セット目以降）**: DMMぱちタウンに詳細な数値が掲載されているが、いずれも設定差なし（全設定共通）と明記されているため、判別要素としては使えない。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能。CSS・HTML骨格・JSアーキテクチャ（per-setting配列、`logBinomLikelihood`、`computeCandidateSettings`、`buildChips`、`render`、softmax正規化）は `apps/2026-09-06-tokyo-ghoul-slot-checker/` を踏襲
- 尤度計算: 各二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後softmax的に正規化（一様事前分布を仮定）
- 空欄フィールドの安全対策: `parseField(el)` ヘルパーが空欄を `null`、それ以外を非負整数として返し、各チャンネルの対数尤度計算を「そのチャンネル自身のnフィールドが非nullかどうか」でゲートしている（`apps/2026-09-07-monhun-rise/` のパターンを採用）。空欄は「データなし」を意味し、「0回観測」と誤読されることはない
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
