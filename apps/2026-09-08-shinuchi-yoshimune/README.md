# スマスロ 真打 吉宗 設定判別ツール

「真打 吉宗」（スマスロ、大都技研、機種ID 4983 ※同名の旧機種「吉宗」（機種ID 4778）とは別台のため、ページタイトルが「真打 吉宗」であることを確認したうえで採用）の設定判別を助ける計算ツール。[DMMぱちタウンの機種ページ「設定判別・推測ポイント」](https://p-town.dmm.com/machines/4983#anc-point)（2026/09/01更新）と[一撃「真打 吉宗」設定差・設定判別要素まとめ](https://1geki.jp/slot/l_shinuchi_yoshimune/0/)（2026/09/01更新）の両方を全文確認したうえで、公開されている判別要素をDMMぱちタウンの分類順（終了画面系→真BIG中/エンディング中のボイス→通常時演出→獲得枚数表示）のまま反映し、実戦データと示唆演出の出現回数から設定期待度を算出します。

公開URL: https://haruikntv.github.io/weekly-apps/2026-09-08-shinuchi-yoshimune/

## 機能

- **数値データ**（①）: 以下4系統をそれぞれ独立した二項尤度チャンネルとして入力可能
  - **AT初当たり確率**（総G数ベース。一撃のみに完全な設定1〜6テーブルが掲載）
  - **CZ出現率**（総G数ベース。AT初当たりと母数（総G数）が共通のため見出しを共有）
  - **抜刀メーターMAX（ベル10個）到達時の抜刀チャンス当選率**（母数がAT初当たり・CZ出現率とは異なるため見出しを分離）
  - **CZ（悪人成敗チャンス）当選時の「柳生」出現率**（母数がCZ当選回数そのものであるため、さらに見出しを分離）
- **判別要素**（②）: AT終了画面（示唆画面6種）、真BIG中・エンディング中のボイス（示唆ボイス10種）、通常時演出「御白洲ビジョン」（示唆キャラ2種）、獲得枚数表示（3種）——計21種類をDMMぱちタウンの分類のままカテゴリラベル付きで1つのリストにまとめてタップ式カウンターで記録
  - 金文字表示の「〜濃厚」は1回でも出現すれば矛盾する設定を候補から確実に除外
  - 斜体表示の「〜示唆」は確定情報ではないため、ハード除外はせず出現回数と［弱/強/(無印=通常)］の強さに応じて参考程度の重みだけを加える
- タップ式のカウンターUI（コンパクトな一覧チップ表示でページを短く保つ）
- 数値データとカウント結果を組み合わせて、現在の有力候補と最有力設定をリアルタイム表示
- 広告枠（`.ad-slot`）を3か所設置：ヘッダー直下（728×90）、判別要素と結果の間（300×250）、フッター上（728×90）。今はプレースホルダー表示のみ（詳細はリポジトリルートのREADME「広告の設置について」を参照）

## 一撃（1geki.jp）とのクロスチェック

DMMぱちタウンと一撃、両方のページを全文確認したところ、抜刀メーターMAX時の抜刀チャンス当選率・CZ当選時の柳生出現率・サブ液晶（御白洲ビジョン）の設定示唆・獲得枚数表記・AT終了画面・真BB/エンディング中のボイスは、両サイトで数値・内容ともに完全に一致していた。

一撃側にのみ掲載されていたのが**AT初当たり確率とCZ出現率の設定1〜6完全テーブル**。DMMぱちタウンの「設定判別・推測ポイント」欄にはこの2つの掲載がなく、一撃側でのみ確認できたため、本ツールでは一撃の値を採用し、`P_AT_INITIAL`・`P_CZ_APPEARANCE`のコメントにその旨を明記した。

## データについて

以下は本文を確認したうえで、あえて数値チャンネル・判別要素チップのいずれにも採用しなかった項目とその理由。

- **コパンダトロフィー**（銅／銀／金／稲妻柄／虹の5色、DMM・一撃の両方に画像は掲載）：一撃側に「示唆内容は、他機種を参考にした推察」と明記されており、機種公式の設定差データではなく他機種からの類推にすぎないため対象外とした。DMM側にも本機のトロフィーに対応する具体的な設定示唆テキストの記載はなかった。
- **メニュー画面での設定示唆（吉宗／大岡越前／天英院）**：一撃側に「示唆の詳細な内容は現状不明だ」「？？？」と明記されており、公開されている具体的なマッピングが存在しないため対象外とした。
- **AT終了画面・獲得枚数表示の出現率テーブル**（設定1〜6ごとの出現%）：これらは「どの画面が出たか」というイベント自体をチップでカウント済みであり、出現率テーブルを二項尤度チャンネルとして重ねて使うと同じイベントを二重計上することになるため、チップ判定（濃厚/示唆）のみを採用し、確率テーブルは未使用とした。
- **ステージ演出（大奥＝周期到達濃厚、天守閣＝CZ以上濃厚）**：これらは「周期到達」「CZ当選」というゲーム内イベントの示唆であり、設定（1〜6）そのものの判別要素ではないため対象外とした。
- **AT中のキャラクターフラッシュ**（大岡越前＝特殊上乗せ以上濃厚、吉宗＝真高確率以上濃厚、大奥＝真BB濃厚）：報酬レベル（上乗せ枚数や真高確率移行）の示唆であり、設定差データではないため対象外とした。
- **CZ失敗時の「曠野の決闘」当選率**（設定1: 1/128.0、設定6: 1/64.0）：DMM側で設定2〜5が「調査中」のまま未掲載であり、完全な設定1〜6テーブルではないため対象外とした。
- **小役確率**（弱チェリー・強チェリー・弱スイカ・強スイカ・弱チャンス目・強チャンス目など）：DMM側の表は非レア役高確中／レア役高確中の内部状態別の値のみで、設定ごとの内訳が示されていないため設定差データとしては利用できず対象外。

## 技術メモ

- 依存ライブラリなしの単一HTMLファイル（プレーンなHTML/CSS/JS）。ビルド不要で、そのまま静的ホスティング可能
- 参照実装として[スマスロ東京喰種 設定判別ツール](../2026-09-06-tokyo-ghoul-slot-checker/)の白／黒／赤パレットのCSS（`<style>`ブロック）をそのまま流用し、HTMLの骨格（ヘッダー→広告枠→①数値データ→②判別要素→広告枠→③結果→出典→免責事項→広告枠→フッター）とJSアーキテクチャ（`logBinomLikelihood`・`computeCandidateSettings`・`buildChips`・`render`のソフトマックス正規化）も踏襲した
- 尤度計算: 各数値チャンネルの二項分布 `P(k|n,p)` の対数尤度を合算し、示唆要素は出現回数（上限3回でキャップ）×tier別の重み（弱0.2／通常0.35／強0.5）を加算。その後ソフトマックス的に正規化（一様事前分布を仮定）
- 判別要素は単一のデータ配列（`ITEMS`）で定義し、各項目の`kind`（hard/soft）と`cat`フィールドで確定/示唆の別とDMMの分類ラベルを保持。チップUIは`cat`が変わるタイミングで自動的にラベル＋新しい行を生成する
- 空欄の数値フィールドは「未入力（データなし）」として扱い、「0回観測」とは区別する。`parseField(el)`ヘルパーが空欄なら`null`を返し、各チャンネルの`logBinomLikelihood`呼び出しはそのチャンネル自身のフィールドが`null`でないことを個別にチェックしてからゲートする（[スマスロ モンスターハンターライズ 設定判別ツール](../2026-09-07-monhun-rise/)の`render()`と同じパターンを踏襲）。これにより、共有の総G数（`totalG`）だけ入力してAT当選回数を空欄にした場合でも、「AT当選0回」と誤って計算されることはない
- `numericInputs`配列（要素の並び順）→ イベントリスナー（`numericInputs.forEach((el) => el.addEventListener('input', render))`）→ `render()`内の分割代入、の3点の並び順が一致していることを確認済み
- AT初当たり・CZ出現率の2チャンネルは母数（総G数）が共通のため1つの見出しにまとめる一方、抜刀メーターMAX時の抜刀チャンス当選率（母数＝抜刀メーターMAX到達回数）とCZ当選時の柳生出現率（母数＝CZ当選回数）はそれぞれ独立した母数を持つため、見出しを分離している
